# `bin/analyze` の集計セクション定義と実測

対局記録（JSONL）の事後分析が出す各セクションの**定義・門・実測ベースライン**。
CLAUDE.md から切り出した（起動方法は CLAUDE.md の「コマンド」節）。

**analyze に集計行を足したら `arena.yml` と `check-economy.yml` のフィルタも直すこと**
（ジョブサマリーは集計行だけを拾う grep なので、足しただけでは CI に出ない）。

共有定義の置き場は `src/mate_economy.rs`（#28）・`src/check_economy.rs`（#31）・
`src/check_prep.rs`（#34）。**診断と CI で定義が食い違うと較正の数字が無意味になる**ので、
別々に数え直さずここを呼ぶ。

- `cargo run --release --bin analyze -- records/*.jsonl` — 対局記録の事後分析。
  アリーナも `ARENA_RECORD_DIR` を設定すると候補(A)視点の記録を同形式で出力する
  （CIでは常時有効で artifact `arena-records` に上がる。真実の全手順つきなので
  そのまま analyze にかけられる）。
  game:end の全公開棋譜をリプレイし、反則の原因分類（王手解消失敗/飛び込み/経路封鎖/打ちマス）・
  駒得収支・只取られ・損な交換・取り返し逃し・詰み逃し・**玉移動反則の行き先再訪**
  （同一局で既に同じ `to` へ玉反則した回数。`KING_REPEAT_FOUL_W` の発火上限）・
  **王手中の汚名マス玉逃げ**（汚名マスへの玉移動が真に合法＝解消できる決定のうち、
  それを選んで解消した回数 / 選ばず反則した回数。項が正しい王手解消を沈める機会）を集計する。
  **被詰めろオラクル**（2026-07-25）: 相手番の各局面で相手に一手詰めが存在したかを
  数える。相手が実際に詰みを見つけたかに依らないので、**相手が詰みを実行して
  こない環境（アリーナの凍結版同士は互いに玉位置が見えない）でも自玉の受けの
  改善を直接測れる**（nofoul オラクルと同じ趣旨）。実測の基準値: ローカルの
  対人記録83局で 232回/79局（うち打ち詰み166回・実際に詰まされた57回）。
  **詰み経済セクション**（2026-08-27、issue #28 の P0-1/P0-2。従来の
  「被詰めろ N回 / M局（うち打ち詰み K回）」を置き換えた）:
  - **排他的分類**: 従来の `打ち詰み` フラグは `drop_mate` の有無だったので
    「打ちでも盤上でも詰む」局面が打ち側にだけ数えられ**排他分類ではなかった**。
    `mate::mate_moves_in_1_fast` で全詰め手を列挙し union で
    `打ちのみ / 盤上のみ / 両方` に分ける。実際に詰まされた手の種別も別に出す
  - **エピソード単位**: 連続した相手番の被詰めろを1つに畳む（手番単位だと
    「何回危険に入ったか」と「1回の危険が何手番続いたか」が混ざる）
  - **手数調整した露出**: bot の決定点・終盤（90手目以降）の決定点を分母にした
    100決定点あたりのエピソード数と初回被詰めろの手数。
    「局が長くなっただけ」と「同じ手数帯でも危険が増えた」を分けるため
  - **攻め／受けを分けた終局**: 全終局に占める詰み比率ではなく bot の
    詰み負け率・詰み勝ち率
  - **受けの漏斗**: 被詰めろは相手番なので**一手巻き戻し**、bot の直前の決定点で
    ①真実上「指した後に相手の一手詰めが消える手」の本数 ②それが候補生成
    （`candidate_moves`、自駒のみ）に載るか ③その決定点に厳密粒子があったか
    （記録の `chose` の `debug.sample_slots`。**2手読みは厳密粒子ゼロには
    効かない**）。入口で受けがあったか／最後に回避できた手番も分けて出す
  - 実測（`records/` 59局、旧記録なので③は空）: 被詰めろ 95エピソード/182手番、
    詰め手は **打ちのみ28 / 盤上のみ25 / 両方42**、実行は **打ち16 / 盤上23**、
    入口で安全手あり 79/95・**候補生成に載った率は 100%（候補生成は律速でない）**。
    vs v14 の8局（予算200ms の動作確認・統計ではない）では
    **被詰めろ手番の決定点の 94.7% が厳密粒子ゼロ**
  - `mate_moves_in_1_fast` の単発コストも常時出す（P1-A の前提。59局・4200決定点で
    p50 9.5µs / p95 76.6µs / 最大 280µs、終盤 90手目以降は p50 41.5µs）。
    `TSUITATE_MATE_COST=1` を付けると完全版と全決定点で突き合わせ、比も出す
    （**絞り込みの効き目は 1.4倍しかない**: 支配項は王手手ごとの
    `has_any_legal_move` であって非王手手の列挙ではない）
  **王手中の反則経済セクション**（2026-08-28、issue #31 の P0-1/P0-2/P0-3。
  粒子を回さないので arena-records にそのまま常設できる）:
  - **型の分類**（P0-1）: 王手中の bot の手番を「最初の反則の手種 → 受理された手の
    手種」で分ける（玉以外の盤上手→玉の手 / 玉以外→玉以外 = kakutori 型 /
    玉→玉 = 逃げ先の選別 / 玉→玉以外 / 打ち）。**分母は反則0の手番も含む
    全王手手番**（新しいプローブを足す害の estimand がそこなので、反則した手番
    だけを数えてはいけない）。手種は真実の駒配置ではなく
    `CheckSolver::captures_checker`＝**bot の意図**で分ける（空振りの捕獲試みも
    プローブ）。真実由来の列は別に持つ: 最初の反則の着手先に真に敵駒がいたか・
    それが王手駒か / 開始時に**真に合法だった候補の本数**（1本の手番は価格では
    避けられない）/ **ソルバー最善が最初から合法だった手番の割合**（1反則も
    要らなかった手番）/ 受理された非玉手の開始時ソルバー p 順位
    （**エンジン順位ではない**。粒子が要るので P0-4 の rank_probe の領分）/
    開始時の残り反則
  - **王手駒仮説の希釈**: 真の王手駒（マス・駒種とも一致）に載っている仮説の
    **重みシェア**と正規化エントロピーを反則あり／なしの手番別に出す。
    「知らない（希釈）」と「知っていて払う」を分ける量
  - **手種別・順番別の p_legal 較正**（P0-2）: 記録の `chose.debug.p_legal` を
    手種 × 手番内の順番（0/1/2+）で並べ、**捕獲試みの方向つき較正誤差**
    （平均予測 − 合法率）を**元対局 cluster bootstrap CI** つきで出す。
    H3 の門は「CI 下限 > 0.1 かつ v13/v14 の両相手で同方向」で、**Brier では
    H1（価格）と H3（較正）を分けられない**。旧記録（p_legal 無し）はその旨を出す
  - **ソルバー方策の破滅**（P0-3）: 解消確率の argmax で指し直すと 8反則以上を
    積む手番の、①真の王手駒が仮説集合にあったか ②積んだ反則の原因
    （真実から分類: 王手駒が残る／捕獲先が支えられていた／別の敵駒の利き／
    経路／打ちマス）。「ソルバーに従え」は解ではないことの記録
  **発見セットの実測（run 33149098094、run 32697854659 の main vs v13 / v14 各104局）**:
  v14 側は issue 本文の表を完全に再現する（王手中 178手番 / 291反則、型1 =
  61手番 118反則、残り反則の分布まで一致）ので復元は実戦の分類と一致している。
  - **H3（較正）は棄却**: 捕獲試みの方向つき較正誤差は **v14 +0.025
    [−0.008, +0.057] / v13 −0.009 [−0.055, +0.036]** で、門（CI下限 > 0.1・
    両相手で同方向）に届かないどころか**符号が逆**。捕獲プローブの p_legal は
    概ね当たっている＝**P1-γ は指示されない**。過信が出ているのは**玉の手**
    （順番2+ で v14 +0.096 / v13 +0.126）で、これは `legal_under` が支え駒を
    置かない既知の盲点と同じ方向だが、γ は玉の手には掛けない設計
    （`check_king_prior` 第1版の教訓）なので補正には使えない
  - **破滅は「知らない」ではなく希釈**: ソルバー方策が8反則以上を積む6手番
    （v14 4 / v13 2）は**すべて真の王手駒がマス・駒種とも一致で仮説に載っている**。
    真の王手駒の重みシェアは反則ありの手番で **0.035〜0.037**（反則0の手番は
    0.078〜0.084）・正規化エントロピー **0.99 = ほぼ一様**で、シェアの低さ自体が
    反則の予測子
  - 反則した手番の **47.2%（v14）/ 54.0%（v13）はソルバー最善が最初から真に合法**。
    一方で受理された非玉手の開始時ソルバー p 順位は **4位以上が 46/57・41/43** =
    kakutori 型は「単に次点へ進んだだけ」ではない（H2 の材料。ただしソルバー p の
    順位であってエンジン順位ではないので、判定は P0-4 待ち）
  - 初版 run 33141692604 は `view_from_model` が視界の手数に 0 を渡していて
    CheckSolver の既知敵駒の鮮度窓（`move_number − 8`）が無制限だった
    （2026-08-28 修正）。**ソルバー由来の列だけ**が動いており（型の表・残り反則・
    記録の p_legal から作る較正は不変）、窓が正しくなるとソルバー単体 p の Brier が
    0.2168/0.2153 → 0.2001/0.2017 と基底率予測を初めて明確に下回る
  ローカル `records/` 59局（旧記録なので P0-2 は測れない）でも破滅3手番はすべて
  マス・駒種一致で、同じ「希釈」の署名。共有定義は `src/check_economy.rs`、
  表と門と残りの段への含意は `docs/check-economy-p0.md`
  **P0-4 の実測（run 33157124844、3 seed・2000ms・型1+型2 の全決定点）**:
  実再決定は**初回決定と同じ prewarm 済み instance の継続**として作り、
  **反則の観測を入れない対照を同じ配管で取る**（PR #32 レビュー [P1]。
  独立に組み直すと反則注入の効果と再構築ノイズが混ざる）。
  - **中止条件（k\* ≤ 3 が 20% 未満 かつ 首位が変わるのも 20% 未満）には該当
    しない**が、枝ごとに強さが違う
  - **α（価格）は生きている**: 型1（issue の 61手番/118反則の塊）で k\* の
    中央値 **2.80 / 4.32**・k ≤ 3 で **43.5%（v14）/ 40.0%（v13）** が玉の手へ
    反転。**型2（kakutori 型）は価格では動かない**（4.2% / 17.5%）ので、
    **α を型で切らずに一律に掛けると型2 の捕獲プローブまで沈む**
  - **β（動的継続価値）の支持は弱い**: 生の「静的な次点と違う」率 61〜70% の
    うち **44〜60% はノイズ床**（反則の観測を入れない対照でも起きる）で、
    **正味は v14 18.9% / v13 15.2% = どちらも 20% 未満**。型別では型2 の正味
    だけが 22.5〜28.0% で、玉逃げに落ち着く型1 は 7.7〜11.5%
  - **再決定そのもののノイズ床が 44〜60% ある**（同じ clone 元・同じ視界・同じ
    除外集合でも、`choose` のたびに `Estimator::update` が壁時計デッドラインまで
    若返らせるので粒子集合が変わる）。**オフラインの再ランキング診断はすべて
    この床を踏む**ので、「順位が変わったか」を数える指標は対照を同じ配管で
    取ってペア差で見ること（初版 run 33149098094 の「66〜75% で次善手固定の
    仮定が外れる」は生の値なので**撤回**）
  - 読み方の限界: **初回ランキングの首位が実戦の最初の反則と一致するのは
    64〜67%**（壁時計予算で粒子数が揺れる）。k\* の分布は「実戦のその決定
    そのもの」ではなく「同じ状態から現行方策が引き直したときの分布」。k\* は
    感度であって価格の測定ではない（水準は P0-7 の影の価格の領分で、単位が
    勝率なので `foul_cost` とは曲線の形しか比べられない）
  **連続王手の起点セクション**（2026-08-29、issue #34 の P0-1。粒子を回さないので
  arena-records にそのまま常設できる）: 「bot が玉の手で王手を解消 → 次の相手手番で
  再び王手」を取り出し、2回目の真の王手駒を **(a) 前の玉位置 / (b) その隣接 /
  (c) それ以外**に分ける（「前回と同じ駒が追った」は位置分類と混ぜず別軸のフラグ、
  両王手は別層）。**門は「(a)+(b) が過半」ではない**（頻度が高くても、被覆の有無で
  反則が変わらないなら形を変える意味が無い）: `(a) の頻度 × F4 有無による反則差` と
  `(b) の頻度 × 実王手駒マス被覆の有無による反則差`を別々に出し、元対局 cluster CI を
  付けて合算も出す。**実測（run 32697854659）**: 玉逃げの **45〜50%** で次の手番も王手に
  なり、その王手駒の **57%** が (a)+(b)（(a) の 60〜76% は同じ駒が追ってきたもの）
  = 指導4の観察は実在するが、**寄与量は両相手とも CI が 0 を跨ぐ**
  （合算 v13 +0.101 [−0.193, +0.359] / v14 +0.189 [−0.058, +0.443]）。
  **人間相手（旧 `records/`）は (a) 7.2% / (b) 52.2% と分布が違う**が、bot の build も
  相手も違うので人間差には帰属できない
  **王手の質の指標2種**（2026-07-29、ユーザーの指導に基づく設計）:
  ①「王手駒の即取られ」= 直接王手した駒を直後に取られた回数（弱い王手。
  実測ベースライン: 直接王手の53〜56%が即取られ・大半が取り返しなし）、
  ②「王手の強さ」= 王手直後の相手の合法解消手数 K・受け側の視界での選択肢 N
  （同じマスを別の駒で取る手は重複排除した「異なる確かめ」の数）・直後の実反則。
  実測: **K≤2 の王手は実反則 0.81〜1.17回/王手 vs K≥3 は 0.40〜0.46回（約2.4倍）**、
  N は平均79〜82手で N<10 はアリーナ800局で出現ゼロ（対人・終盤では効きうるので
  指標には残す）。王手の期待反則数は「手段クラス数 × 解消手の互いに素性 ÷ 解消手数」
  で決まる（詳細はメモリ strong-check-few-resolutions）
