「知っていて払っている」せいなのかを、**runtime を一切変えずに**測る。
issue #28（詰み経済）の総合判定「受けは検出できるが、受けた後の継続が反則負けで終わる」の
続きにあたる。

## P0-4 w\* 監査（`bin/check_probe`）

「浮かせたい候補がそもそも在るのか」を方策を変える前に測る
（`TSUITATE_PROBE_AUDIT` と同じ考え方）。**runtime には何も入らない**。

決定点は「王手中で実際に反則した bot の手番」で、既定の対象は型1
（玉以外 → 玉の手）と型2（玉以外 → 玉以外）。1決定点につき2つのランキングを取る:

1. **手番開始時（反則0）** … `for_each_decision_full` が渡すのはその手番の反則を
   全部食った後の状態なので、両者のログ末尾から反則の観測を `fouls_this_turn` 本
   だけ落として復元する（`add_foul_obs` が対で積む `MyFoul` / `OpponentFoul`。
   落とす末尾が本当に反則の観測かを確かめてから落とす）
2. **実戦の反則列を食った後（実再決定）** … `Estimator::update` を通した本物の
   再ランキング。若返り・ソフト救済・`prior_weight` の反則比例ブースト・
   `foul_tried` の除外まで全部通る。**prewarm は1回だけ**で、①の instance を
   `clone_boxed` して `MyFoul` を食わせた**継続**として作る（別々に組み直すと
   壁時計デッドラインのぶん粒子集合が別物になり、反則注入の効果と再構築ノイズが
   混ざる。下記「H2 は対照との差で見る」）
3. **対照（A）** … ②と**同じ視界（＝同じ残り反則＝同じ価格）・同じ除外集合**で、
   **反則の観測だけを入れずに**選び直したランキング

出す量:

- **k\***: 玉の手が首位になる最小の反則コスト倍率。価格は玉の手の (1−p) 側にも
  効くので「score 差 ÷ プローブの傾斜」では出ない。**P1-α と同じ
  `check_cost = max(k × base, 床)` で全候補を再計算して交点を探す**
  （`check_economy::k_star`。`score = min(p·G,G) − (1−p)·c + …` なので
  コストの付け替えは `−(1−p)(c_k − c)` で厳密。gain も p_legal も再計算しない）。
  順位は**乱数を除いたスコア**（`score − tiebreak`）で付け、同点は USI の辞書順
- **門の分母は「首位が玉以外」の決定点だけ**。決定点の分類は seed の多数決で
  1回だけ決め、多数決で既に玉の手なら門の分母から**丸ごと**外す
  （少数側の 1 unit だけで分母1の「反転」を数えると門の割合が水増しされる）
- **反則注入後の実再決定が静的な次点と違うか**（H2 の生の値）。「静的な次点」＝
  初回ランキングから実戦の反則列を除いた最上位 = 現行 `combine_score` が暗黙に置く
  「次善手固定」の仮定そのもの
- **H2 は対照との差で見る**: 生の「静的な次点と違う」率は**再決定そのもののノイズ**を
  含む（同じ設定の2 run で初回の首位が 67〜69% しか一致しない = 壁時計予算で
  粒子数が揺れるため）。対照（A）は価格も除外集合も B と同じで観測だけが無いので、
  **B と A の差が「反則を観測したことによる信念更新の効果」そのもの**。
  A と静的な次点の差はノイズ床として併記する
- 監査の健全性: **初回ランキングの首位が実戦の最初の反則と一致した率**
  （オフライン復元がその決定をどれだけ再現できているか。予算やコードが記録と
  違うと下がるので、判定の前にここを見る）

中止条件: **k\* ≤ 3 で反転する決定点が 20% 未満 かつ 反則注入後に首位が変わる
決定点も 20% 未満**なら α / β の枝は中止（m061/m036 型の「候補が全部悪手」）。

seed は独立標本として数えず、決定点ごとに多数決を取る。

## 実装済みの3段（粒子を回さない）

入力は**アリーナの対局記録**（`arena-records-*` の JSONL）。真実の全手順・反則試行・
選択手の `debug.p_legal` が入っているので、粒子を回さずに全部復元できる。
共有定義は `src/check_economy.rs`（`bin/analyze` と、以後の P0-4/P0-5/P0-7 が
**同じ定義**で手番・手種・順番を数えるための場所。別々に数えると較正の数字が意味を失う）。

### 視界の復元は決定点の手数を渡す

`check_economy::view_from_model` に**必ず決定点の手数**を渡す（`scenario_core::make_view`
と同じ規約）。`CheckSolver` は既知の敵駒マスの鮮度を `view.move_number − 8` で切るので、
0 を渡すと窓が無制限になり、実戦では載らない古い幻の駒を base に載せた**別物の
ソルバー**になる。ここがずれると手種の分類（`captures_checker`）・ソルバー p の順位・
仮説のシェアとエントロピー・破滅の判定が全部ずれる。
（初版はここを 0 のまま移設していて、ローカル記録で「破滅 7手番 / ソルバー最善が
最初から合法 38.9%」と出ていた値が修正後は「3手番 / 36.3%」に変わった。
run 33141692604 の**ソルバー由来の列は撤回**し、修正後に取り直す。
記録の `p_legal` から作る P0-2 の較正と、粗い束（玉 / 玉以外 / 打ち）で決まる
型の表はこの影響を受けない）

### 手種は「bot の意図」で分ける

`CheckMoveKind` は真実の駒配置ではなく **`CheckSolver::captures_checker`**
（王手駒仮説のマスへ玉以外で移動し、その仮説の下で解消する手）で捕獲試みを判定する。
空振りの捕獲試みも意図としては捕獲プローブなので、同じ束に入れないと
「プローブの較正」が測れない。真実で敵駒がいたか・それが王手駒かは
**別の列**（`truth_enemy_at_to` / `truth_checker_at_to`）に持つ。

### 分母は反則0の手番も含む全王手手番

型の表の割合は**王手中の bot の手番全体**を分母にする。反則した手番だけを数えると、
P0-6 の非劣性 estimand（新しいプローブを足す害）に対応する母数が見えない。

### 手数の対応

`check_economy::decision_groups` に閉じる: 反則は手番を変えないので `MyFoul` の
`move_number` はその決定点の手数そのまま、`MyMove` は**適用後**の値なので 1 引く。
受理手が出たらそこで手番を閉じる（同じ手数の手番が2つ続くことはない）。
`accepted_legal_at_entry` は**整合性検査**（反則は局面を変えないので常に true。
false が出るなら手数の対応がずれている）で、発見ではない。

### 「事後的には無駄だった」を測る列

- `legal_candidates_at_entry` … 開始時点で**真に合法だった候補の本数**。
  1本しか無い手番の確かめは価格では避けられない
- `best_legal_rank_at_entry` … 真に合法な候補のうちソルバー p が最上位のものの順位。
  1 なら「ソルバー最善が最初から合法だったのに反則してから到達した」。
  **分母は開始時にソルバーを作れた手番だけ**（両王手で仮説が全滅するとソルバーが
  作れず順位が付かない。0 として数えると率が下振れするので判定不能として別に出す）
- `accepted_rank_at_entry` … 受理された非玉手の開始時ソルバー p 順位。
  **エンジンの順位ではない**（粒子が要るので P0-4 の領分）。上位なら
  「情報が生産的だった」のではなく「単に次点へ進んだだけ」の可能性が高い、という粗い代理
- `true_hyp_share` / `hyp_entropy` … 真の王手駒（マス・駒種とも一致）に載っている
  仮説の重みシェアと、仮説重みの正規化エントロピー。**「知らない（希釈）」と
  「知っていて払う」を分ける量**

### P0-2 の判定は Brier ではない

H3 の門は**方向つき較正誤差**「捕獲試みの 平均予測 − 合法率」の
**元対局 cluster-bootstrap CI の下限が 0.1 を上回る**こと、かつ v13 / v14 の
**両相手で同方向**であること。Brier は H1（価格）と H3（較正）を分けない。
`cluster_ratio_ci` の統計単位は元対局で、手番も seed も独立標本として数えない。

この較正は**現行方策が選んだ手**のものであって、γ で順位を変えた後の候補分布へは
外挿できない（候補分布上の較正は P0-5 で真実ラベル付けして取る）。

### P0-3 は「ソルバーに従え」の反証を残す

解消確率の argmax で指し直すと反則は減る（実測 291 → 211）が、**8手番は逆に
8〜10反則**を積む。P1 の方策がソルバーの p を強く信じるほどこの破滅を継承するので、
破滅手番（8反則以上）ごとに ①真の王手駒が仮説集合にあったか（マス・駒種とも一致 /
マスのみ / 無い）②積んだ反則の原因（真実から分類: 王手駒が残る / 捕獲先が支えられて
いた / 別の敵駒の利き / 経路 / 打ちマス）を記録する。
`CheckSolver::legal_under` が仮説の王手駒1枚しか置かない盲点（支え駒・ピン）は
**この issue では直さない**（原因を記録するだけで別 issue）。

## 回し方

**通常のコード push では走らない**。既存の Arena 実行の記録に対して回す:

```
gh workflow run check-economy.yml -f arena_run_id=<Arena実行ID> \
  -f opponents="estimator_v13 estimator_v14"
```

`gh` が使えないときは `.github/ci/check-economy.request.json` を置いて push
（例は `check-economy.request.example.json`。削除の push は全ジョブがスキップされる）。

**相手ごとに別ジョブで集計する**のが要点: 判定は「v13 / v14 の両相手で同方向」なので、
両者の記録を混ぜて1つの数字にしてはいけない。

同じ集計行は `arena.yml` のジョブサマリーにも出る（**analyze に集計行を足したら
arena.yml と check-economy.yml の両方のフィルタを直すこと**）。

P0-4 は**粒子を回すので P0-1〜P0-3 の数十倍かかる**ため既定では走らない
（`run_probe: true` で有効化）。元対局単位で `probe_shards` 個に割り、
`probe-aggregate` が `check_probe report --shards N` で合算する。
**シャードが欠けたら失敗させる**（決定点の分母が狂うため）。CSV の1行目の
`#meta` に seed 数・型・予算・config 指紋・コード版（`source_fingerprint`）・
記録集合の指紋・**相手**・決定点数を書き、`report` が「同じ実験の独立サンプルか」を
検査する（別の実験を混ぜた集計・重複シャードは失敗）。

完全性の検査は3段で、**どれも既定では失敗**（`--allow-incomplete` で警告へ降格）:

1. **決定点ごとに seed が揃っているか**（揃わないと多数決の分母が決定点ごとに変わり、
   2/3 seed の点は同数で「反転しない」側へ倒れる）
2. **決定点そのものが消えていないか**（全 seed でランキングが取れなかった決定点は
   行が1つも残らないので、行がある決定点しか見ない ①では捕まらない）
3. **H2 の値（生 / 対照 / 正味）が欠測していないか**（B や A のランキングだけ
   取れなかった unit は行が残って `changed` 系が空になり、集計の `filter_map` が
   黙って落とす。全 seed で欠測した決定点は H2 の分母から丸ごと消えるので、
   20% の門が欠測の偏りで動く）相手を meta に持つのは、
`records` の指紋がディレクトリ全体のハッシュなので**同じ記録集合から
`--opponent` だけ変えた2本を指紋では区別できない**ため。決定点数は
「全 seed でランキングが取れずに決定点ごと消えた」ぶんを検出する
（行がある決定点しか見ない seed の欠落検査では捕まらない）。思考予算は**記録を取ったアリーナと揃える**こと
（予算が違うと粒子数が変わり、「その決定点で実際に見えていたランキング」では
なくなる）。ローカルなら:

```
TSUITATE_THINK_BUDGET_MS=2000 cargo run --release --bin check_probe -- \
  --seeds 3 --jobs 6 --out data/check_probe.csv <records...>
```

### H3（較正）は棄却

門は「捕獲試みの 平均予測 − 合法率 の元対局 cluster CI 下限 > 0.1 かつ両相手で同方向」。
実測は **v14 +0.025 / v13 −0.009 で符号すら逆**、CI 下限はどちらも 0 未満。
**捕獲プローブの p_legal は概ね当たっている**（v14 の順番別: 0回目 +0.041 /
1回目 −0.004 / 2回目以降 −0.028、v13 は 0回目 −0.051 / 1回目 +0.076 /
2回目以降 +0.102 と順番による向きも一致しない）。**P1-γ は指示されない**。

過信が出ているのは**玉の手**のほう（v14 順番0 +0.048 / 順番2+ **+0.096**、
v13 順番0 +0.058 / 順番2+ **+0.126**）で、これは `CheckSolver::legal_under` が
仮説の王手駒1枚しか置かない既知の盲点（支え駒・見えない利き）と同じ方向。
ただし γ の設計は**玉の手には掛けない**（一律の玉割引が3シード全て悪化した
`check_king_prior` 第1版の教訓）ので、この過信はそのままでは補正に使えない。
仮説側（`legal_under` の拡張）は別 issue。

### 破滅は「知らない」ではなく「希釈」

ソルバー方策が 8反則以上を積む手番は 6（v14 4 + v13 2）で、**そのすべてで
真の王手駒はマス・駒種とも一致する仮説として集合に載っている**。積んだ反則の原因も
「王手駒が残る（仮説違い）」が 37 / 13 で支配的 = **正しい仮説が一様な仮説群に
埋もれて argmax が別の手を選ぶ**。実際、真の王手駒の重みシェアは反則ありの手番で
**0.035〜0.037**（反則0の手番の 0.078〜0.084 の半分以下）・正規化エントロピーは
**0.99 = ほぼ一様**で、シェアの低さ自体が反則の予測子になっている。

### 型1（61手番）は「単に次点へ進んだだけ」ではない

受理された非玉手の開始時ソルバー p 順位は **4位以上が 46/57（v14）・41/43（v13）**。
一方で反則した手番の 47.2% / 54.0% は「ソルバー最善が最初から真に合法」だった。
**順位が下位の手に落ち着いている**ので、H2（候補固有の動的継続価値）の材料は残る。
ただしこれは**ソルバー p の順位であってエンジンの順位ではない**ので、
「浮かせたい候補があるのか」の判定は P0-4（`bin/check_probe` のエンジン順位と k\*）待ち。

### 残りの段への含意

- **γ（較正マップ）の枝は落ちた**。α（価格）と β（動的継続価値）が残る
- α / β の中止条件（P0-4）は**該当しない**が、枝ごとに強さが違う:
  **α は型1 で生きている**（k\* 中央値 2.8〜4.3・k ≤ 3 で 40〜44% が反転）一方、
  **β の支持は弱い**（対照つきの正味は 15〜19% で 20% 未満。型2 に限れば 22〜28%）
- 仮説の希釈（シェア 0.04・エントロピー 0.99）は H1/H2 とは別の第4の説明として
  実測された。これは価格でも継続価値でもなく**信念側**（CheckSolver の仮説重み）の

### 判定: 中止条件には該当しない（α は生きている。β は弱い）

中止条件は「k\* ≤ 3 で反転する決定点が 20% 未満 **かつ** 反則注入後に首位が変わる
決定点も 20% 未満」。**k\* 側がどちらの相手でも 20% を超える**ので、AND 条件の
中止条件には該当しない。ただし枝ごとに強さが違う:

- **α（価格）は生きている**。型1（issue の 61手番 / 118反則の塊）で k\* の中央値
  **2.80 / 4.32**、k ≤ 3 で **43.5% / 40.0%** が玉の手へ反転する。
  **型2（kakutori 型）は価格では動かない**（4.2% / 17.5%・中央値 5〜8）ので、
  **α を型で切らずに一律に掛けると型2 の捕獲プローブまで沈む**
- **β（動的継続価値）の支持は弱い**。生の「静的な次点と違う」率 61〜70% のうち
  **44〜60% はノイズ床**（反則の観測を入れなくても起きる）で、**正味は
  v14 18.9% / v13 15.2% = どちらも 20% 未満**。
  型別では **型2 の正味だけが 22.5〜28.0%** と 20% を超え、型1 は 7.7〜11.5%。
  つまり「反則を観測して候補順位が動く」のは kakutori 型のほうで、
  **玉逃げに落ち着く型1 では信念更新はほとんど効いていない**

### 再決定そのもののノイズ床が 44〜60% ある

対照（A）は B と**同じ prewarm 済み instance の clone・同じ視界（＝同じ残り反則＝
同じ価格）・同じ除外集合**で、反則の観測だけを入れずに選び直したもの。それでも
初回ランキングの次点と 44〜60% で食い違う。原因は `choose` のたびに
`Estimator::update` が壁時計デッドラインまで若返らせること（同じ入力でも粒子集合が
変わる）。**現行方策は同じ局面で選び直すだけで候補順位がこれだけ動く**。

これは issue #24 の教訓（「測定そのもののノイズが門と同じ大きさ」）の再現で、
**オフラインの再ランキング診断はすべてこの床を踏む**。H2 のように「順位が変わったか」を
数える指標は、**対照を同じ配管で取ってペア差で見ないと意味を持たない**
（初版は生の値を報告していて「66〜75% で次善手固定の仮定が外れる」と読んでいた。
run 33149098094 のその数字は撤回する）。

### 読み方の限界

- **初回ランキングの首位が実戦の最初の反則と一致するのは 64〜67%**。k\* の分布は
  「実戦のその決定そのもの」ではなく「**同じ状態から現行方策が引き直したときの
  分布**」と読むこと
- k\* は**ランキングがどれだけ動くか**の感度であって価格の測定ではない
  （価格の水準は P0-7 の影の価格。単位が勝率で、`foul_cost` の評価点とは
  曲線の形しか比べられない）
- 「反転しない unit」（kmax=30 まで玉の手が首位にならない）は v14 91 / v13 40。
  玉の手の p が低い決定点では**価格では原理的に反転しない**
