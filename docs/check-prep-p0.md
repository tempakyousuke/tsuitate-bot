# 被王手の**前**の準備（王手耐性）P0（issue #34）

**位置づけ**: #28（詰み経済）と #31（王手中の反則経済）は、どちらも
「機構は動く・反則は減る・勝率に変換されない」で閉じた。#31 が測ったのは
**王手が来てから**の価格・順序・較正で、**王手が来る前の形**は測っていない。
ここで測るのは「王手が来たときの出口の本数と質が、王手前の自駒配置で
決まっているか」。

**runtime には何も入らない**（`bin/analyze` の集計セクションと
`bin/check_prep_probe` を足しただけ。粒子も回さない）。

| 段 | 何を識別するか | 実装 | 状態 |
| --- | --- | --- | --- |
| P0-1 連続王手の起点 | 指導4（玉がいた位置に王手の原因の駒がいる）の実測 | `bin/analyze` | 実装済み・計測済み |
| P0-2 較正プローブ | H1 / H2 と統計的 H0 | `bin/check_prep_probe` | 実装済み・計測済み |

段は**前が落ちたら次へ進まない**順序で並んでいる（issue #34 の中止条件）。

## 特徴量（`src/check_prep.rs`）

すべて `PlayerView` 相当（自駒＋持ち駒＋観測ログ）だけから決まるので値そのものに
ノイズは無いが、**意味は楽観上限**である: 飛び駒の利きは**自駒にしか遮られない**
（隠れた敵駒・ピン・両王手は扱わない）し、「空きマス」は「自駒がいないマス」。
名前もそのとおりに付けてある（`potential_covered` / `potential_flight`）。

- **F1 王手起点の潜在被覆**: 自玉 K に対する**王手起点マス集合 C(K)** は
  **玉位置ごとの固定集合**（盤端までの8方向の距離2以上の全マス＋桂の跳び起点2マス）。
  **自駒で止めない**のが要点で、自駒を置いて未被覆マスを集合から消せると
  「分母を縮めて被覆率を上げる」分母操作が成立してしまう。
  桂 / 直線 / 斜線を別列にし、**確定利き**（歩・桂・金銀の歩進）と
  **楽観レイ**（飛角香）も別列に持つ。**隣接8マスは F3 の領分で F1 には持たない**
  （説明力を見てどちらかを選ぶのではなく、設計時点で分担を固定する）
- **F2 攻撃面と潜在逃げ道**: `open_dirs`（盤端まで自駒に遮られていない方向）/
  `open_len`（自駒に当たるまでの連続マス数の合計）/ `flight_all`（隣接の自駒非占有）/
  `flight_shielded`（そのうち距離2が盤外か自駒 = 逃げ先の背後がすぐ塞がっている）。
  **P0 の診断専用**で P1 の arm には入れない
- **F3 隣接の状態数**: 8近傍を `自駒非占有・非被覆 / 自駒非占有・被覆 / 自駒占有` の
  3状態で数える（第1状態が現行 `king_holes`）。加えて**占有の有無によらない
  隣接の被覆数** `adj_covered` を持つ（下記の実測で王手の 8 割が隣接から来るため）
- **F4 出発マスの被覆**: 玉の手について「出発マスに**着手後も**玉以外の自駒の
  利きがあるか」

`K` は3つを区別する（issue #34 の用語）: `K_def_truth`（真実盤面の全合法手数）/
`K_def_gen`（診断側の候補生成のうち真に合法な本数）/ `K_def_runtime`
（観測ログ込みの runtime 候補生成での本数）。

## P0-1 連続王手の起点（`bin/analyze`）

「bot が玉の手で王手を解消 → 次の相手手番で再び王手」を取り出し、2回目の
真の王手駒を **(a) 前の玉位置 / (b) その隣接 / (c) それ以外** に分ける。
「前回と同じ駒が追った」は位置分類と混ぜず**別軸のフラグ**、両王手は別層で
「全王手駒を除去可能か」を手番単位で判定する。

**門は「(a)+(b) が過半」ではない**（頻度が高くても、被覆の有無で反則が変わらないなら
形を変える意味が無い）。`(a) の頻度 × F4 有無による反則差` と
`(b) の頻度 × 実王手駒マス被覆の有無による反則差`を**別々に**出し、
元対局 cluster CI を付けて合算も出す。

## P0-2 較正プローブ（`bin/check_prep_probe`）

**単位は「bot の全 handoff」**（= bot が受理手を指し終えた時点 = P1 が変えられる配置）。
被王手手番だけに条件づけると `F → 被王手 ← 相手の攻撃力 → K・反則` の
**collider** が開き、形に直接効果が無くても分離してしまう。
**主目的変数は「次の bot 手番に発生した王手中反則数」**（次に王手されなければ 0）。

計測時点は3つ: `pre`（直前の bot 受理手より前）/ **`handoff`（主 exposure）** /
`entry`（相手の王手着手後）。主解析は `handoff` の F と `pre→handoff` の差分で、
`entry − handoff` は「王手手が形を壊した量」として別列に持つ。

**終端の手番**（反則負けなどで受理手が無く `end.moves` に現れない手番）も
`check_prep::decision_snapshots` が1つ足す。落とすと**反則を積んで終局した手番だけが
系統的に欠測**して、門が甘くなる方向へ偏る。

段は3つ:

1. **構成概念検証**: 「実際の王手駒を玉以外で真に合法に取れたか」（oracle）を
   起点の被覆がどれだけ再現するか。**主指標は適合率**で、リフトではない —
   「被覆なし → oracle 陰性」はほぼ**論理的帰結**（被覆は真の利きの楽観上限なので、
   被覆が無ければ真の取り手も無い）で下駄を履いている。例外は handoff から entry の
   間に王手手が形を壊した場合だけ。
   **層ごとに独立の門を出す**（F1 = C(K)（距離2以上）/ 隣接 = F3 の領分 /
   両王手 = 別層）。層を分けずに1つの適合率にすると、実測で 8 割を占める隣接
   （別概念）が F1 の門を支配してしまう。**段3へ進む条件は F1 層の門**
   （主 estimand が F1 由来だから）で、**適合率の cluster CI 下限 > 0.5 かつ
   リフトの CI 下限 > 0**
2. **発火母数**（`anchor_probe` の教訓）: 観測された王手中反則のうち、直前の
   handoff の候補手の中に F を改善する到達可能な手があった割合。門は 20% 未満で中止
3. **主 estimand**: 層を固定したうえで主特徴量を Q90 / Q10 に置いたときの
   **周辺平均差**。モデルは **hurdle 分解**に固定（反則あり = ロジスティック /
   ありの場合の回数 = **ゼロ切断＋上側打ち切り** Poisson。`y == 残り反則` は
   「その手番で反則負けした」= `Y ≥ cap` としてしか分からないので上側確率で入れる）。
   合成する第2段は**観測される回数の期待値そのもの**
   `E[min(Y,cap)|Y>0] = Σ_{k=1}^{cap-1} k·P(Y=k|Y>0) + cap·P(Y≥cap|Y>0)`
   で、`min(E[Y|Y>0], cap)` の頭打ちでは**ない**（一般に一致しない。λ=1 / cap=2 で
   1.4180 vs 1.5820）。尤度側が上側打ち切りを扱っているのに g-computation でだけ
   別の量へ戻ると、判定値が静かにずれる。
   **係数は個別に読まない**（hurdle の2段の係数は符号が逆を向きうる）。
   secondary は Holm 補正で、**主特徴量は名前で保持する**（当てはめが落ちた特徴量を
   詰めると、繰り上がった secondary が「事前登録の主」として無補正で表示される）。
   当てはめが収束しなかった draw は捨てるので、**有効 draw が半数未満の bootstrap は
   CI を出さない**

層・共変量（総効果の回帰で調整する）: 手数・玉位置（盤端距離）・自駒数・持ち駒・
材料差・自玉周辺の自駒密度・残り反則・候補数・先後。**`K_def_*` と機構列は
入れない**（狙っている媒介変数と結果側の変数だから）。CI は元対局 cluster bootstrap。

### 元 Arena 実行の実験条件の検査

主回帰の前提は「同一 build / config の記録だけ」だが、**記録（JSONL）の `match` /
`end` にあるのは戦略名と相手名だけ**で、CSV meta の `source_fingerprint` は
解析バイナリの版でしかない。そこで `check-prep.yml` は同じ run の

- `arena-result-<相手>-s*/arena-summary.json`: candidate / baseline / 実効設定の指紋
  （`cand_config` / `baseline_behavior` / `cand_knobs`）/ 局数 / 時計 / 思考予算
- `arena-result-<相手>-s*/arena-games.jsonl`: commit と `match_seed`
- `arena-combined/combined.json`: 全シャード合算の局数

も取り、**シャード集合が 0..n-1 で完備・実効設定が全シャードで一致・
局数と記録の本数が一致・合算局数と一致**を確かめてから解析する。
`expect_candidate` / `expect_match_seed` / `expect_games` を渡せば期待値との照合も
入る。**検証セットでは `expect_match_seed` を必ず渡す**（発見セットと独立な seed で
あることを機械的に固定するため）。どれか1つでも外れたら解析を進めない。

**事前登録の主 estimand は両相手とも CI が 0 を跨ぐ**（v14 は上限 +0.0011 の境界、v13 は明確に
null）。判定は「v13 / v14 の両相手で同方向かつ有意」なので、**統計的 H0 を棄却できない**。
調整済みでも、有意になるのは v14 の F1 と v13 の隣接で**相手が入れ替わる**。

一方で**符号は4つの量すべてで両相手一致している**、というのがこの段の実質的な所見:

- **F1（距離2以上の起点の被覆）は負** = 遠隔の王手起点に利きを作ると反則が減る（指導1 の向き）
- **隣接の被覆は正** = 隣接を被覆すると反則が**増える**（指導3 と逆の向き）
- **`f3_open_uncovered`（穴の数）は負** = 穴が多いほうが反則が少ない（= 逃げ道が要る）

**この2つは逆を向いているので、混ぜた `f13_cov` は打ち消し合ってゼロになる**
（v14 +0.0031）。「王手起点の被覆」という**単一の構成概念は成立していない**: F1 と隣接は
別物として扱わなければならない（issue #34 の P1 が arm を F1 単独 / F3 単独 / F1+F3 と
分けていたのは、この意味で正しい設計だった）。指導2（逃げる）と指導3（固める）の衝突も、
`f3_open_uncovered` が負であることに現れている。

なお `--origin-weights` / `--adj-share` は P0-2 の出力がそのまま貼れる形で出す
（発見セットの実測: v14 `knight:34,line:51,diag:17;d2:66,d3:21,d4:8,d5+:7` / `--adj-share 0.83`、
v13 `knight:29,line:31,diag:26;d2:65,d3:13,d4:4,d5+:4` / `--adj-share 0.84`）。

## P0 の判定（2026-08-29）

**この形のままでは検証セットへ送らない**。

- 段1（構成概念検証）と段2（発火母数）は両相手で通過している。**特徴量は測りたいものを
  測れているし、方策が動かせる候補も在る**（「浮かせたい候補が無い」型の失敗ではない）
- しかし段3の主 estimand は**両相手とも 0 を跨ぐ**。効果量は v14 で −0.030 反則/手番、
  v13 で −0.014。CI 幅から SE は約 0.017（v14）なので、**同じ効果量を両相手で有意にするには
  各相手 200〜300局が要る**（104局では検出力が足りない）
- 事前登録の中止条件のうち「主特徴量の CI が 0 を跨ぐ」に**発見セットの段階で**該当した。
  発見セットの役割は定義と重みを固定することなので、ここで null なら同じ定義を検証セットへ
  送っても null しか出ない

次に進むなら、選択肢は3つ（**どれも P1 の実装ではなく計測の作り直し**）:

1. **標本を増やす**（各相手 200〜300局の Arena を新しい `match_seed` で取り、
   同じ定義のまま測り直す）。効果量が本物なら検出力の問題として解ける。
   **記録の再利用でコストはゼロにならない**（新しい対局が要る）ことに注意
2. **主特徴量を2本立てに事前登録し直す**: F1 と隣接は符号が逆なので、
   「王手起点の被覆」を1本の量にまとめるのをやめ、**F1 単独**と**隣接被覆**を別々の主として
   登録する。実測分布（隣接 83%）を `--adj-share` に入れて混ぜるのは、
   **逆向きの2つを平均する**ことになりむしろ効果を消す
3. **打ち切る**。#28・#31 は「機構は実在するが勝率へ変換されない」で閉じたが、
   ここはその手前で「**形と反則の関連自体が 104局では検出できない**」。
   反則の 8 割が隣接起点から来ていて、隣接の被覆はむしろ反則を増やす向きなので、
   「王手前に形を作る」施策の余地はもともと薄い、という読み方もできる

**P0-3（w\* 監査）と P0-4（一手強制の局所継続）は実装していない**。段3が落ちた以上、
「浮かせたい候補が首位になるか」を測っても、その候補が反則を減らす根拠が無い。
段3を通してから作ること。

## 落とし穴（同種の判定をやり直すときに先に読む）

- **被王手手番に条件づけない**。`F → 被王手 ← 相手の攻撃力 → K・反則` の collider が開く。
  実際、issue 本文の「出口≤1本が 37%」は反則した手番に条件づけた値で、条件づけない分布では
  11.9〜24.0% だった
- **構成概念検証をリフトで読まない**。被覆は真の利きの楽観上限なので「被覆なし → oracle 陰性」は
  ほぼ論理的帰結で、リフトは下駄を履く（実測 +0.95）。中身は適合率のほう
- **終端の手番を落とさない**。反則を積んで終局した手番は `end.moves` に現れないので、
  素直に決定点を回すと**反則が多い側が系統的に欠測**する
- **F1 と隣接を1つの量に混ぜない**。符号が逆なので混合は効果を消す
- **主 estimand を係数で読まない**。hurdle の2段の係数は符号が逆を向きうるので、
  合成した周辺平均で読む
