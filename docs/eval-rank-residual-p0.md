# 人手採点を候補手評価へ戻す — P0（棋譜外へ一般化するかの判定）

2026-08-26。issue #24 の P0。**この文書は P0 の記録**で、P1（bounded residual の
runtime 統合）へ進むかどうかの判断を「判定」節に書く。

## 位置づけ（変えないこと）

- P0 の目的は二択を決めること: ①棋譜外へ一般化する信号がある → 小さな残差モデルを
  P1 で統合する ②同一棋譜の暗記しかできない → **実装せず**、必要な追加レビュー数と
  局面層を確定する
- scenario suite を arena の代わりにしない。**最終採否は通常 arena のガントレット**
- `value_nn`（勝敗教師）を置き換えない。人手の局所順位教師とは役割が違う
- 未採点候補を悪手として扱わない（`?` は欠測）
- 真実盤面・実戦の正解手・コメント文・棋譜名を実対局の特徴量に入れない

## 実装

| 部品 | 場所 | 役割 |
| --- | --- | --- |
| eval → 決定点の復元 | `src/eval_rank.rs` | `## N手目` → `ply = N-1`、`### N手目（和名(USI)の反則後）` → 同じ ply ＋ 元棋譜の `*illegal` をその USI まで注入。元 KIF は `scenarios/archive/<eval名>.kif`（無ければ `scenarios/<eval名>.kif`） |
| 特徴量 | `eval_rank::feature_row` | 入力は `PlayerView` と `CandidateScore` **だけ**。46列（内訳・候補集合内の位置・状態・着手） |
| エクスポータ | `bin/export_eval_rank_data` | 決定状態 × seed で `choose` → 候補ランキングと採点を結合して CSV ＋ summary JSON |
| 分析 | `scripts/eval_rank/fit_residual.py` | leave-one-source-KIF-out ＋ 訓練 fold 内の nested CV（α）。pairwise ridge |

### 復元の関門（黙って落とさない）

- 復元した `(ply, fouls)` に対応するシナリオ kif があれば `scores=` の**完全一致**を
  検査し、ずれたら停止する。反則後ブロックの対応が `foul_blocks.py` の FOUL_MAP と
  一致することも `cargo test 反則後ブロックの対応がpython側の表と一致する` が検査する
  （別の手目・別の反則後サブ状態へ接続する事故は PR #3 で実際に起きた）
- **採点済みなのに現行候補集合に無い手**は `in_candidates=0` の行として残す。
  黙って落とすと候補生成 recall が測れず、「未採点候補の除外による見かけの改善」と
  同じ穴が分析側に開く
- 現行候補にあるが eval に未収載の手、ランキングが取れなかった決定状態も summary に件数で出る

### 特徴量の健全性

`feature_row` の入力は自分側の完全既知情報（`PlayerView`）と bot 自身が計算した
内訳（`CandidateScore`）だけで、`Position`（真実）は型として渡らない。
`cargo test 特徴量は相手の駒配置に依存しない` が「相手の駒を全部消した別の真実」から
作った view で行が変わらないことを実測で確かめる。
タイブレーク乱数は `CandidateScore::tiebreak` へ分離したので、特徴量に載る `adjust` は
乱数を除いた決定的な補正だけ。USI 文字列・絶対マスの one-hot・棋譜名・ply の固有 ID は
そもそも列に無い。

### 分割（ここを間違えると全部無意味になる）

採点 5,035 件のうち **94.4% が `quest_20260731` と `quest_0809` の2局由来**なので、
行・候補・決定点のランダム分割はほぼ確実にリークする。分割単位は元 KIF だけにし、
同じ棋譜の通常ブロック・反則後ブロック・全 seed を必ず同じ fold へ置く。
主評価は leave-one-source-KIF-out、α は訓練 fold 内の nested CV（これも元 KIF 単位）。
指標は source KIF ごとの macro 平均で、行の micro 平均は主張に使わない。
seed は独立標本として数えない（決定状態ごとに平均してから状態を平均する）。

### bounded residual（P1 の統合形）の W スイープ

素の残差ランカーは現行 score を捨てた形なので不利だ、という反論を潰すために、
issue の P1 が提案する `pred = score + W × cap × tanh((r − r̄)/cap)`（cap=2点）を
そのまま holdout で掃いた。**W=0 は現行と完全一致**。

| W | top-1 平均得点 | 0〜2点 top-1 率 | 未採点手を選んだ率 | concordance |
|---:|---:|---:|---:|---:|
| 0 | **5.862** | 0.301 | 0.053 | 0.735 |
| 0.1 | 5.850 | 0.303 | 0.053 | 0.744 |
| 0.25 | 5.778 | 0.303 | 0.057 | 0.748 |
| 0.5 | 5.838 | 0.272 | 0.088 | 0.758 |
| 1 | 5.753 | 0.304 | 0.062 | 0.763 |
| 2 | 5.813 | 0.281 | 0.086 | 0.782 |
| 4 | 5.717 | 0.313 | 0.066 | 0.788 |

**これが P0 の核心**: concordance は W に対して**単調に上がる**（0.735 → 0.788）のに、
**top-1 平均得点はどの W でも現行を超えない**。学習しているのは「採点済みの手どうしの
並べ方」であって「実際に指す手」ではない。同じ形が既に3度観測されている
「未採点手への逃避で見かけの改善が出る」の**モデル版**で、今回は逃避が指標を
上げるのでなく下げる側に出た。

### 層別・seed・学習曲線

- 層別（holdout 予測のみ）: 被王手 6.01 → 4.92・反則後 4.86 → 3.55 と**小さい eval 群で
  大きく逆行**する。改善らしきものは序中盤の concordance +0.010 程度
- seed を変えたときの選択一致率は 0.626 → 0.644（粒子揺れへの頑健性は変わらない）
- 学習曲線（訓練に使う元 KIF を 1..7 本に振る）: concordance 差は
  −0.030 / +0.028 / +0.022 / +0.010 / +0.017 / +0.041 / +0.040、**標準偏差は
  どこでも ±0.28**。飽和ではなく、**分散が「どの棋譜を holdout にしたか」で
  決まっている**（棋譜数が本数として律速）

### 学習された係数（全データ・α=3000、標準化後）

`static_gain +1.10` / `to_rank_own +1.04` / `dist_own_king −1.02` /
`checker_removal −0.86` / `risk +0.83` / `gain +0.63` / `is_drop −0.60` /
`value_nn −0.49` / `mover_value −0.40`。
`score` 係数 +0.10 に対しそれ以外のノルム 2.58 なので、**現行 score の再現では
ない**（暗記でもない: USI・絶対マスは列に無い）。

方向は `bin/eval_features` の局面内中心化回帰（玉候補距離1 +1.08 / 安さ +0.88 /
打ち −0.43）と一致する。目新しいのは **`value_nn` の係数が負**なこと =
人手の局所順位は value ネットとマージンで食い違う。ただし上のとおり、この一致は
**選ぶ手の改善には変換されていない**。

## 判定

**P0 不合格。runtime 実装（P1）をしない。**

| 合格条件 | 実測 | 判定 |
|---|---|---|
| 大きい quest 2局の完全 holdout で top-1 得点 +0.5 以上 **または** 0〜2点 top-1 率 25% 以上の相対減 | 0809: −0.78 / −53.6%、31: −0.99 / +21.9% | 否 |
| macro pairwise concordance +5pt 以上 | +0.040 | 否 |
| 被王手・反則後の小さい eval 群で top-1 −0.5 超の逆行がない | 最悪 −1.00（foul03） | 否 |
| 改善が未採点候補の除外・特定USI/マスの暗記・1棋譜で説明されない | **未採点選択 5.3% → 16.1%**、fold 間で concordance の符号が反転（+0.026 / +0.010 / −0.092 / −0.192 / −0.141 / +0.712 / +0.002 / −0.006） | 否 |

中止条件のうち **「source-KIF holdout で改善が消える / 符号が局ごとに反転する」**と
**「top-1 得点は上がらず、順位一致だけが上がる」**の2つに当たる。

**候補生成は律速ではない**（recall 99.7%）ので、issue が用意していた分岐
「candidate recall が低ければ次 issue を候補生成の多様化へ切り替える」は**該当しない**。

## 再判定に要るもの（issue の「追加4局」を具体化する）

方向自体（人手の局所順位に情報がある）は否定されていない。concordance が W に
単調なのは信号が実在する証拠で、実際 `value_nn` との食い違いのような使える所見も出た。
再判定するなら、**先に2つの構造問題を直す**。順番が逆だと同じ結果が出る。

1. **採点の被覆を、方策が到達しうる範囲まで広げる**（今回の主因）。
   候補 113.8 手のうち採点は 18.3 手（16.1%）で、現行 top-10 でも 77.5% しか
   採点されていない。順位を組み替える器を入れる以上、**その器が持ち上げる手が
   採点済みでなければ測れない**。既存の `append_unscored.py` ループ（候補ノブで
   suite → 2回以上選ばれた未収載手を `?` 追記 → 採点 → `sync_eval.py`）を、
   実験ごとでなく**学習ループの内側**へ入れる必要がある。
   概算コスト: 現行の被覆（上位15）を上位30へ広げるだけで
   1棋譜あたり +約9手/決定点 ×約100決定点 = **+900手の採点**
2. **独立棋譜を増やす**。採点の 94.4% が2局由来で、学習曲線の標準偏差は
   本数によらず ±0.28。±0.05 の門をこの分散で判定できない。
   追加は**既存2局の近傍でなく対人実戦から**、先後・序中終盤・被王手・反則後で
   層化して**4局以上**（8 → 12 クラスタで fold あたりの重みが 1/12 になる）

この2つが済むまで、人手採点は**目的関数（suite / SPSA）としてだけ使う**という
現状の役割を変えない。`bin/export_eval_rank_data` と `scripts/eval_rank/fit_residual.py`
は、採点が増えたときに同じ判定をやり直すための配管として残す（既定挙動は不変）。
