# 人手採点を候補手評価へ戻す — P0（棋譜外へ一般化するかの判定）

2026-08-26。issue #24 の P0。**この文書は P0 の記録**で、P1（bounded residual の
runtime 統合）へ進むかどうかの判断を「判定」節に書く。

## 位置づけ（変えないこと）

- P0 の目的は二択を決めること: ①棋譜外へ一般化する信号がある → 小さな残差モデルを
  P1 で統合する ②同一棋譜の暗記しかできない → **実装せず**、必要な追加レビュー数と
  局面層を確定する
- scenario suite を arena の代わりにしない。**最終採否は通常 arena のガントレット**
- `value_nn`（勝敗教師）を置き換えない。人手の局所順位教師とは役割が違う
- 未採点候補を悪手として扱わない（`?` は欠測）
- 真実盤面・実戦の正解手・コメント文・棋譜名を実対局の特徴量に入れない

## 実装

| 部品 | 場所 | 役割 |
| --- | --- | --- |
| eval → 決定点の復元 | `src/eval_rank.rs` | `## N手目` → `ply = N-1`、`### N手目（和名(USI)の反則後）` → 同じ ply ＋ 元棋譜の `*illegal` をその USI まで注入。元 KIF は `scenarios/archive/<eval名>.kif`（無ければ `scenarios/<eval名>.kif`） |
| 特徴量 | `eval_rank::feature_row` | 入力は `PlayerView` と `CandidateScore` **だけ**。46列（内訳・候補集合内の位置・状態・着手） |
| エクスポータ | `bin/export_eval_rank_data` | 決定状態 × seed で `choose` → 候補ランキングと採点を結合して CSV ＋ summary JSON |
| 分析 | `scripts/eval_rank/fit_residual.py` | leave-one-source-KIF-out ＋ 訓練 fold 内の nested CV（α）。pairwise ridge |

### 復元の関門（黙って落とさない）

- 復元した `(ply, fouls)` に対応するシナリオ kif があれば `scores=` の**完全一致**を
  検査し、ずれたら停止する。反則後ブロックの対応が `foul_blocks.py` の FOUL_MAP と
  一致することも `cargo test 反則後ブロックの対応がpython側の表と一致する` が検査する
  （別の手目・別の反則後サブ状態へ接続する事故は PR #3 で実際に起きた）
- **採点済みなのに現行候補集合に無い手**は `in_candidates=0` の行として残す。
  黙って落とすと候補生成 recall が測れず、「未採点候補の除外による見かけの改善」と
  同じ穴が分析側に開く
- 現行候補にあるが eval に未収載の手、ランキングが取れなかった決定状態も summary に件数で出る

### 特徴量の健全性

`feature_row` の入力は自分側の完全既知情報（`PlayerView`）と bot 自身が計算した
内訳（`CandidateScore`）だけで、`Position`（真実）は型として渡らない。
`cargo test 特徴量は相手の駒配置に依存しない` が「相手の駒を全部消した別の真実」から
作った view で行が変わらないことを実測で確かめる。
タイブレーク乱数は `CandidateScore::tiebreak` へ分離したので、特徴量に載る `adjust` は
乱数を除いた決定的な補正だけ。USI 文字列・絶対マスの one-hot・棋譜名・ply の固有 ID は
そもそも列に無い。

### 分割（ここを間違えると全部無意味になる）

採点 5,035 件のうち **94.4% が `quest_20260731` と `quest_0809` の2局由来**なので、
行・候補・決定点のランダム分割はほぼ確実にリークする。分割単位は元 KIF だけにし、
同じ棋譜の通常ブロック・反則後ブロック・全 seed を必ず同じ fold へ置く。
主評価は leave-one-source-KIF-out、α は訓練 fold 内の nested CV（これも元 KIF 単位）。
指標は source KIF ごとの macro 平均で、行の micro 平均は主張に使わない。
seed は独立標本として数えない（決定状態ごとに平均してから状態を平均する）。

### 指標の作り方（PR #25 の3回のレビュー反映）

初版から3回直している。**4件とも「残差ランカーが良く見える」側へ効いていた**ので、
同種の判定をやり直すときは先にここを読むこと。

- **未採点の top-1 を仮の点で埋めない**。`?` は欠測という契約どおり、得点系は
  「top-1 が採点済みの決定状態」だけで条件つきに数え、「未採点手を選んだ率」を
  別指標にする。仮 4 点で混ぜると、未採点選択が増える側の腕の得点が実点次第で反転する
- 条件つきの平均は腕ごとに母集団が変わるので、**合否も CI も「両腕とも top-1 が
  採点済み」の決定状態だけの対比較**（`paired_metrics`）で出す
- **未採点への逃避が増えたら判定を止める**（許容 +0.01）。**macro だけでなく
  大きい quest 1局ごとにも見る**: macro の関門だけだと、その局で逃避が増えても
  他クラスタで減れば相殺されて通る（実測でも macro +0.125 に対し
  quest_0809 は +0.366・quest_20260731 は +0.348 と、局ごとに見ると3倍近い）
- **タイブレーク乱数はどの特徴量にも載せない**。`adjust` だけでなく `score` /
  `static_score` も乱数を含むので3つとも引く。順位系は `det_order`（乱数を除いた
  スコア）で付け直し、**完全同点は USI の辞書順で割る**（安定ソートに任せると
  乱数の並び順がそのまま `rank` / `rank_frac` に残る。実測で決定的スコアが完全同点の
  候補は 8,145 件、1,088 決定状態×seed のうち 706 = 65% に存在した）
- **P1 の統合形は順位番号でなく実スコアへ合成する**。乱数込みの実スコアを
  非特徴列 `engine_score` として出し、baseline の再現と
  `engine_score + W·cap·tanh(残差/cap)` の数値合成に使う。順位番号
  （`engine_rank`）へ残差を足すと候補間の実スコア差が消え、同じ残差でも順位差だけで
  逆転可否が決まる別物になる。`engine_rank` は現行順位の監査用として残す
- **`engine_score` を丸めない**。`{:.6}` で出すと 5.0000004 と 5.0000003 が同値になり、
  現行方策では順位がついている候補が CSV 上で同点になる（実測で
  **1,088 決定状態×seed のうち 19 件**が該当した）。Rust の既定表示（round-trip する
  最短表現）で出し、読み込み時に「`engine_score` の降順が `engine_rank` の昇順と
  厳密に一致する」ことを検査して、崩れたら停止する

### 測定そのもののノイズ（**+0.05 の門は1本の測定では判定できない**）

思考予算が壁時計ベースなので、同じコード・同じ設定でもエクスポートのたびに粒子数が
揺れる。素の残差ランカーの評価経路が同じ3本を並べると:

| エクスポート | macro concordance の差 | macro 対比較 top-1 の差 |
|---|---:|---:|
| `det_order` 修正後 | −0.010 | −0.283 |
| `engine_score` 追加後 | +0.019 | −0.027 |
| `engine_score` 丸め撤去後 | **+0.050** | −0.786 |

**門（+0.05）はこのばらつきの中に完全に入る**。3本目はちょうど門と同値になったが、
これは効果ではなく分散。**concordance の符号や合否を1本の測定で論じてはいけない**。

一方で**他の4条件は3本とも同じ向き**に出る: 大きい quest 2局の対比較 top-1 は
常に負、小さい eval 群の逆行、fold 間の符号反転、未採点への逃避（局ごとに +0.2〜+0.37）。
P0 の判定はこちらで確定している。

### 採点の被覆（**これが効き方を決めている**）

- 1決定状態あたりの候補 **113.8 手、うち採点済み 18.3 手（16.1%）**
- 現行 score の **top-1 が採点済み 91.6% / top-3 85.3% / top-10 75.7%**
- 採点済みなのに現行候補集合に無い手は 204 行（**候補生成 recall 99.7%**）

`make_eval` は「その時点の上位15候補＋実戦手」しか列挙しないので、順位学習の教師も
評価指標も採点済みの部分集合しか見られない。一方**argmax はいつでも未採点側へ
逃げられる**。

### 素の残差ランカー（現行 score を捨てた形）

両腕とも top-1 が採点済みの決定状態だけの対比較:

|---|---:|---|---|
| arena-check-flee02 | 1 / 1 | 10.00 → 10.00 | 0.000 → 0.000 |
| arena-check-flee03 | 1 / 1 | 10.00 → 10.00 | 0.000 → 0.000 |
| arena-check-flee04 | 1 / 1 | 7.50 → 7.00 | 0.000 → 0.000 |
| arena-check-foul02 | 5 / 7 | 3.40 → 2.60 | 0.500 → 0.600 |
| arena-check-foul03 | 7 / 7 | 4.00 → 2.54 | 0.667 → 0.893 |
| arena-recap01 | 1 / 1 | 4.00 → 2.00 | 0.750 → 1.000 |
| **quest_0809** | 86 / 106 | 5.19 → **4.34** | 0.091 → 0.131 |
| **quest_20260731** | 108 / 148 | 5.10 → **4.43** | 0.336 → 0.430 |
| **macro** | — | **6.148 → 5.362** | 0.293 → 0.382 |

条件つき macro（母集団が動くので参考）: 8〜10点 top-3 recall 0.684 → 0.402・
**未採点手を選んだ率 0.027 → 0.133**・pairwise concordance 0.758 → 0.808。

**十分な状態数のある2局はどちらも下がる**（−0.85 / −0.67）。これは3本のエクスポート

### bounded residual（P1 の統合形）の W スイープ

`pred = engine_score + W × cap × tanh((r − r̄)/cap)`（cap=2点）。**W=0 は現行と
完全一致**。得点は W=0 との対比較。

| W | macro top-1 得点 W=0→W | macro 0〜2点 top-1 率 | quest_0809 の差 | quest_20260731 の差 | 未採点率 | concordance |
|---:|---|---|---:|---:|---:|---:|
| 0 | 6.197 → 6.197 | 0.293 → 0.293 | ±0 | ±0 | 0.027 | 0.758 |
| 0.1 | 6.199 → 6.345 | 0.293 → 0.290 | +0.091 | +0.003 | 0.026 | 0.772 |
| 0.25 | 6.198 → 6.284 | 0.293 → 0.292 | +0.081 | −0.002 | 0.025 | 0.783 |
| 0.5 | 6.198 → 6.211 | 0.293 → 0.291 | +0.024 | +0.074 | 0.024 | 0.786 |
| 1 | 6.199 → 6.137 | 0.293 → 0.287 | −0.028 | +0.176 | 0.024 | 0.797 |
| 2 | 6.290 → 6.129 | 0.281 → 0.288 | −0.159 | +0.283 | 0.056 | 0.826 |
| 4 | 6.159 → 5.959 | 0.291 → 0.308 | −0.147 | +0.098 | 0.067 | 0.825 |

**大きい2局は W ごとに符号が入れ替わり、互いに逆を向く**（W=2 で −0.159 / +0.283）。
エクスポートを変えると値も入れ替わる（前回は W=2 で −0.025 / +0.131）ので、
系統的な効果ではない。concordance だけが W に単調（0.758 → 0.826）なのは
3本とも共通 ——**順位は揃うが、指す手は良くならない**。

### 層別・seed・学習曲線

- 層別（holdout 予測のみ・条件つき）: 被王手・反則後の小さい eval 群で逆行が出る
- seed を変えたときの選択一致率は上がるが、**良い兆候ではない**: 残差ランカーは
  粒子由来の項への依存が薄いぶん決定が安定するだけで、安定して悪い手を選んでいる
- 学習曲線（訓練に使う元 KIF を 1..7 本に振る）: 標準偏差はどこでも ±0.16〜0.19 で、
  本数を増やしても縮まない。**分散が「どの棋譜を holdout にしたか」で決まっている**

### 学習された係数

大きいのは `static_gain` / `to_rank_own` / `static_score` / `dist_own_king`（負）/
`checker_removal`（負）/ `risk` / `is_drop`（負）/ `mover_value`（負）。
`score` 単体の係数よりそれ以外のノルムの方が1桁大きいので、**現行 score の再現では
ない**（暗記でもない: USI・絶対マスは列に無い）。向きは `bin/eval_features` の
局面内中心化回帰（玉候補距離1 +1.08 / 安さ +0.88 / 打ち −0.43）と一致する。
ただしこの一致は**選ぶ手の改善には変換されていない**。

## 判定

**P0 不合格。runtime 実装（P1）をしない。**

| 合格条件 | 実測 | 判定 |
|---|---|---|
| 大きい quest 2局の完全 holdout で top-1 得点 +0.5 以上 **または** 0〜2点 top-1 率 25% 以上の相対減 | 0809: −0.85 / −43.6%、31: −0.67 / −28.0%（いずれも対比較。3本のエクスポートすべてで負） | 否 |
| macro pairwise concordance +5pt 以上 | +0.050（**ただし3本で −0.010 / +0.019 / +0.050 と門をまたいで散る**ので、1本では判定できない） | 判定不能 |
| 被王手・反則後の小さい eval 群で top-1 −0.5 超の逆行がない | 最悪 −2.00（arena-recap01） | 否 |
| 改善が未採点候補の除外・特定USI/マスの暗記・1棋譜で説明されない | fold 間で concordance の符号が反転（+0.000 / +0.008 / −0.079 / +0.109 / −0.079 / +0.450 / −0.006 / −0.002） | 否 |
| 未採点への逃避が増えていない（許容 +0.01） | macro 0.027 → 0.133、**quest_0809 +0.236 / quest_20260731 +0.291** | 未確定 |

中止条件のうち **「source-KIF holdout で改善が消える / 符号が局ごとに反転する」**に
当たる。concordance の行だけは1本の測定では判定できないが、**それが通ったとしても
他の3条件が落ちる**ので判定は不合格で確定する。最終行は「他が通っていれば追加採点で
決まる」種類の未確定で、これも結論を変えない。

**候補生成は律速ではない**（recall 99.7%）ので、issue が用意していた分岐
「candidate recall が低ければ次 issue を候補生成の多様化へ切り替える」は**該当しない**。

## 再判定に要るもの（issue の「追加4局」を具体化する）

方向自体（人手の局所順位に情報がある）は否定されていない —— concordance は W に
単調で、`bin/eval_features` の回帰と向きが一致する係数も出る。
再判定するなら、**先に3つ直す**。順番が逆だと同じ結果が出る。

1. **採点の被覆を、方策が到達しうる範囲まで広げる**（今回の主因）。
   候補 113.8 手のうち採点は 18.3 手（16.1%）で、現行 top-10 でも 76.7% しか
   採点されていない。順位を組み替える器を入れる以上、**その器が持ち上げる手が
   採点済みでなければ測れない**（残差ランカーの未採点選択は大きい2局で +0.35 前後）。
   既存の `append_unscored.py` ループ（候補ノブで suite → 2回以上選ばれた未収載手を
   `?` 追記 → 採点 → `sync_eval.py`）を、実験ごとでなく**学習ループの内側**へ
   入れる必要がある。概算コスト: 現行の被覆（上位15）を上位30へ広げるだけで
   1棋譜あたり +約9手/決定点 ×約100決定点 = **+900手の採点**
2. **独立棋譜を増やす**。採点の 94.4% が2局由来で、学習曲線の標準偏差は
   本数によらず ±0.16〜0.19。±0.05 の門をこの分散で判定できない。
   さらに macro 平均は1決定状態のクラスタと106状態のクラスタを同じ重みで扱うので、
   **小さい eval が増えるほど macro が実態から離れる**。追加は**既存2局の近傍でなく
   対人実戦から**、先後・序中終盤・被王手・反則後で層化して**4局以上、かつ全局
   レビュー**（1決定点だけの eval を増やしても macro を歪めるだけ）
3. **測定を複数エクスポートで平均する**。壁時計予算のせいで、同じコードでも
   macro concordance が ±0.03 揺れる（門と同じ桁）。1本の測定で符号を論じない

この3つが済むまで、人手採点は**目的関数（suite / SPSA）としてだけ使う**という
現状の役割を変えない。`bin/export_eval_rank_data` と `scripts/eval_rank/fit_residual.py`
は、採点が増えたときに同じ判定をやり直すための配管として残す（既定挙動は不変）。
