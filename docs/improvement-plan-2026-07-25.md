  凍結は次の有意な改善（項目2 or 3）に相乗りさせる。
  **下限ガード**: ペア比較で有意な劣化、または反則・思考時間・主要シナリオ

### 2. 自駒 en-prise 逃げの改善（小粒・先行課題）

**目的**: 教師bot自身の逃げ率 42% を引き上げる。直接の強さに加えて、
en_prise_flee 信念の上限（教師実測が天井）を将来の再学習で押し上げる
ブートストラップになる。

**仮説**: 2手読みは「1手読みの上位8×scale」しか展開しない。静的リスク項の
スコアでは逃げ手が上位8に入らず、実測期待損失（2手読み）の恩恵を受ける前に
足切りされている疑い。

**手順**:
1. まず計測（足切り仮説以外も同時に測る）: アリーナ記録から
   「既知の当たりが付いた自駒がある局面」で
   - 逃げ手の**静的rank**（2手読み候補入りした率）と**2手読み後rank**
   - 逃げ手 vs 選択手の**スコア差分内訳**（どの項で負けているか）
   - 逃げなかった場合の**次手被捕獲率・交換損**（真実盤面での実被害）
   を集計する。**情報漏洩ガード**: en-prise の判定は「bot視点の観測履歴
   だけから定義」（自分が駒を取ったマス等）と「真実盤面での実被害診断」を
   分けて記録する。前者だけが実装に入ってよい（observation.rs にない情報を
   使わない、の公平性担保）
2. 足切りが原因なら: 既知 en-prise 駒の逃げ手を2手読み候補へ**強制昇格**
   （上位8とは別枠で数手。思考予算内に収まるか p99 を確認）
3. 昇格後も評価で負けるなら: 差分内訳で負けている項を特定してから
   構造変更を検討（exposed 系スカラーは SPSA 済み領域なので再調整はしない）

**検証**: 教師逃げ率（export データ実測 41.7% → 目標 55%+）、
analyze の只取られ件数、scenario suite、200局ガントレット。

**中止基準**: (a) 強制昇格しても選択率が上がらない（＝2手読みの期待損失評価
自体が逃げを正当化しない）、または (b) 選択率は上がるが勝率・只取られ・
反則のいずれも改善しない場合、リスク評価の構造問題として記録し撤退。

**計測結果（2026-07-25、GCE・200局・5911局面・逃げ手19171件、bin/flee_probe）**:
- **足切り仮説は主因ではない**: 逃げ手の39.9%は2手読み候補に入っており、
  2手読み後も順位はほぼ不動（静的rank 42.2 → 最終rank 42.2）。負けているのは
  gain 本体（Δgain −15.1）で、p_legal・反則コスト・removal 項はほぼ中立
- **真実側の実被害がほぼ無い**: 逃げなかった場合に次手で実際に取られたのは
  2.7%、平均交換損 0.07。bot相手は当たりを追撃してこない（相手も自駒の位置を
  見えていない）ため、**逃げの期待値は実際に低く、2手読みの評価はbot相手には
  概ね正しい**
- 含意: 強制昇格（手順2）はアリーナ勝率には効かない見込み（中止基準(b)相当の
  事前確定）。逃げ率向上は「人間相手の挙動」としての価値であり、
  capture_bet_var_w=2.5 と同種の挙動優先判断が必要 → 実装可否はユーザー判断。
  強さの改善路線としては項目3（信念ネット）を先行させる。
  注: 過去メモの「教師逃げ率41.7%」は opp_move 学習データの文脈定義
  （手単位の逃げ質量）であり、本計測の決定点単位の逃げ率7.5%とは分母が異なる

### 2.5. 詰めろ（攻め・受け）の明示的評価【新規・2026-07-25】

**発端**: GUI 対局のレビューで、59手目に受けを1つも指さず攻め手 `N*8三` を選び、
60手目 `G*7八` で詰まされた（`scenarios/mate-net.kif`）。真の盤面で数えると
後手の一手詰めは `G*7八` の1つだけで、受けは詰めマスを埋める `R*7八`/`N*7八`、
玉逃げ4手、支えの 6六桂を取る2手、7八に利かせる2手と複数あった。
`R*7八` は静的評価でも常に2〜4位まで来ていたが、攻め手（9一の金取り、gain 1.4）に
0.45 差で負けていた。

**なぜ既存の機構が全部素通りしたか**（測定済み）:
- `depth2_delta` の被詰みペナルティ（`DEPTH2_MATE_PEN=30`）は**駒を取る応手だけ
  全列挙**で、詰めろの `G*7八` は駒を取らない「静かな応手」。約200手から
  2サンプルの近似にしか掛からない（発火確率 ≒1%）
- `drop_check_danger`（`hand_drop_w=0.0757`）は玉周りの空きマス・レイ長の**線形和**。
  「逃げ場がゼロになる」という組合せ条件を表現できず、`R*7八` が得る差は +0.27 止まり
- valueネットの教師（bot 自己対局）に詰めろ局面がほぼ無い

**ユーザーの提案**（採用）: 受けの価値はアリーナ勝率では測れない（相手の凍結版も
玉位置が見えず詰みを実行してこない ＝ `flee_probe` で確認した「bot相手は追撃して
こない」と同じ構図）。そこで**攻め側（詰めろ生成）を先に入れて相手が詰みを
実行できるようにし、受けの価値を測れる環境そのものを作る**。教師bot の挙動が
信念・評価の上限になるという項目2と同じブートストラップ。

**実装**（0 が既定 = 従来と同一挙動、独立にアブレーション可）:
- `src/mate.rs` — 持ち駒打ち限定の一手詰め検出。`Mate`（盤上の駒だけで詰み）と
  `IfSupported`（玉で打った駒を取る以外に受けがない = 支えが1枚あれば詰み）の
  2段階。攻め側は自分の支え駒を知っているので `Mate`、受け側は相手の支えが
  不可視なので `IfSupported` も 0.5 倍で数える
- `strategy.rs` — `mate_threat_w`（攻め）/ `mate_risk_w`（受け）。gain の内側
  （p_legal 割引を受ける）だが `expected` の外（終盤は厳密粒子が枯れて
  `legal==0` になるため）。判定プールは厳密粒子が全滅していれば taint へ落とす
- `bin/analyze` — **被詰めろオラクル**。相手番の局面で相手に一手詰めがあった
  回数を数える。相手の強さに依存しない受けの直接指標

**計測（2026-07-25）**:
- 打ち限定で被詰めろの 72% をカバー（対人83局 232件中166件）。コストは
  思考時間で誤差内（16局アリーナで平均 562ms → 526ms）
- 受け `mate_risk_w=3`: mate-net 58手目で **8/8 シードが `R*7八`/`N*7八` を選択**
  （従来 0/8）
- 攻め `mate_threat_w=4`: mate-net 57手目で `N*6六` が rank 122〜250 → 6〜16 位

**アリーナ実測（2026-07-25、200局 vs v11・match_seed=20260725・ペア比較）**:

| 条件 | 勝率 | 被詰めろ | /100手 | 実際に詰まされた | 反則/局 |
|---|---|---|---|---|---|
| 対照（両項0） | 52.5% ±6.9 | 112 / 48局 | **0.65** | 21 | 6.48 |
| `mate_risk_w=1` | 57.0% | 156 / 62局 | 0.88 | 19 | 6.41 |
| `mate_risk_w=1.5` | 46.5% | 137 / 58局 | 0.77 | 23 | 6.89 |
| `mate_risk_w=2` | 51.8% | 135 / 60局 | 0.76 | 16 | 6.88 |
| `mate_risk_w=3` | 49.0% | 136 / 56局 | 0.77 | 22 | 6.91 |
| `mate_threat_w=4` | 50.0% | 107 / 56局 | 0.64 | 18 | 6.91 |
| 両方（3 / 4） | 48.0% | 112 / 54局 | 0.69 | 25 | 6.63 |

**結論: 受け・攻めとも全指標で中立〜わずかに悪化。採用しない**（既定 0 のまま）。

読み方:
- 勝率は全条件で誤差内。しかも w に対して**単調でない**（46.5〜57.0% と、幅が
  信頼区間とほぼ同じ）= ノイズ
- 受けの一次指標として用意した**被詰めろも、全ての w で対照より多い**
  （0.65 → 0.76〜0.88 /100手）。狙いと逆方向で、かつ最弱の w=1 が最悪。
  「w の大きさの問題ではなく、SPSA 調整済みの評価に何かを足すこと自体が
  局所最適から外している」形
- 当初疑った「ペナルティが gain を負に振り切って combine_score の割引形を
  変える」は否定済み（発火ゼロの局面でも gain<0 が 100/111 と元々多数派）
- 一方 mate-net シナリオでは 0/8 → 8/8 と明確に効く。**その局面では正しい手を
  選ぶが、自己対局全体では割に合わない** — flee_probe（項目2）と同じ構図で、
  bot 相手には詰みが実行されない（「実際に詰まされた」は 16〜23 で w に無関係）

**決定（ユーザー判断 2026-07-25）**: `mate_risk_w` / `mate_threat_w` は 0 のまま据え置き、
`src/mate.rs`・`scenarios/mate-net.kif`・analyze の被詰めろオラクルは
**回帰テストと診断基盤として残す**。順序を元のブートストラップ計画へ戻し、
**攻め側が詰みを実行してくる環境を先に作ってから受けを再測定する**。
再挑戦時は `TSUITATE_MATE_RISK_W` / `TSUITATE_MATE_THREAT_W` で即座に試せる。

### 3. NN段階②: 信念ネット（本命・中期）

**目的**: 粒子の信念の質を構造側から改善する。対象は
(a) 王手駒ビリーフ較正（kakutori 根本原因の残り半分）、
(b) 占有マスビリーフ → 最多反則カテゴリ「打ちマス」の削減、
(c) 反則経済31ptギャップへの初の構造的アプローチ。

**設計方針**（particle-likelihood-nn の教訓を反映）:
- **評価側の再重み付けチャネルは使わない**（オフライン較正が大幅改善しても
  アリーナ中立＝チャネル飽和を実測済み。ブランチ nn-particle-likelihood 参照）
- 統合先は**提案分布側**。ただし Estimator::Guide への薄い prior 注入だけだと
  過去の occupies/path_blocks（粒子が十分ある局面では分布をほぼ動かせない）を
  踏襲するリスクがあるため、**リプレイ / 若返り / ソフト救済 / 枯渇時再生成の
  4チャネルを別々にアブレーション**し、どの生成局面で分布が実際に変わるかを
  先に固定する
- **ネット出力は raw board sampler にしない**: マスごとの独立占有確率から
  直接サンプルすると駒数・駒種多重集合・二歩・行き所・テンポ制約・駒間相関が
  壊れる（C-8 の設計論点と同根）。出力は**既存の合法配置・手順生成の
  候補順位・局所選択確率を動かす prior** として使う。盤面直接合成をやるなら
  C-8 の state-space synthesis として別フェーズに切り出す
- 入出力: 観測履歴（反則列・捕獲イベント・王手宣言・手数）→ マスごとの
  占有確率＋駒種分布。opp_move_nn と同様に手書き forward pass で載る規模に抑える
- 王手中の再重み付けは有害・玉位置質量を潰すな（ansatsu 回帰）の2教訓を
  設計段階でゲート化
- 学習データはアリーナ記録（真実つき）。**定石更新時はデータ再生成**、
  4シードで頑健性確認（opp_move / value NN と同じ手順）

**注意**: p_legal への直接供給は、反則マス記憶系4種（prior_legal / 最終
p_legal 直接制約を含む）が全滅したチャネル。統合チャネルを変える場合の
次候補は p_legal 側ではなく **C-8 系の state-space synthesis / hybrid 合成粒子**
（過去ログとの整合。docs/c8-direct-synthesis.md）。

**検証**（段階ゲート制。前段で失敗したら実装チャネルを変える）:
1. オフライン較正: 占有予測 vs 現行粒子集計、真の王手駒信念 2.7% → 2桁%
2. **live粒子質量**: 真実マス・真の王手駒への質量が実際の live 粒子群で
   増えたか（オフライン勝利で終わった particle-likelihood-nn の再発防止。
   これが動かなければ次段に進まない）
3. **決定点内の指標**: 評価対象候補の p_hit / p_legal の順位変化、
   打ちマス反則候補が上位Nから落ちた率、王手中の正解回避手が top1/top3 に
   入る率
4. scenario diag（kakutori / ansatsu）+ scenario suite
5. 100局 smoke → 200局フルガントレット（全凍結版）。挙動指標は analyze の
   打ちマス反則件数と nofoul ギャップ再測定（構造改善が反則経済に効いたかの
   直接指標）

**中止基準**: ゲート1〜2で改善が出ない、または最終ゲートでアリーナ中立が
続く場合は統合チャネルを C-8 系へ1回だけ変えて再挑戦、それでも中立なら
段階②を保留して記録（particle-likelihood-nn と同じ扱い）。

### 4. checker_removal_w の w スイープ（任意・低優先）

checker_removal_w=1.0 は未調整の新パラメータ。ただし SPSA 第3〜5ラウンドが
連続不発なこと、capture_bet_var_w は方向が既知（アリーナ最適は 2.0 側）で
ユーザーが挙動優先の 2.5 を選択済みなことから、**SPSA 第6ラウンドは組まない**。
value_nn_w と同じ**単純 w スイープ**（0.5 / 1.0 / 2.0 を各100局 vs v10 +
kakutori 19/20 の維持確認）を GCE が空いているときに回す程度でよい。

### 5. 人間対局レビューの継続（機会的）

scenario-gui の対局モードで実戦レビューの敷居が下がった。目的は
「先回りの逃げ」「無目的手の横並び」の**実例収集**。収集した局面は
学習データに回す前に、まず**固定回帰テスト**（シナリオ化して scenarios/ へ
常設）にする — value net の「seed 偶然合格」パターンを避けるため、
オフライン検証セットとしての価値が先。
過去実績: knight_bait_w・home_lance_move・kakudo 角道誤信・dragon-check-drop。

## 進め方

1 → 2 → 3 の順。1 は CI を回すだけなので即着手。2 は計測（手順1）までやって
仮説の真偽を見てから実装判断。3 は 2 の結果（教師の逃げ挙動改善）を学習データに
反映できるとなお良いので、2 の決着後にデータ生成から入る。
