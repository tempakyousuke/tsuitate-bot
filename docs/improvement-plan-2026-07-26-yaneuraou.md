# やねうら王の知見に基づく改善計画（2026-07-26）

元資料: `docs/yaneuraou-lessons.md`（調査 2026-07-26）。
本書はその第5章「段取りの提案」を、**V4 実施後の実測**と現状コードの確認結果で
更新した実行計画。各項目に目的・手順・成功条件・中止基準を付す。

## 現在地

- v11 凍結済み（2026-07-25）。main には `king_hole_w`（V4）が**既定0**で載っている
- 元資料の第5章は「評価関数（V1〜V4）が先、探索・資源（A〜H）が後」の順序だったが、
  **その前提が V4 の実測で崩れた**ので順序を入れ替える（次節）

### 順序を入れ替える理由: 評価項の積み増しは3連敗している

| 施策 | オフライン／機構の指標 | アリーナ勝率 |
|---|---|---|
| 詰めろ2項（mate_risk / mate_threat） | mate-net 0/8 → 8/8 | 全 w で中立〜悪化、非単調 |
| en-prise 逃げの強制昇格 | 逃げ手の39.9%は既に2手読み候補入り | 事前に無効と判定（実被害2.7%） |
| V4 `king_hole_w` | 被詰めろ 363→300（打ち詰み −33%、**w に単調**） | 非単調に散り、有意差なし |

共通する敗因が2つある。

1. **相手botは情報を持たないので、守りの改善が実害の減少に変換されない**。
   被詰めろも en-prise も「相手が知っていれば刺さる」形で、アリーナでは実行されない。
   → **アリーナで採否を決める項の合格条件は勝率のみ**（V4 の結論）
2. **SPSA 収束点への加算は局所最適から外す**。詰めろ2項では最弱の w=1 が最悪という
   「w の大小でなく、足すこと自体が悪い」形が出た

やねうら王の V1〜V3 も **1 の影響を受ける側**（利き・紐は本質的に守り寄り）で、
かつ **2 の対策（新パラメータの SPSA 再調整）を必ずセットにしないと同じ轍を踏む**。

一方 **A/B/C/E（資源配分と高速化）は 1 の影響を受けない**。
「同じ持ち時間から取り出せる棋力」の話なので、相手が何を知っているかに依存しない。
しかも E は V1〜V2 の前提でもある。**したがって資源側を先にやる。**

### 現状コードで確認した事実（計画の前提）

| 事実 | 位置 |
|---|---|
| 思考予算は環境変数だけで決まる固定値（既定2000ms）。`clocks` は未使用 | `strategy.rs:272`, `:1221` |
| **凍結版も同じ環境変数を読む**（`estimator_v7.rs:2166` 他）。`-f env=` での予算スイープは**両側に効いてしまう** | `frozen/estimator_v*.rs` |
| 実測の平均思考時間は 526〜562ms（予算2000msに対し約1/4） | improvement-plan-2026-07-25 の詰めろ計測 |
| 本番300秒+3秒・`MAX_PLIES=200`（自分の手番は最大100回）なら、1手あたり使える時間は概算 **(300000+3000×100)/100 = 6000ms** | `selfplay.rs:29,33-34` |
| 2手読みは固定の上位8足切り | `strategy.rs:1580` |
| `is_attacked` は最初の1枚で `return true`（利き数がない） | `shogi.rs:308` |
| `coverage_w` は SPSA が 0.0013 まで潰した（全マス平等な被覆マス数） | `strategy.rs:351`, `:730` |
| 紐の割引は `is_attacked` の二値で一律係数 | `strategy.rs:2891`, `:2909` |

**この表の3〜4行目が最大の発見**: 本番でも使える時間の**1割弱しか使っていない**可能性が高い。
やねうら王の TimeManagement（項目A）を「残り時間に応じて配る」機構として作り込む前に、
**そもそも予算を増やせば強くなるのか**を測るべき。ここが計画全体のゲートになる。

## 順序

```
0. 発火率フック（計測基盤）        ← 完了（2026-07-26）
1. 予算-強さ曲線の測定【ゲート】   ← 完了・不合格（2000msで飽和）
2. A+B+C（時間配分・打ち切り・widening）  ← 取り下げ
3. E（利きの差分計算）             ← 実測 3〜8% で着手しない。派生実験も不採用
4. V1 → V3（+ SPSA マスク再調整）  ← ここが次
5. V2（距離重み）                  ← E 不要と判明したので 4 の直後に繰り上げ可
6. F（NN入力に利き数）
7. 後回し: D / G / H / V5 / V6 / V7
```

**実行の副産物（計画外だが優先度が高い）**: 本番の思考予算を 900ms → 2000ms へ
引き上げる（項目1の実測で 900ms は 2000ms より −14.5pt）。300秒+3秒 条件での
安全確認（時間切れゼロ・残り最小・p99）を通してから CLAUDE.md の運用を更新する。

**2026-07-26 時点の総括**: やねうら王由来の「計算資源」側（A/B/C/E）は
**全部落ちた**。予算を増やしても強くならず（飽和）、利き走査は速い（3〜8%）。
残るのは評価の表現力（V1〜V3）と、その外側にある信念の質。
逆に言えば、**この計画で最初に測るべきだったのは資源側で、それが安く否定できた**
のは収穫（3件の実装をせずに済んだ）。

## 0. 発火率フック（`dbg_hit_on` 相当）

**目的**: 「中立だった変更が、効いていないのか・そもそも発火していないのか」を切り分ける。
詰めろ2項・king_hole_w の据え置き判断はいずれもこの区別が付かないまま終わっている。

**手順**:
- `strategy.rs` に軽量カウンタ（項名 → 発火回数・平均寄与・スコア順位を変えた回数）を置き、
  `TSUITATE_DBG_HITS=1` のときだけ集計してプロセス終了時に stderr へ出す
- アリーナのシャードジョブでこれを拾い、ジョブサマリーに載せる（`bin/analyze` と同じ扱い）
- 最低限ほしい粒度: 「発火局面率」「発火時の平均寄与（歩換算）」「その項が top1 を
  入れ替えた率」。**3つ目が本命**（寄与があっても順位を変えなければ勝率に効きようがない）

**成功条件**: 既定0の `king_hole_w`/`mate_*_w` を w>0 で回したとき、
上の3指標が既知の実測（被詰めろの単調減少）と整合する数字を出すこと。

**中止基準**: なし（小さく、以降すべての判定に効く）。ただし**ホットパスに条件分岐を
足すので、無効時のコストがゼロになる形**（`cfg` かアトミックの一括ガード）にする。

## 1. 予算-強さ曲線の測定【ゲート】

**目的**: 「思考予算を増やすと勝率がどれだけ上がるか」を実測し、
項目2（A/B/C）の上限を先に見る。曲線が寝ていれば資源配分の作り込みは無価値。

**前提作業（必須）**:
- **候補側だけの予算ノブを作る**。`TSUITATE_THINK_BUDGET_MS` は凍結版も読むため、
  今のままでは両側の予算が動いて比較にならない。現行 `strategy.rs` だけが知る
  名前（例 `TSUITATE_CAND_THINK_BUDGET_MS`、未設定なら従来どおり）を追加する。
  凍結版は名前を知らないので自動的に既定2000msに留まる
- `selfplay.rs:33-34` の `FISCHER_INITIAL_MS`/`FISCHER_INCREMENT_MS` を env で
  上書き可能にする（本番相当 300秒+3秒 でアリーナを回すため。arena.yml にも入力を足す）

**手順**:
1. アリーナ条件（1000秒+3秒）で候補予算を 900 / 2000（対照）/ 4000 / 8000 と振り、
   各100局 vs v11（`match_seed` 固定のペア比較）。**対照ランを必ず同時に回す**
   （候補単独の数字は解釈できない — メモリ arena-main-control-baseline）
2. 本番条件（300秒+3秒）でも 2000 / 4000 / 6000 を回し、**時間切れ負けが出る境界**と
   思考時間 p99／平均を記録する
3. 併せて、実際の消費時間の分布を出す（1手あたり消費 ÷ その時点で使える時間）。
   「クロックの何%を使っているか」が A の伸びしろそのもの

**成功条件（＝項目2へ進む条件）**: 予算4000〜8000で v11 に対し**単調かつ有意な**
勝率上昇があること（100局で誤差±10ptなので、20pt級の差でなければ200局へ）。

**中止基準**: 曲線が2000msで飽和している場合、A/B/C の上限は「浮いた時間の使い道が無い」
ことになるので**項目2を丸ごと取り下げ**、項目3（E）→4（V1/V3）へ進む。
この場合でも副産物として「本番の `TSUITATE_THINK_BUDGET_MS` を安全に上げられる上限」が
確定するので、デプロイ設定は更新する。

### 実測（2026-07-26、各100局 vs v11・match_seed=20260726・1000秒+3秒）→ **不合格**

| 候補予算 | 勝率 | think 平均/p99 | クロック消費 | 残り最小 |
|---|---|---|---|---|
| 900ms | **40.8% ± 9.5** | 535ms / 1404ms | 2.4% | 1000秒 |
| 2000ms（対照・既定） | 55.3% ± 9.6 | 1188ms / 3115ms | 5.2% | 1000秒 |
| 8000ms | 55.8% ± 9.5 | 4228ms / 12025ms | 18.5% | 770秒 |

**2000ms で飽和している**。予算4倍で +0.5pt（誤差内）なので、成功条件
「4000〜8000で単調かつ有意な上昇」を満たさない。→ **項目2（A+B+C）は取り下げ**。
「勝負どころに時間を配る」以前に、**配った時間が強さに変わらない**。
時間を増やして伸びるのは粒子数・読み幅だが、その先で効く評価の側が飽和している
（＝ ボトルネックは計算資源ではなく評価と信念の質）という読み。

**副産物（こちらが本命の収穫）**: 900ms は 2000ms より **−14.5pt**。
CLAUDE.md の運用「本番（300秒+3秒）へは `TSUITATE_THINK_BUDGET_MS` を 900 前後に
絞ってデプロイする」は、**約14pt を捨てている**ことになる。しかも 2000ms でも
クロック消費は 5.2%（1000+3 条件）で、本番条件に引き直しても十分な余裕がある。
→ 300秒+3秒 条件での安全確認（100局、両者とも既定2000ms）:

| 指標 | 実測 |
|---|---|
| 勝率 | 51.9% ± 9.6（同条件同士なので50%付近が正しい） |
| **時間切れ** | **0** |
| クロック消費 | 13.9% |
| 残り最小 | **300秒**（＝初期値を一度も下回らない。加算3秒 > 平均消費1.2秒） |
| think 平均 / p99 | 1195ms / 3116ms |

**本番の思考予算は既定 2000ms のままでよい**（絞る必要がなかった）。
CLAUDE.md の運用記述を更新済み。

## 2. A+B+C を1セット（時間配分・早期打ち切り・widening）— **取り下げ（2026-07-26）**

項目1のゲートが不合格（2000msで飽和）だったため着手しない。
以下は将来ゲートの前提が変わったとき（例: 評価側が改善して予算-強さ曲線に
再び傾きが出たとき）のために残す。

**A: 残り時間からの予算配分**
- `SearchBudget::from_ms()` の入力を `view.clocks`（`protocol.rs:96`）から計算する
- ついたて固有の差: **反則しても手番が変わらない**ので、1手番あたり `choose()` が
  複数回走る。`MTG`（残り決定回数の見積り）は「残り手数 × (1 + 平均反則率)」で出す。
  平均反則は analyze 実測で 6.5/局程度なので係数は記録から取る
- 素朴な式で始める: `optimum = 残り時間/MTG + increment`、
  `maximum = min(optimum×3, 残り×0.3)`。序盤の削り（やねうら王の手数係数）は
  **別ノブにして単独でアブレーション**する（ついたては序盤の情報量がさらに少ないので
  削ってよい、という仮説の検証）

**B: 早期打ち切りと延長**
- MCTS 側の考え方を移す: 「訪問数」→ 候補に使った粒子数、「勝率差」→ `score` 差、
  `rest_maximum_po` → 残り予算で追加評価できる粒子数
- stage1 で差が開いていれば stage2 を上位2〜3手で打ち切って**時間を次の手へ繰り越す**。
  接戦なら上位群にだけ粒子を追加する
- **罠**: 候補間スコアは `p_legal` 割引後の合成値。差が小さい＝どちらでも良い、では
  ない（反則確率が拮抗しているだけ）。打ち切り判定は `gain` と `p_legal` を分けて見る

**C: progressive widening**
- `depth2_top_k`（`strategy.rs:1580` の固定8）を時間で決める。
  上位から stage2 へ流し、予算切れか「残り候補の stage1 上限 < 現1位の stage2 スコア」で停止
- **罠**: 「8を16にする」だけなら既に予算スケールでできる。比較対象は
  「同じ壁時計で top_k 固定 vs 適応」であって「8 vs 16」ではない

**成功条件**: **本番相当（300秒+3秒）**で v11 に 200局・`match_seed` ペアで有意勝ち越し。
かつ 1000秒+3秒条件で有意な劣化がないこと。時間切れ負けゼロ、思考時間 p99 が
クロック配分の上限内、引き分け率の悪化なし。

**中止基準**: A 単独で中立、かつ B/C を足しても中立の場合は撤退して記録。
「時間を使い切って引き分けが増える」変質が出た時点で即中止（analyze の終局理由で監視）。

## 3. E: 利きの差分計算（独立・並行可）

**目的**: 評価粒子数の上限を上げる。`NN_SAMPLES=48`/`PRESSURE_SAMPLES=16` の
コメントが「ボトルネックは NN の forward pass ではなく**利き走査**」と明記している
（`strategy.rs:317-320`）ので、ここが効けば全評価項の分散が下がる。

**着手前に必須**: **利き走査の実コストを測る**。「測らずにやらない」。
全体の3割未満しか占めていなければ着手しない。

### 実測（2026-07-26、`bin/effect_cost --features effect-profile`）→ **着手しない**

実対局モード（アリーナと同じ経路。推定器は毎手の差分更新）で 900ms 予算・2局:

| 部品 | 呼び出し回数/決定 | 1回 | 思考時間シェア |
|---|---|---|---|
| `Position::is_attacked` | 120万〜230万 | 15〜16ns | **3〜8%** |
| `Position::legal_moves` | 1.1万〜2万 | 2.1µs | 4% |
| `opp_move_nn_forward` | 30万〜61万 | 60ns | 3% |
| `value_nn_forward` | 400 | 570ns | 0.0% |
| `board::move_targets` | 1100〜1300 | 0.5µs | 0.1% |

**利き走査は 3〜8%**（マイクロベンチがキャッシュに有利な条件なので実際は
数倍かもしれないが、それでも3割には遠い）。基準どおり **E は着手しない**。
差分更新はバグると静かに壊れる投資なので、この見送りは素直に得。

**同時に分かった、より重要なこと2つ**:

1. `strategy.rs:317-320` の「**ボトルネックは NN の forward pass ではなく
   利き走査**なので粒子数を絞る」というコメントは、少なくとも現在は
   **成り立っていない**（利き走査 3〜8% / value_nn 0.0%）。
   `NN_SAMPLES=48` / `PRESSURE_SAMPLES=16` の根拠が実測で崩れているので、
   **これらの上限を上げる余地がある**（V2 の「全マス走査は高い」という
   前提も同様に見直しが要る = V2 は E を待たずに着手してよい）
2. `value_nn_forward` が **406回/決定**しかない。設計上は
   「候補 × min(粒子数, nn_samples=48)」で数千回になるはずで、2桁小さい。
   発火率フック（項目0）でも value_nn の発火は 47.5% の決定でしかなかった。
   **valueネットは想定よりずっと薄くしか効いていない**疑いが濃い
   （`expected` の内側にあるため厳密粒子が枯れると丸ごと無効になるのが一因）。
   これは「無目的な安全手の横並び」が直らない理由の候補でもある

上の 1・2 は**測って初めて見えた**もので、E 本体より価値が高い。

### 3-b. 派生実験: 厳密粒子ゼロの決定を taint 粒子で評価する → **不採用**

発火率フックの実測（CI 2033決定/シャード）で、決定の内訳が分かった:

| 条件 | 割合 |
|---|---|
| 厳密粒子ゼロ（`expected` が丸ごと無効） | **26.5%** |
| うち taint 粒子もゼロ（粒子に依らない項だけで指している） | 10.7% |
| 王手中 | 15.6% |
| value_nn の前提充足 | 65.4% |

厳密粒子が全滅すると `expected`（駒得期待値・情報利得・攻め圧力・valueネット）が
ゼロになり、着手は前進バイアス・展開・被覆・と金プローブと事前確率だけで決まる。
`mate_pool`・`blind_king_attack`・CheckSolver 投票が既に持っている
「厳密が全滅していれば taint」の規約を評価本体へ広げてみた
（`TSUITATE_EVAL_TAINT_FALLBACK=1`、p_legal には混ぜない）。

**結果（200局 vs v11・match_seed=20260726 のペア比較）**:

| 条件 | 勝率 | 反則/局(A) |
|---|---|---|
| 対照（main） | 56.5% ± 6.9 | 6.41 |
| taint フォールバック | **50.5% ± 6.9** | 6.73 |

改善なし（むしろ −6pt、反則もわずかに悪化）。**採用しない**（既定オフのまま
ノブとして残す）。読み: taint 粒子は敵の盤上駒が嘘なので、駒得期待値・攻め圧力の
ような「相手の駒の位置に依存する量」を計算させると、質の悪い信号を
評価本体へ流し込むことになる。玉位置だけを使う `blind_king_attack` や、
自駒と持ち駒だけで決まる詰み判定（`mate_pool`）が taint で成立するのとは
量の性質が違う、という切り分けになった。

**残る事実**: 決定の26.5%で評価本体が薄いこと自体は変わっていない。
埋めるなら「嘘の粒子で評価する」ではなく「粒子を枯らさない」側
（信念ネット = improvement-plan-2026-07-25 の項目3）が筋。

**手順**:
1. `shogi.rs::Position` に利き数ボード（先後×81マスの u8）を持たせ、着手適用時に差分更新
2. `is_attacked` は差分ボードを引くだけにする（O(1)）
3. **全計算と差分計算が一致するプロパティテスト**を必ず付ける（perft と同じ規律。
   `IncrementalEstimator` が既にこの型のテストを持っているので同じ設計で）

**成功条件**: `pressure_samples`/`nn_samples`/`mate_samples` を据え置いたまま
1手あたりの壁時計が有意に下がること。そのうえでサンプル数を上げた版が
v11 に対して中立以上（**高速化単体で勝率が上がるとは限らない**ので、
合格条件は「同じ壁時計でより多くの粒子」までとする）。

**中止基準**: 差分更新のバグが2回以上テストで露見する規模になったら、
`is_attacked` の早期 return を保ったまま**利き数だけキャッシュ**する縮小版に落とす。

## 3-c. 只取られの主因は「取り返しの評価が消えること」だった（2026-07-26）

**発端**: ユーザー指摘「取られた駒を取り返す評価値が低すぎて只取られが多いのでは」。

`bin/analyze`（main・50局）: **取り返し機会713回中 実行235回（33%）**、
得だったのに逃した63回、只取られ296回。

`bin/recapture_probe`（新規・20局280機会。観測だけで取り返し機会を定義し、
真実は診断にのみ使う）:

| 指標 | 実測 |
|---|---|
| 候補に取り返し手あり | 49.6%（残り半分はそもそも届く自駒が無い） |
| うち実行 | 56.1% |
| 負けている内訳（得なのに逃した39件） | score −1.97 = gain −0.84 / adjust −0.65 / p_legal −0.08 |
| **取り返し手の期待駒得** | **1.189**（真実の敵駒価値は平均 5.41） |
| 取り返し手の取られリスク | 1.053 |

**評価が低いのではなく、駒得が丸ごと消えていた**。厳密粒子が全滅した決定
（26%）では `expected` がゼロになり、そこに含まれる駒得期待値ごと落ちる。
実例（`scenarios/recap-dragon.kif` = 相手の龍が銀を取った直後）をシード6本で:

| seed | 龍を取り返す 6a7a の順位 | gain | 厳密粒子 |
|---|---|---|---|
| 0,1,4,5 | 1位 | 11〜13 | あり |
| 2,3 | **89〜93位** | **0.045** | **ゼロ** |

**対応**: `blind_king_attack` と同じ思想で、嘘の盤面（taint）は使わず
**観測だけから確実に言えること**を使う。直前の相手手が自駒を取ったマスには
相手の駒が確実にいる（観測そのもの）。駒種は不明だが**相手の盤上に残る駒の
多重集合は観測から一意に決まる**ので、その平均交換価値で見積もる。
厳密粒子ゼロの決定でだけ gain に
`期待交換価値 − mover_w_captured × 自駒価値 × capture_reveal_risk` を加える
（`BLIND_RECAPTURE_W`、既定1.0）。実測で同局面 4/6 → **6/6**。

3-b の taint フォールバックが失敗したのと同じ穴を、**別の情報源で**埋めた形
（taint は物理制約を緩めた盤面なのでそのマスに駒がいる保証すら無いが、
観測由来のこの経路にはその弱点がない）。

### 実測（2026-07-26）: 機構は大きく効くが、勝率は動かない

同一シャード（同じ match_seed の50局）で対照と比較:

| 指標 | 対照（main） | ブラインド取り返し |
|---|---|---|
| 取り返し機会 | 713 | 681 |
| 実行 | 235（33%） | 253（37%） |
| **得だったのに逃した** | **63** | **24（−62%）** |
| 只取られ | 296 | 253 |
| **駒得収支** | 取った3178 / 取られた3450 = **−272** | 3378 / 3309 = **+69** |

200局全体では 只取られ 1050 → 1003、反則 6.41→6.48（横ばい）、
思考時間 横ばい、シナリオ回帰なし（recap-dragon 17/20 で常設）。
**勝率は 56.5%±6.9 → 51.5%±6.9 で改善なし**（差は誤差内）。

**なぜ駒得が勝率にならないのか**: このアリーナの終局理由は
**詰み 43 / 反則負け 157**（＝約78%が反則負け）。50局で歩換算340点ぶんの
駒得改善が出ても、勝敗はほぼ反則経済で決まっているので勝率に現れない。
被詰めろ（king_hole_w）・逃げ（en-prise）・詰めろ2項がすべて中立だったのも
同じ構造で、**「評価の質」より「反則の少なさ」が勝敗を支配している**。
これは nofoul オラクルの31ptギャップ（docs/c8-direct-synthesis.md）と同じ話を
別角度から見たもので、**評価側の改善はアリーナ勝率では原理的に測りにくい**。

含意: 今後の評価項は「アリーナ勝率で有意勝ち越し」を唯一の合格条件にすると
**永久に何も通らない**。対人価値のある挙動改善（本件・capture_bet_var_w と同種）は
機構指標＋シナリオ回帰で採否を決め、**勝率は「有意に悪化していないこと」の
下限ガードとして使う**のが現実的（ユーザー判断）。

## 4. V1（利き数）→ V3（予防的な紐）

E の後（または E と同時）。**この2つは必ず SPSA 再調整とセットで測る**。

**V1: `attack_count(sq, by) -> u8`**
- `recapture_risk`/`exposed_capture_risk` の紐割引を、一律係数（`recapture_defended=0.4692`）
  から**攻め枚数 vs 守り枚数**に変える。現状は「2枚で狙われ1枚で守る駒」と
  「1枚で狙われ1枚で守る駒」が同じ評価になっている
- `king_zone_pressure`（`strategy.rs:3018`、攻撃されているマス数のカウント）を
  利き数の逓減和へ。初期値はやねうら王の実測（1本=1.0, 2本=1.76, 3本=2.25）
- ついたて固有: **守り枚数は完全既知・攻め枚数は粒子加重**という非対称な扱いになる

**V3: 予防的な紐**
- 全自駒に「味方の利きがあれば加点」。**自駒同士の連結は完全既知**なので粒子不要・安い
- V4 と違い、**紐は相手の情報状態に依存しない**（相手が偶然踏み込んだときに実際に
  取り返せる＝真の駒得になる）ので、V4 で失敗した「守りがアリーナで実現しない」構図に
  当てはまらない可能性がある。ここが V1〜V3 に賭ける根拠
- 質（相手の利きによる減点）は粒子経由で精度が落ちるので**紐だけ先に入れて測る**

**手順**:
1. V1 を入れて既存項の分母を置き換える（新パラメータを増やさない形を先に）→ 200局
2. V3 を新パラメータ1つで足す → 発火率フック（項目0）で発火局面率と top1 入替率を確認
3. **`TUNE_PARAMS` マスクで新パラメータ＋隣接項（`recapture_defended`/`exposed_defended`/
   `pressure_w`/`attack_w`）だけを SPSA 再調整**（GCE、`TUNE_SPAN` で局所化）。
   詰めろ2項の「足すこと自体が局所最適から外す」への直接の対策
4. 再調整後の中心点で 200局フルガントレット

**成功条件**: 各段階で v11 に有意勝ち越し（`match_seed` ペア、対照ラン同時）。
analyze の只取られ・損な交換の件数が減っていること（V1 の直接指標）。

**中止基準**: 手順3（SPSA 再調整）まで通して中立なら、**評価項の積み増し路線は4連敗**として
打ち切り、V2 以降には進まず項目6（NN入力）へ振り替える。

## 5. V2: 利きの価値を玉からの距離で重み付け

E と V1 が両方通った後にのみ着手（全マス走査なので最も高い）。

- `coverage_after` を「マス数」から `Σ 利き数価値 × w[玉からの距離]` に置き換える
- 自玉からの距離は**ノイズゼロ**（自玉位置は完全既知）。相手玉側は粒子加重平均に
  なり、`blind_king_attack` の一般化にあたる
- **切り分け必須**: 「`coverage_w` をゼロにしただけの版」も並べる。
  距離重みが効いたのか、単にノイズが減っただけなのかを分ける
- 初期値はやねうら王の実測配列（`{1024,496,297,...}`、相手の利きの方が重い非対称）。
  ついたて側の `attack_w=0.0434`/`pressure_w=0.0918` が独立に同じ非対称性を
  見つけている点が信頼の材料

**成功条件**: 200局で有意勝ち越し、かつ思考時間 p99 の悪化が予算内。

## 6. F: NN 入力に利き数を足す

V1 の量をそのまま `value_features.rs` に足す（現在の20次元に利き数が1つも無く、
**手作り項と NN が同じ盲点を共有している**）。次元がほとんど増えないので過学習リスクは小さい。

手順は既存どおり: 記録用アリーナ → `export_value_data` + `export_pairwise_data` →

`export_value_weights.py` → クロスチェック期待値再生成 → **w スイープ** → ガントレット。
**定跡を更新していたらデータ再生成**。

注意（メモリ offline-validation-must-include-engine-choice）: オフライン2手比較の
合格で判断しない。実エンジンの選択で確認し、目標値を変えたら w を測り直す。

## 別線（この計画には含まれないが本命）

反則経済31ptギャップ（＝粒子の信念の質）に**やねうら王側の対応部品は無い**。
これは improvement-plan-2026-07-25 の項目3（NN段階②: 信念ネット）の領分で、
本計画とは独立に進む。**資源配分（項目1〜3）は信念ネットの評価コストにも効く**ので、
先に E を通しておくと段階②の粒子数の制約が緩む、という関係にはある。

## 共通の検証規律

- 判定は CI の 200局ガントレット・`match_seed` ペア比較・**対照ラン同時実行**
