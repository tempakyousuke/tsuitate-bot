# 改善計画 2026-08-22: ターン内の反則プローブ計画（probe planning）

Status: **計測完了・不採用（既定 0 のまま残置）**。機構は設計どおり動き、
反則も増やさず、コストもほぼゼロだが、**勝率は 2シード208局で中立**
（52.4% → 54.1%、CI ±6.8）。`TSUITATE_PROBE_PLAN_W=1` で再試行可。
計測の全記録は末尾。本文（設計）は着手時点のスナップショット。

## 診断: 限界は粒子ではなく「粒子の上に載っている意思決定の形」

現行の意思決定は候補手ごとに独立なスカラーを作る**単発 argmax**:

```
score(m) = min(p_legal·gain, gain) − (1 − p_legal)·foul_cost + foul_probe + adjust
```

これは不完全情報ゲームでいう PIMC（粒子ごとの完全情報評価を平均する）で、
教科書どおりの病理が2つ出る。とくに後者がこのゲームでは致命的:

- **strategy fusion**: 「世界ごとに正しく指せる」前提で平均するので、
  「分からないから確かめる」を表現できない
- **情報獲得の計画がない**: ついたて将棋は**反則しても手番が変わらない**。
  つまり1手番の正解は単一の手ではなく「A を試す → 反則なら B → 反則なら C」という
  **ターン内の適応的な決定木**。今のコードはそれをスカラー1個
  （`drop_probe_w` / `foul_probe`）で近似するしかない

この読みは3つの実測が支持している:

1. **nofoul オラクルのギャップ 31〜36pt**（vs v6 86.2% / vs v7 83.2% に対し実測
   51〜59%）。伸びしろは盤面評価ではなく**反則の経済**にある。104局中72局が
   詰みでなく `foul_limit` 決着 = 反則枠10がこのゲームの実質的な資源
2. **信念ネットは粒子に決定的に勝つのに勝率は動かない**（対数損失
   0.6227→0.3777、ブラインド AUC 0.685→0.821、供給チャネル2つとも中立）。
   信念の質はもうボトルネックではなく、信念を着手に変換する経路がボトルネック
3. **`bin/eval_features` の回帰**: 静的特徴の argmax 3.2点・線形 4.1点・
   エンジン 5.4点・上限 7.9点。手作り評価は静的特徴から取れるものをほぼ取り切っている

そして**反則経済に触った施策だけが勝率に変換されている**: `last_foul_guard`
+5.3pt、被王手の確かめの経済セット vs v14 +6.2pt、`drop_probe_w` の凸ゲート、
`check_capture_prune`。一方で盤面評価のスカラー項は40件以上が中立。

## 設計: 深さ2の AND/OR 再帰を明示的に解く

反則中は**真の局面は動かず、動くのは自分の信念だけ**。だから「信念 b・残り反則 k」
から手を選ぶ問題は深さ ≤ k の AND/OR 木で書ける:

```
V(b,k) = max_m [ p_legal(m)·V_accept(m) + (1 − p_legal(m))·V(b | m が非合法, k−1) ]
```

**必要な量はすべて計算済み**である点が要点。`evaluate()` は粒子ごとに
`pos.is_legal(mv)` で合法/非合法に分割しているので、`P(foul|m)` も
**反則後の事後信念（= 非合法だった粒子の部分集合）もタダで手に入る**。
追加の推論は要らない。

実装する量（深さ2で打ち切り):

```
V_after(m) = max_{m' ≠ m} score(m' | b に「m は非合法」を条件付けた事後)
V_base     = max_{m' ≠ m} score(m' | b)                  ← 何も学ばずに指す次善手
probe_plan(m) = w · (1 − p_legal(m)) · max(0, V_after(m) − V_base)
```

`combine_score` の**外側**（`foul_probe` と同じ層）へ加算する。意味は
「反則は純損ではない。反則した後の最善手が、何も学ばなかった場合より
`V_after − V_base` だけ良くなる。その利得は反則枝（確率 1−p）でだけ実現する」。

`foul_cost` は「反則1回を焼く平均的なコスト」の手調整スカラーで、
情報の対価は入っていない。この項がその欠けている半分にあたる。

### なぜ既存の手作り項の一般化になっているか

- `drop_probe_w`（打ちマスの占有確定 → 次手で回収）は、この式の
  **特殊ケースをハードコードしたもの**。買える情報を「占有の確定」に、
  回収を「捕獲価値」に固定している
- `foul_occ_attack_w`（この手番の打ち反則で確定した駒への当たり）は、
  事後で `p_legal` と駒得が変わることの**手作りの近似**。プローブ計画は
  「事後で全候補を評価し直す」ので同じものを**導出**する
- `foul_cost_pow` / `last_foul_guard{,_2,_3}` は残り枠に対する反則コストの
  急峻化。プローブ計画が効けば、これらは手調整でなく「残り k の再帰」から出る

### 実装上の要点（罠と対策）

1. **事後は再正規化する（証拠の減少ではない）**: 部分集合をそのまま
   `evaluate` へ渡すと `degen = 1 − n/eval_particles` が上がって `p_legal` が
   事前へ寄り、「条件付け」が「粒子が枯れた」と誤解される。部分集合の重みを
   **元の総質量へスケールし直す**（事後 = 質量の再正規化）。
   これで `p_legal` のブレンド較正は条件付け前後で一貫する
2. **ゼロ点不動**: 情報が動かない候補（`p_foul` が小さい / 全粒子が同意していて
   反則質量が 0 か 1 に張り付く / 部分集合が空）は**厳密に 0**。大半の候補が
   ゼロ点で動かない形にする（`threat_value` 差分化・`drop_hit_evac` の教訓）
3. **安全方向のみ（既定）**: `max(0, ·)`。負側（悪い知らせ）は `foul_cost` が
   既に払っているので二重計上になる。`TSUITATE_PROBE_PLAN_SIGNED=1` で
   両側にできる（アブレーション用）
4. **反則枠を使い切る方向へ暴走させない**: `drop_probe_repeat_gate` の失敗
   （反則/局 6.4→8.2・−12.8pt）と同じ穴。残り枠が薄いときは発火させない
   （`TSUITATE_PROBE_PLAN_MIN_LEFT`、既定4）。買えない情報に値段はつかない
5. **王手中は無効**: `p_legal` の出所が粒子でなく CheckSolver の仮説分布なので、
   条件付けも仮説側でやるべき（別工事）。反則の内訳も打ちマス270・経路封鎖164 >
   王手がらみ222 で、**非王手側が多数派**なのでプロトタイプはそちらを狙う
6. **taint 評価では無効**: taint 粒子は反則の説明を緩めて生かした粒子なので
   合法性の証拠に使えない（`p_legal` に混ぜない既存の規約と同じ）

### 近似（既知の割り切り）

- 深さ2で打ち切る（「反則2回目の後」は再帰しない）
- プローブ候補は静的スコア上位 K 本、継続候補は上位 M 本。事後で初めて
  浮上する手が M の外にあると拾えない
- `adjust`（タイブレーク・手戻り減点・ブラインド玉攻め等）は条件付け前の値を
  流用する。非王手・厳密粒子ありの決定では adjust は粒子にほぼ依存しない
- 段階1の後段パッチ（`home_gold_attack` の gain 加算）は継続候補では再現しない

## 計測計画

**この項の伸びしろは勝率より低分散な指標で測れる**のが利点。判定は
「勝率だけ」ではなく次の順で見る:

1. **オラクルギャップ**（`-f oracle=nofoul`）: 通常 vs nofoul の差が縮むか。
   これが設計の直接の目的関数
2. **反則/局と `foul_limit` 決着率**（`bin/analyze`・アリーナのサマリー）。
   **増えていたら即不採用**（`drop_probe_repeat_gate` の署名）
3. **思考時間**（平均/p99）。K×M 回の追加 `evaluate` のコスト。既定 K=6・M=12 で
   段階1の 20〜25% 増を見込む。時計は 300秒+3秒 で消費 13.9% なので余力はあるが、
   「遅くなったが勝率が上がった」を避けるため必ず見る
4. 全件 suite（同一コミットで対照とペア、20試行）
5. ガントレット v9〜v14

**この項は「アリーナ中立でも反則が減れば採用」ではない**: 反則の削減が
勝率へ変換されるのが `last_foul_guard` / 確かめの経済セットで実証済みの経路なので、
反則が減って勝率が動かないなら機構が意図どおり動いていない疑いを先に潰す。

### なぜ効かなかったか（次への申し送り）

いちばんありそうな説明は、**非王手側の反則経済は `drop_probe_w` と
`foul_occ_attack_w` が既に拾い切っている**こと。`merge=max` は
「手作りを下回らせない」設計なので、手作りが既に十分強気なら
計画値が上乗せされる決定はそもそも少ない。実際 quest31-m015 でも
導出値 4.696 < 手作り 5.29 で、`max` では計画値の出番がなかった。

**伸びしろが残っているのは王手中**（反則内訳: 王手がらみ222 に対し
打ちマス270・経路封鎖164 だが、`foul02` の理論値「反則3回」に対し
実測 4.1 で壁が残っている）。ただしそこは `p_legal` の出所が
CheckSolver の仮説分布なので、**粒子の分割ではなく仮説分布を
条件付ける別実装**が要る。
