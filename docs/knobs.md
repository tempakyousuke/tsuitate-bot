# 評価ノブ（`TSUITATE_*`）の一覧と採否記録

`strategy.rs` / `check.rs` / `estimator.rs` の評価・推定パラメータを外から差し替える
環境変数の全量と、**各ノブをどう計測してなぜ既定値をその値にしたか**の記録。
CLAUDE.md から切り出した（索引は CLAUDE.md の「評価ノブ」節）。

読み方:

- **既定値がそのまま現行挙動**。`0` / `off` のノブは実装だけ残した不採用・保留で、
  env から与えれば再試行できる（作業点はコード中の定数コメントか下の本文にある）。
- 設定の解釈は `config.rs` が構成境界で一度だけ行い、以後は `StrategyConfig` を見る。
  ノブを足したら `STRATEGY_ENV_KEYS` へ通すこと（通し忘れは `cargo test` が落とす）。
- **凍結版 v6〜v14 は凍結時点で読んでいた env を今も読む**（一覧は
  `frozen::env_keys_in_source(name)`）。`-f env=` はプロセス全体に効くので、
  候補側だけに効かせたいときは `-f cand_env=` / `ARENA_CAND_KNOBS` を使う。
  **v15 以降は実行時 env を読まない**（`frozen::HERMETIC_FROM`）。
- 採否の基準は「同一コミットのペアで scenario suite ＋ アリーナ・ガントレット」。
  手順は CLAUDE.md の「強さの検証」と `docs/arena-ops.md`。

## ノブ別の記録

- `TSUITATE_LINK_WORK_W` / `_REF` / `TSUITATE_REPEAT_PENALTY_W` — 2026-07-28 に
  採用した項の切り戻し・スイープ用（既定は 1.0 / 2.0 / 0.3。0 にすると従来挙動）
- `TSUITATE_CHECK_STRENGTH_W`（既定 0 = 無効）— **王手の強さ**（相手の合法解消手数 K）
  による値付け。g(K)=2.4/(1+K)−0.51 の中心化再配分で、強い王手（K≤2）を押し上げる。
  w=2 の実測（200局×3シード vs v12）: 強い王手 +14〜39%・詰み 148 vs 131 と機構は
  設計どおり動くが、**相手の反則総量は増えず勝率は中立**（51.5% vs 対照51.7%）—
  再配分だけでは反則総量が動かない（mate_threat/king_hole と同じ構図）ため既定0。
  SPSA対応（51個目）。王手の強さの理論と実測は `docs/analyze-metrics.md` の analyze の節と
  メモリ strong-check-few-resolutions 参照
- `TSUITATE_CHECK_KING_PRIOR_W`（既定 1.0、0 で従来挙動）— **玉での王手駒捕獲の
  過信補正**（2026-07-29 採用）: CheckSolver::legal_under は仮説の王手駒1枚しか
  置かないため、「玉でその仮説マスを取る手」を支え駒を無視して p=1.00 と断言し
  反則していた（実測: 単独仮説合法な玉捕獲の実際の合法率は 73%。p=1.00 断言の
  まま反則が400局で8件中6件が玉捕獲）。解消確率の玉捕獲寄与に実測事前確率
  0.73 を掛け、反則減衰も 1−0.73 へ緩和。**割引は玉捕獲だけに限定する**こと:
  玉の逃げ（実測75〜81%）まで一律に割り引いた第1版は較正は正しいのに
  3シードのペア比較で全て悪化した（選択が不確実な合駒・捕獲プローブへ
  押し出される。argmax シミュ 611→630 が事前に警告）。限定版はオフラインで
  p=1.00 反則 8→0・シミュ 611→601、アリーナ 53.5/53.0/48.5% vs 対照
  51.5/52.0/49.7%（中立、バグ修正として採用）。凍結版はこの名前を知らない
- `TSUITATE_CHECK_BELIEF_OCC_W`（既定 **0** = 無効、作業点 1.0）—
  **王手駒仮説の占有事前**（v15 候補、2026-08-19）。CheckSolver の仮説は
  自玉へ利きうる全（マス,駒種）なので、空きマスの幻仮説が生存すると正しい
  捕獲の `p_legal` が薄まる。pointwise 信念ネットは「今どの駒が王手して
  いるか」は表現できないが、**空きマスに王手駒は居ない**という必要条件は
  占有較正（対数損失 0.36 / AUC 0.89）で粒子より当たる。仮説重みへ
  `(1−w)+w·p_occ` を掛け、床 0.05 で仮説を殺さない（健全性）。
  **粒子が王手を投票できるときは掛けない**: 乗算を投票の前に置くと
  床 0.05 × 投票9倍 = 0.45 が占有1.0の幻仮説に負け、段階②の
  「王手中の再重み付けは有害」と同じ形になる（700ms×3試行で kakutori
  注目手 1/3→0/3 を確認してゲートした）。ブラインドのときだけ、
  捕獲マスブーストの後に掛ける。直前の捕獲マスは観測で占有確定なので
  乗らない。p_legal への直接供給（反則マス記憶系が全滅したチャネル）
  ではなく、制約推論の事前だけを動かす。凍結版はこの名前を知らないので
  `-f env=` は候補側にだけ効く。
  **既定 1.0 で PR #8 に入ったが、vs v14 で負け越しが見えたため 2026-08-19
  に既定 0 へ戻す**（ユーザー判断。機構は残す。env `=1` で再試行可）。
  同一 `match_seed=20260819`・104局のペア: 既定 1.0 のままの対照は
  **44.2%±9.5**（46勝58敗、run 32246124602）、既定 0 に戻した対照は
  **55.8%±9.5**（58勝46敗、run 32250461719）。時間切れ0・思考平均 1.21〜1.25s
- `TSUITATE_KING_REPEAT_FOUL_W`（既定 **0** = 無効、作業点 0.8）—
  **過去手番で玉が反則した行き先への再訪割引**（2026-08-19 実装、同日打ち切り）。
  一つの対局の中で同じ玉移動の反則を繰り返すのは、原因だった相手駒が
  動いた・無くなった・飛角の利きが遮られた、という観測が無いのに同じ
  マスへ玉を出すこと。同手番の同一 USI は `foul_tried` が既に除外する。
  ここは**手番をまたいだ行き先**だけを `p_legal *= (1−w)` で安全方向に
  落とす（gain 内の広い課税は `anchor_move` / `drop_probe_repeat_gate`
  で反則経済を壊した）。解除は観測できたときだけ: ①そのマスで駒を取った
  ②玉がそこへ受理された。相手の静かな移動や飛角の路線遮断は観測できない
  ので解除しない。王手中も有効（汚名マスの逃げだけ。玉逃げ全体を
  割り引いた `check_king_prior` 第1版とは違う）。kakutori の角捕獲や
  king-evade の同手番 5b/7b/6b 連発は発火しない。凍結版はこの名前を
  知らない。診断は `bin/analyze` の「玉移動反則の行き先再訪」と
  「王手中の汚名マス玉逃げ」（真に解消できるのに選ばず反則した回数）。
  **占有事前を既定 0 に戻したうえでの再計測**（2026-08-19、同一
  `match_seed=20260819`・全件 suite 20試行 + vs v14 104局）:
  - 対照（w=0）: suite **994 / 5.186**（未採点77、run 32250461707）・
    アリーナ **55.8%±9.5**（58勝46敗、反則/局 A 5.72 / B 6.11、詰み47、
    時間切れ0、run 32250461719）
  - 候補（w=0.8）: suite **1016 / 5.142**（未採点50、run 32250464906）・
    アリーナ **56.7%±9.5**（59勝45敗、反則/局 A 6.00 / B 6.08、詰み47、
    時間切れ0、run 32250464935）
  kakutori 11→10/20・king-evade 注目手 20/20 維持（反則 34→39）。
  analyze（同一 records・104局）: 行き先再訪 **4→0**（機構は発火）だが
  上限が4件、反則合計 595→624（5.72→6.00/局）、只取られ 477→505。
  **2026-08-19 ユーザー判断: 既定オンしない・実験打ち切り**。
  アリーナ差は +1勝（ノイズ）で v15 凍結相場（vs v14 +7〜11pt）に届かない。
  視聴棋譜（4八玉の3七反則のあと、原因の桂が3七を通過して2九成）では
  解除条件（そのマスで取る／玉が受理）を満たさず汚名が残る。C-8 の
  「反則マスを覚える系統」と同じ結論。再訪の本丸は粒子／玉隣接の利き
  信念で、再訪専用項は足さない。機構と env は残す（`=0.8` で再試行可）。
  初回計測 Arena #320/#321 は占有事前既定 1.0 が混入していたので使わない
- `TSUITATE_ESCAPE_COVER_W`（既定 0 = 無効）— **逃げマス被覆**の凸ボーナス
  （2026-07-29、対人局レビュー human-play-review-2026-07-29 の N*6四が発端）。
  粒子上の相手玉の隣接マスのうち未被覆の逃げ先が残り U 個のとき w×1/(1+U) を
  攻め圧力グループ（confidence ゲート・expected 内）へ加算。attack_w が被覆
  マス数に線形なのに対し「最後の逃げ道を塞ぐ手」ほど増分が跳ねる凸形で、
  check_strength_w（王手時点の再配分）が中立だった「強い王手が成立する形を
  作る」前段の中期項。王手中は無効。SPSA対応（52個目）
- `TSUITATE_DEFENDER_CAPTURE_W`（既定 0 = 無効）— **守り駒の捕獲**ボーナス
  （同レビューの 6一成銀「金取り＋守り駒削減」が発端）。粒子上の相手玉の
  8近傍にいる相手駒を取る手へ交換価値とは別のフラット加点。王手中は無効。
  SPSA対応（53個目）。どちらも凍結版はこの名前を知らない。
  **実測（2026-07-29、escape=2/defender=1 の同時オン）は不発で既定0のまま**:
  ペアアリーナ 51.0% vs 対照53.0%・詰み54→37と機構が逆向き、動機シナリオも
  defender-capture 0/20（対照1/20）・mate-net-attack N*6f 0/20 のまま、w=2 では
  信念上の玉への攻め打ちが増えて反則負け3/20が発生。守り駒の存在・玉位置とも
  粒子ビリーフが表現できておらず、攻め側中期項の律速は玉位置ビリーフ
  （メモリ v2-bottleneck-is-king-belief の再確認）
- `TSUITATE_DROP_HIT_EVAC_W`（既定 0 = 無効）— **打ち当て露出**（2026-07-30、
  対人局レビューの残候補「竜退避」= dragon-evac 20/20 への対応）。敵陣の
  自分の大駒（飛角竜馬）は相手が歩を持った瞬間「頭への見えない歩打ち→次手で
  捕獲」の的になり、打ちは観測されないので事前退避しか対策がない。自駒配置＋
  相手の確定持ち駒（GameModel::opponent_hand = 取られた自駒の上界）だけで
  決まる粒子不要・ノイズゼロの項。露出の差分 w×(現局面−着手後) を gain 内へ
  加点（大半の候補は0でゼロ点不動 = threat_value差分化の罠を回避。退避・頭の
  自駒封鎖が正、歩を持たれた状態での敵陣突入が負）。王手中・相手が歩を持たない
  ときは無効。SPSA対応（54個目）。凍結版はこの名前を知らない。
  **実測（2026-07-30）**: dragon-evac は w のしきい値 0.15〜0.2 で解決
  （w=0.2 で退避20/20 = 8g8b 14/8g8e 5/8g8h 1、w=0.5 で 8g8e 20/20、
  suite の他シナリオは回帰なし）。**アリーナはペア3シードで中立〜微負のため
  既定0**: w=0.2 合算 47.8% vs 対照 50.2%（46.7/51.0/46.5 vs 51.5/47.5/51.5、
  200局×3シード vs v13、match_seed=20260801〜03）、w=0.5 も 46.5% vs 51.5%
  （seed01のみ）。詰み131 vs 130・反則/局・平均手数は変質なし = **相手botは
  頭打ちをほぼ実行しないので退避はテンポ損しか生まない**。ただしこれは
  「対人でのみ有効」ではなく**相手側の機会損失**（ユーザー指摘 2026-07-30）:
  露出した大駒を取れる機会を現行bot自身も逃しており、攻め側（既知位置の
  敵大駒への支え付き頭歩打ち）を改善すればアリーナでも露出が実際に咎められる
  ようになり、この守り項は有効に転じ得る（共進化）。対人・本番では env から
  有効化して試せる。攻め側の改善が先（既定 4.0、1.0 で無効）— **王手宣言と同時に
  自駒が取られたマスの王手駒仮説ブースト**（2026-07-29、king-evade.kif が発端）。
  「そこへ来た駒がそのまま王手している」は開き王手より優勢な説明。同時に
  CheckSolver の仮説列挙から**既知の敵駒マスを除外するバグを修正**した
  （粒子の駒種近似が「王手しない駒種」を返すと真の王手駒マスが仮説集合から
  丸ごと消えていた。列挙は保存・復元方式で常に行う＝健全性優先、ノブなし）
- `TSUITATE_CHECK_CAPTURE_PRUNE`（**既定 on**、`0` で従来挙動 = 切り戻しノブ）—
  **捕獲＋王手の開き王手判定**（2026-08-19 採用、arena-check-flee02 が発端。
  ユーザー指摘「6七で取られたことは分かっているのだから同銀を調べるべき」）。
  直前の相手手が自駒を S で取って同時に王手宣言なら、王手駒は S の駒か
  開き王手の飛び駒のどちらか。CheckSolver はこれまで S の仮説を ×4 で
  強めるだけで S 以外を残していた（flee02 で非6七仮説が 18%、残り反則1回の
  foul_cost=60 では p_legal 0.82 の同銀 gain 14.7 が 0.989 の玉逃げ 1.26 と
  僅差で 2〜3/10 逃げ）。自駒配置だけで「玉–Q が直線・間に自駒なし・S が
  間にない・間のどこかから S へ動ける」を満たさない仮説を**除去**する
  （健全な演繹、粒子不要。全滅なら何もしない）。隠れた飛車によるピン
  （9八/8八飛の同銀反則）は仮説に載らないので p=1.00 はやや強気だが、
  「居座られるほうが辛い」のでユーザー判断で調べに行く方向。
  実測: flee02 の同銀 p_legal 0.82→**1.00**（score 1.2→13.9）、通常10試行で
  flee02 8→10/10・**flee03 1→10/10**・flee05 0→3・foul03 5→8（反則 61→55）、
  kakutori/king-evade/dragon-check-drop/recap-dragon 回帰なし。アリーナ
  run 32264804062（104局、match_seed=20260815）: vs v13 **54.8%±9.6**
  （同シード main 対照 50.0〜54.0）/ vs v14 **51.9%±9.6**（同シード v14 同一性
  確認 44〜47%）、反則/局 6.26〜6.45（相手 6.59）・時間切れ0。
  バグ修正＋シナリオ解決＋アリーナ中立〜微正の採用パターン
