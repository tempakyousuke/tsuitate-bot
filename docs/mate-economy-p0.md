# 詰み経済 P0: 受け側の計測基盤（issue #28）

2026-08-27。issue #28 の **P0-1 / P0-2 / P0-3 / P0-6 と P1-A**（推奨順序の
1・2・4・5の一部）の実装記録。runtime の挙動は**完全に不変**で、入ったのは
`mate.rs` の列挙関数・`mate_economy.rs` の診断・`bin/analyze` / `bin/mate_probe` /
`bin/mate_continue` だけ。**採否の判断（P0 の判定 → P1 へ進むか）は、CI の
`Mate economy` ワークフローを実際の arena 記録に対して回してから**出す
（ここに載せているローカル記録の数字は動作確認であって基準線ではない）。

## 背景（issue #28 より）

終局の主経路が反則負けから詰みへ移った。arena の `combined.json` で
2026-07-26 は詰み終局 21.5% だったのが、2026-08-24 の run 32697854659 では
vs v13 37.5% / **vs v14 51.0%**。詰まされた 28局（vs v14）の内訳は
**実行された詰め手が 打ち 9 / 盤上移動 19**、うち 16局はその局面に打ち詰みが
1つも無い。**現行の被詰めろ判定 `mate_risk_w` は `mate::drop_mate_threat`＝
打ち詰みしか見ない**ので、その 16/28 は評価の視野外にある。

## 入ったもの

### `mate::mate_moves_in_1_fast`（P1-A）

現行の `mate_in_1` は「全合法手を試して**最初の1手**だけ返す」診断専用だった。
P0 の排他的分類（`drop-only / board-only / both`）にも P1-C の「詰め手集合の
総方策質量」にも**全列挙**が要るので、次の3つを足した:

- `mate_moves_in_1(pos)` — 全合法手版の完全列挙（正解基準）。`mate_in_1` は
  この先頭を返すだけになった（返す手は従来と同じ）
- `mate_moves_in_1_fast(pos)` — **王手になりうる手だけ**に絞った列挙。絞り込みは
  3経路の構成的な和で、どれも必要条件を見落とさない側に倒してある:
  打ちは既存の `drop_check_candidates`（歩は打ち歩詰めが反則なので原理的に
  一手詰めにならず `legal_moves` 側でも落ちる）、盤上の直接王手は
  「着手後の駒種で `to` から玉へ利くか（移動元は空きとみなす）」、
  盤上の開き王手は「玉 → `from` が同一直線・間は空き・`from` の先に自分の
  走り駒がその向きへ利く」
- `has_mate_in_1_fast(pos)` — 1件見つけ次第打ち切る早期脱出版

**完全性はテストで担保する**（`mate_fast_agrees_with_full_search`）: 24シードの
乱数自己対局で 90手まで進めながら、毎局面で `mate_moves_in_1` との**集合一致**と
`has_mate_in_1_fast` の一致を検査する（2000局面超・詰めが実際に出ていることも
assert する）。実戦局面でも `mate_fast_agrees_on_real_game_position` で照合する。
`bin/analyze` も `TSUITATE_MATE_COST=1` のとき全決定点で両版を突き合わせる。

### 実測コスト（P1-A の前提）

初期局面の perft から出した movegen 単価は「詰み直前の終盤で相手の合法応手を
ほぼ全走査する最悪ケース」の代理にならないので、**実戦の記録の全決定点**で測る。
`bin/analyze` が常時出す（記録59局・4200決定点・release）:

| | 回数 | p50 | p95 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| 全決定点 | 4200 | 9.5µs | 76.6µs | 280.0µs |
| 終盤（90手目以降） | 89 | 41.5µs | 115.6µs | 193.8µs |

**絞り込みの効き目は 1.4倍しかない**（`TSUITATE_MATE_COST=1` の実測:
絞り込み 21.7µs/回 vs 完全版 30.2µs/回）。支配項は「王手になる手それぞれの
`has_any_legal_move`」であって、非王手手の列挙ではないため。
issue #28 の概算（B が約1,400探索・C が約1,800探索 = 合計 160〜320ms）は
終盤 p50 41µs を当てると約 130ms、p95 116µs だと約 370ms で、**予算 2000ms の
7〜19%**。P1-C の `mate_samples` と対象候補数はこの実測から決めること。

### `bin/analyze` の詰み経済セクション（P0-1 / P0-2 前半）

従来の「被詰めろ N回 / M局（うち打ち詰み K回）」を次へ置き換えた。

- **排他的分類**: 従来の `打ち詰み` フラグは `drop_mate` の有無だったので
  「打ちでも盤上でも詰む」局面が打ち側にだけ数えられ、**排他分類ではなかった**。
  全詰め手の union で `打ちのみ / 盤上のみ / 両方` に分ける
- **実行された詰め手の種別**: 実際に詰まされた手の USI で `打ち / 盤上移動`
- **エピソード単位**: 連続した相手番の被詰めろを1つに畳む（手番単位だと
  「何回危険に入ったか」と「1回の危険が何手番続いたか」が混ざる）。
  エピソード長のヒストグラムも出す
- **手数調整した露出**: bot の決定点・終盤（90手目以降）の決定点を分母にして
  100決定点あたりのエピソード数。初回被詰めろの手数も。
  「局が長くなっただけ」と「同じ手数帯でも危険が増えた」を分けるため
- **攻め／受けを分けた終局**: 全終局に占める詰み比率ではなく、
  bot の**詰み負け率・詰み勝ち率**
- **受けの漏斗**（P0-2）: 被詰めろ局面は相手番なので**一手巻き戻し**、bot の
  直前の決定点で ①真実上「指した後に相手の一手詰めが消える手」の本数
  ②それが bot の候補生成（`strategy::candidate_moves`、自駒のみ）に載るか
  ③その決定点に厳密粒子があったか（記録の `chose` の `debug.sample_slots`。
  **2手読みは厳密粒子ゼロには効かない**）。入口で受けがあったか／最後に
  回避できた手番はいつかも分けて出す

`sample_slots` は現行の `debug_summary` が出しているので、arena の
`arena-records` と実対局の記録の両方で③が埋まる（旧記録は None で欄が出ない）。
③は**その手番の最初の `chose` だけ**を見る。反則後の再選択は同じ move_number で
何度も来るが、粒子は反則の観測を食った後の別状態なので混ぜられない。最初の選択が
`debug: null`（定跡手・旧記録）ならその決定は判定不能のままにする
（回帰テスト `反則後の再選択で最初の決定の粒子状態を埋めない`）。

CI から読むために `.github/workflows/arena.yml` の analyze 出力フィルタも更新した
（このセクションの集計行がシャードのジョブサマリーと `analyze-summary.txt` に
残るようにする）。**analyze に集計行を足したらこのフィルタも直すこと**。

## P0-3 / P0-6 の実装（2026-08-27）

### 共有定義 `src/mate_economy.rs`

`bin/analyze`（P0-1/P0-2）・`bin/mate_probe`（P0-3）・`bin/mate_continue`（P0-6）が
**同じ定義**で数えるための場所。ここに置いてあるのは runtime に入らない診断だけ:

- `MateKind`（`drop_only / board_only / both` の排他的分類）と union の畳み込み
- `safe_moves_at(pos)` = 指した後に相手の一手詰めが消える手の全量（真実を見た理論上限）
- `threat_turns` / `fold_episodes` = 被詰めろの手番とエピソード（連続する相手番を1つに畳む）
- `analyze_game` = 記録1局ぶんの全部（局面列・エピソード・bot の決定点・詰み負け判定）と
  `last_defense_point()` = **最後に受けられた決定点**（P0-3 と P0-6 の出発点）
- `control_points` = 同じ手数帯の**非危険な**決定点（偽陽性率の対照）
- `particle_mate_mass` / `build_rows` / `rescore` / `pick` / `min_w_to_flip` =
  P0-3 のオフライン試作

`bin/analyze` の漏斗もこの定義へ載せ替えた（出力は同一。ローカル記録8局で
突き合わせ済み）。**定義を1箇所にしたのは、P0-3 の「危険な決定点」と
P0-2 の「受けの漏斗」が別の数え方になると較正の数字が意味を失うから**。

再スコアは **P1-B の形**（`gain` から引いて `combine_score` を通す）で計算する。
最終 score へ直接足すのとは等価でない（issue #24 の教訓⑦）ので、
`rescore(w=0) == score − tiebreak` をテストで固定してある。順位は**乱数を除いた
スコア**で付け直し、同点は USI の辞書順で割る（同教訓②）。

### `bin/mate_probe`（P0-3）

```
TSUITATE_THINK_BUDGET_MS=2000 cargo run --release --bin mate_probe -- \
  [--seeds 3] [--jobs N] [--controls 1] [--limit N] [--out data/mate_probe.csv] \
  [--emit <dir> <接頭辞>] <records/ または *.jsonl ...>
```

詰み負けした局の「最後に受けられた決定点」と、同じ局・同じ手数帯の**対照決定点**で、
現行 estimator の候補ランキングと**そのランキングを作った粒子**を
`scenario_core::ranking_and_particles` で同時に取り（`choose` が評価へ渡した
`stratified_sample` の戻りと taint プール = `strategy::ParticleSnapshot`。
その手番で既に試した反則も復元して渡す）、候補ごとに:

- **真実のラベル**: その手を指した後に相手の一手詰めが生じるか（`drop_only /
  board_only / both` つき）
- **粒子上の危険質量 q**: 候補手を各粒子へ適用して `has_mate_in_1_fast`。
  **厳密粒子だけの q と taint 込みの q を別々に**出す（初版の P1-B は厳密だけを読む）
- Brier・しきい値ごとの適合率/再現率・信頼度別の較正・**対照決定点の偽陽性率**
- 受け手の現行順位・top8 / top17 包含率・**argmax が受けへ変わる最小 w**
- 現行 `mate_risk_w`（打ち詰みのみ）の発火の有無 = 盤上詰みが視野外である確認

`--emit` は決定点を `scenarios/` 形式の kif で書き出すので、そのまま
`bin/rank_probe <kif> <ply> 3` / `bin/scenario ... diag` へ流せる。

### `bin/mate_continue`（P0-6）

```
TSUITATE_THINK_BUDGET_MS=700 cargo run --release --bin mate_continue -- \
  [--seeds 2] [--max-safe 4] [--opponent estimator_v14] [--policy-w 2,4,8,16,30] \
  [--jobs N] [--shard i/n] [--out out.jsonl] <records...>
cargo run --release --bin mate_continue -- report <out-*.jsonl...>
```

「最後に受けられた決定点」から**一手だけ強制**して `selfplay::play_continuation`
（通常アリーナと同じ裁定関数）で終局まで指し継ぎ、勝1 / 分0.5 / 負0 で数える。
arm は次の5系統（方策系は事前登録した w ごとに1本ずつなので、既定では
`baseline` / `oracle` / `policy_w0` ＋ `policy_strict@w*` 5本 ＋ `policy_all@w*` 5本 = 13 arm）:

| arm | 強制する手 | 役割 |
| --- | --- | --- |
| `baseline` | 実戦で指した手 | **指し直しの対照**。元局が負けでも 0 とは限らない |
| `oracle` | 真実の安全手（候補生成に載ったものだけ） | `Δoracle` の材料 |
| `policy_strict` | P0-3 の再スコア（厳密粒子の q） | `Δpolicy` |
| `policy_all` | 同（taint 込みの q） | `Δpolicy` |
| `policy_w0` | 同じ経路で w=0（＝現行方策そのもの） | **再決定のぶんの対照**。`Δpolicy − Δpolicy(w=0)` が危険量ペナルティ自身の効果 |

方策 arm は `policy_strict@w<W>` / `policy_all@w<W>` の形で、**事前登録した w の
集合を全部回す**（既定 `2,4,8,16,30`）。probe と continue は同じ run で同時に
走るので、**その run の P0-3 結果から w を1点選ぶことはできない**（PR #30
レビュー2巡目）。1点だけ測って棄却すると「未計測の重みなら門を超えたかもしれない」
を否定できないので、有限個を事前に決めて全部報告し、判定は**その集合の最大**で行う。
同じ候補列になった arm は継続を1回だけ走らせて結果を配る（継続の乱数は
`(局, 決定点, seed)` だけから作るので、候補列が同じなら継続は完全に同一）。

設計上の要点:

- **`Δ` の分母は記録の全対局数 G**（受けの機会が無かった局は 0 として数える）。
  CI は元対局単位の cluster bootstrap（seed を独立標本として数えない）
- **`Δoracle` は最良手を採るぶん楽観**（勝者の呪い）なので、seed を前半（選ぶ）/
  後半（測る）に割った**正直版**も併記する。中止判定（`Δoracle < 0.04`）は
  上限側で見るので楽観は保守的に働く
- **`baseline` を必ず取る**。元局が負けでも「実戦の手を強制して指し直した継続」が
  0 になるとは限らない（両者が指し直すので別の対局になる）。Δ の一部が
  「単に指し直したから」でないことをここで見る
- **方策が真実で非合法な手を選んだら、実対局と同じく反則を積んで次点へ進む**
  （手番は変わらない。上限 10 回で反則負け＝スコア 0）。ここを「非合法なら
  測定不能」にすると方策の実力を過大評価する。観測の記録は審判と同じ関数
  （`truth_replay::add_move_obs` / `add_foul_obs`）を共有する。
  近似であることは明示: 実対局なら反則の観測を食った推定器が**選び直す**が、
  ここでは同じランキングの次点を取る
- **`--max-safe` で落とした安全手の本数を必ず出す**（`Δoracle` はそのぶん下界）。
  選び方は USI の辞書順で等間隔＝現行方策に引きずられない
- **シャードが揃っていなければ判定を出さない**。Δ の分母は全対局数なので、
  1シャードだけ集計すると分子だけが欠けて Δ が机上で小さくなる（`report` が
  meta の `shard` を見て検出する。CI 側でも artifact の本数を数えて失敗させる）

### PR #30 レビューの反映（2026-08-27）

計測の妥当性に直結する4件を直した。**runtime の既定挙動は変えていない**
（粒子スナップショットは診断が明示的に on にしたときだけ保存する）。

1. **q は「ランキングを作ったのと同じ粒子」で測る**。`Strategy` に
   `set_capture_particles` / `last_particles` を足し（既定 off = コピーもしない）、
   `choose` が評価へ渡したプールそのもの（`stratified_sample` の戻りと
   taint プール）を `strategy::ParticleSnapshot` として持ち出す。
   `scenario_core::ranking_and_particles` がランキングと一緒に返す。
   **同じ seed で `build_estimator` を作り直しても同じ集合にはならない**
   （`update` は壁時計デッドラインまで若返る）ので、作り直した粒子で測ると
   「ランキングは集合A・q は集合B」になり、argmax も `Δpolicy` も
   実装予定の方策のオフライン再現になっていなかった
2. **記録の相手と継続対局の相手を突き合わせる**。ガントレットの Arena 実行は
   相手ごとに artifact が分かれるので、`arena-records-*` をまとめて落とすと
   v13 相手の棋譜まで v14 で継続してしまい、Δ が「受けの効果」と
   「相手が変わった効果」の混合になる。`mate_continue` は
   `end.opponent.username` が `--opponent` と違う記録があれば**起動時に止める**
   （`--allow-opponent-mismatch` で承知のうえ混ぜられる）。`mate_probe` も
   `--opponent` で絞れる。ワークフローの `records_pattern` は**空なら
   `arena-records-<opponent>-*` を導出**するようにした
3. **集約の契約を強くした**。meta に判定へ効く実験キー
   （相手・予算・seed 数・`max_safe`・`policy_w`・**実効並列度**・全対局数・
   シャード数・config 指紋・コード指紋・記録集合の指紋）を入れ、`report` は
   全シャードでの完全一致を要求する。同じシャードの二重投入・重複行
   （同じ 局・決定点・arm・手・seed）・baseline があるのに policy arm が
   欠けている (局, seed) も失敗させる（`--allow-incomplete` で警告へ落とせる）。
   検査は `check_inputs` に切り出してテストで固定した
4. **継続の乱数は arm に依らない**。`(局, 決定点, seed)` だけから作るので、
   baseline / oracle / policy_* が同じ乱数列で継続する（共通乱数法）。
   `Δpolicy − Δpolicy(w=0)` の差に継続乱数の違いが混ざらない

### PR #30 レビュー2巡目の反映（2026-08-27）

1. **判定の射程**: `policy_w` を1点固定にすると、その run の P0-3 を見てから
   w を選ぶことができない（probe と continue は同時に走る）。corrected P0-3 では
   argmax が受けになる率が w=4 → w=30 でまだ動く（厳密 37.2%→41.0% /
   taint 47.4%→51.3%）ので、**事前登録した有限個の w を全部回して最大で判定する**
   形にした（arm 名に w を含める・同じ候補列は1回だけ走らせる）

| 条件 | 実測 | 判定 |
| --- | --- | --- |

**結論: P1（受け側の実装）はこの形では進めない**。ただし「必要条件に 0.0015 足りない」
という読み方はしないこと:

- 最大値 +0.0385 は **run 間のばらつき（±0.01）の内側**で、しかも **10 arm の
  最大値**（選択で上振れする）。「門を超えなかった」よりも
  **「超えたと言える材料が無い」**が正確
- **w=0 対照が +0.0240** あり、危険量ペナルティ自身の寄与は最大 +0.0144 /
  たいてい +0.005〜+0.010。**`Δpolicy` の大半は「指し直した」ぶん**で、
  ペナルティが選ぶ手を変えたことによる利得ではない
- **再挑戦するならこの形の再測定ではなく、母数を上げた事前登録**が要る:
  `policy_strict@w8` を主仮説に固定し、**未使用の seed**・より多い seed 数
  （±0.01 のばらつきを 0.004 以下へ落とすには 4〜6倍の標本が要る）で1回だけ測る。
  今の 104局×2 seed では門の周辺を分解できない

中身は「受けは無意味」ではない:

- **上限は実在する**（`Δoracle` +0.125、baseline を引いて実質 +0.111・
  正直版でも +0.072）。受けが勝敗へ変換される余地はある
- **検出も足りている**（厳密粒子で適合率 0.99・誤爆ほぼゼロ、受け手は現行順位の
  中央値1〜2位・候補生成カバー率 99%）
- **変換できないのは「受けた先」**。オラクルの継続は詰みを避けた代わりに反則負けが
  56%（baseline 13%）へ増える。**律速は受けの検出でも候補生成でもなく、
  受けた後の局面での反則経済**
- 初版の P1-B が読む予定だった厳密粒子は、**盤上詰めにはそもそも質量を置かない**
  （`board_only` の平均 q 0.035）ので、`mate_risk_w` を盤上へ広げても
  発火する場所が無い

次にやるなら「受け項」ではなく **①受けた後の反則経済（王手中の確かめの残り
ギャップ 291→206 回）②粒子が盤上詰めの形を持てない信念側**のどちらか。
どちらも issue #28 の非目的か別 issue の領分なので、この issue は
**P0 の記録をもって終了**でよい（最終判断はユーザー）。

- **しかし argmax はほとんど動かない**: w をいくら上げても、受けでなかった 54 の
  決定点のうち受けへ変わるのは 3〜10 件しかない。**最後に受けられた決定点では
  候補の 87% が危険**（陽性 5302/6072）なので、上位を沈めても次の危険手が
  繰り上がるだけ（`m061`/`m036` 型の「候補が全部悪手」と同じ構図）。
  P1-C の「減点は top-k を沈めるだけで安全手を加点しない」という設計上の
  限界が、**P1 を書く前にここで見えている**
- **厳密粒子ゼロが 61%**（全決定点の既知の 29.2% よりずっと高い）。初版の
  P1-B が厳密粒子だけを読むなら、その 61% では何も起きない

#### P0-6（`--seeds 2 --max-safe 2 --shard 0/4`・思考予算 300ms）

**1シャードだけの確認なので Δ は読めない**（分母は全59局のまま、分子は
10局ぶんしかない）。`report` はシャードが揃っていないことを検出して
**判定を出さない**。

```
全 59局（詰み負け 39・継続した局 10）/ 継続 112 局ぶん・--max-safe で落とした安全手 53本
  baseline（実戦の手を強制して指し直し）: +0.0085
  Δoracle（最良の安全手・楽観）:          +0.0254（正直版 +0.0000）
  Δpolicy（厳密 / taint）:                +0.0169 / +0.0000
  対照 w=0（再決定するだけ）:             +0.0169 → ペナルティ自身の効果は 厳密 ±0 / taint −0.0169
  判定: **出せない**（シャード 1/4 しか揃っていない）
  終局理由: oracle は checkmate 13 / foul_limit 19、baseline は 12 / 8
  継続の平均: 思考 222ms / 追加反則 2.70回（うち強制手が非合法で焼いた反則 0.14回）
```

配管として読めること:

- **`baseline` が 0 ではない**（指し直すだけで一部の局は負けなくなる）。
  「元局が負けだから基準は 0」という素朴な前提はこの規模でも崩れる
- **`Δpolicy` と対照 `w=0` が同じ値**＝この母数では危険量ペナルティが
  選ぶ手を変えていない（P0-3 の「argmax はほとんど動かない」と整合）
- **オラクルの継続は反則負けが増える**（foul_limit 19/32 vs baseline 8/20）。
  真実の安全手を強制すると、その後の手番は元の対局と違う局面になるので、
  受けの価値と反則経済の悪化が同時に効く。**「受ければ勝てる」わけではない**
  ことが、この診断の存在意義そのもの
