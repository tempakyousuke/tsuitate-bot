# DeepNash（R-NaD）路線: RL 環境の設計（2026-09-27）

> 種類: 設計。状態: **提案（未実装）**。NN 段階④（フルRL）の着手。

## 背景と方針

- ついたて将棋 viewer に、作者・出所不明の DeepNash 系とみられる bot が現れ、強かった。
  解説記事はなく、作者にも聞けないので手探りで進める。
- 対局した印象（ユーザー観察）:
  - 1手の消費時間は一定で短い → **探索も粒子も使わない、観測履歴から直接手を出す方策ネット**と推定
  - 指し手はある程度散るが、やり口は似ている → 学習済みの混合戦略として自然
  - 反則をしないというより**攻めが上手く、こちらの反則を使わされる**
  - 終局は詰みと反則負けが同程度
- 3つ目は、手書きの評価では届かなかった領域そのもの（`check_strength_w` の結論:
  「選好を入れ替えるだけでは相手の反則総量は動かない。強い王手が成立する形を
  **作る**中期的な項が要る」）。RL なら、報酬が勝敗だけでも反則負けを誘う攻めが自然に出てくる。

**方針**: 学習は R-NaD（DeepNash の中核アルゴリズム）。環境・評価は既存の Rust 資産を流用し、
**物差しは今までどおり arena の凍結版ガントレット**にする。現行 bot は、新方式が v14 に
有意に勝ち越すまで本番に残す。

## 全体構成

```
tsuitate-bot（このリポジトリ）
├─ src/referee.rs      … 手単位で進める審判（selfplay.rs のループから切り出す）
├─ src/rl/encode.rs    … 観測 → テンソル、行動 ⇄ USI、行動マスク（依存は std のみ）
├─ src/rl/policy.rs    … ONNX 方策を読む Strategy（arena・本番用、名前は `rnad`）
└─ rl-env/             … PyO3 の薄いラッパー crate（maturin でビルド。本体の依存は増やさない）

tsuitate-nn（学習側）
└─ rnad/               … R-NaD 本体（PyTorch）、ネット、ONNX 書き出し
```

**不変条件: エンコーダは1か所だけ**。入力は `Strategy::choose` と同じ
`(PlayerView, ObservationLog, foul_tried)` にする。学習中の環境（Python 経由）も
arena・本番の `rnad` Strategy も同じ Rust 関数を呼ぶので、「学習時と推論時で特徴量が
食い違う」事故が構造的に起きない。観測情報の公平性も、今の arena と同じ構造で守られる
（エンコーダは observation.rs にある情報しか受け取らない）。

## 1. 審判（referee.rs）

`selfplay::play_game_with_oracle` は戦略を呼ぶループと裁定が一体になっている。
RL では「行動を1つ受け取って1歩進める」形が要るので、裁定部分を切り出す:

```rust
pub struct Referee { pos, logs: [ObservationLog; 2], fouls: [u32; 2], foul_tried: [HashSet<String>; 2], plies }
impl Referee {
    pub fn to_move(&self) -> Color;
    pub fn view(&self, color: Color) -> PlayerView;
    pub fn step(&mut self, usi: &str) -> StepResult; // Accepted / Foul / Ended(GameResult, reason)
}
```

- 裁定は今と完全に同じ: 反則は手番維持・`OpponentFoul` を相手へ・10回で負け、
  受理なら `MyMove` / `OpponentMoved`（取られたマス）/ 王手宣言を両者へ、詰み・
  ステイルメイト、`MAX_PLIES`=200 で引き分け
- **`play_game_with_oracle` は `Referee` を呼ぶ形に書き換え、裁定の実装を1つにする**。
  等価性は「seed を固定した heuristic 同士の対局で、書き換え前後の観測ログと真実が
  一致する」テストで担保する（CLAUDE.md の「観測の作り方は selfplay.rs と一致させる」を
  二重実装で破らないため）
- `Referee::from_start(StartState)` で途中局面からも始められるようにする（4b の指し継ぎ用。
  checkpoint arena の `play_continuation` も同じ入口へ寄せる）
- 時計は RL 環境では持たない（方策ネットは一定時間で指すので不要）。arena 側は従来どおり

## 2. 観測エンコード（rl/encode.rs）

**手番側を常に先手向きに正規化する**（後手なら盤を180度回す）。ネットは「自分が
下から攻める」局面しか見ない。

### 盤面プレーン（9×9）

| 群 | 枚数 | 中身 |
| --- | --- | --- |
| 自駒 | 14 | 駒種ごと（玉・飛・角・金・銀・桂・香・歩＋成駒6種） |
| 自分の着手履歴 | 2×K | 直近 K 手（K=8）の移動元・移動先。打ちは移動先のみ。線が開いた/塞がった情報の元 |
| 自分が取った駒 | 1＋7 | 取ったマスの鮮度（exp 減衰）＋取った駒種ごとのマス |
| 自駒が取られたマス | 2 | 鮮度（exp 減衰）と回数。**相手の駒が確実にいた場所**の唯一の直接観測 |
| 今の手番の反則試行 | 3＋7 | 移動元・移動先・成りの移動先、打ちは駒種ごとの打ち先。「この手は通らない」＝相手駒の存在や王手の証拠 |
| 過去の反則 | 3＋7 | 今の手番と同じ形を鮮度つきで。**打ちの駒種と成りを落とさない**（同じマスでも歩打ちの反則には打ち歩詰めという別の原因があり、隠れた盤面への証拠が違う。codex レビュー指摘） |
| 王手宣言の履歴 | 2 | 自分が王手されたときの自玉の位置、自分が王手をかけた手の移動先（どちらも鮮度つき） |
| 初期配置から未着手の自駒 | 1 | 定跡・囲いの判断用 |

実装（`src/rl/encode.rs`）では下のスカラーを全面に放送したプレーンも含めて **86 枚**。
鮮度の減衰率・K は最初は固定値にし、後から調べる。
反則の移動元と移動先の**対応**（どの移動元の手がどの移動先で反則したか）はプレーンでは
表せず、同じ手番に複数の反則があると混ざる。困ったらイベント列の入力で扱う（履歴の持ち方の節）。

### スカラー（全マスへ放送してプレーンにする）

- 自分の持ち駒 7種（枚数を正規化）
- 相手の**駒種別保有数（盤上＋持ち駒）**: 駒種の総数 − 自駒 − 自分の持ち駒。平手なら
  **視界だけから確定する**ので履歴が欠けても正しい（持ち駒と盤上の内訳は、相手の打ちが
  観測できないので分からない）
- **履歴の食い違い**: 観測ログから再構成した自駒・持ち駒が視界と一致しなければ 1。
  本番でプロセス再起動により履歴を失った場合などに、履歴由来の特徴が信用できないことを知らせる
- 自分の反則数・相手の反則数（0〜9 を正規化＋「あと1回で負け」の指示子）
- 今の手番で既にした反則の回数
- 王手されているか・直前に王手をかけたか
- 手数 / 200

### 履歴の持ち方について

本家 DeepNash は再帰を使わず、観測に履歴の要約を入れている。まずそれに倣って
**固定長の要約（上の減衰プレーン）**で始める。学習が頭打ちになり、原因が「記憶不足」と
見えたら、イベント列を読む Transformer に置き換える（その時点で判断）。

`belief_features.rs`（観測だけから作る 35 特徴量。1決定点 81 回の計算で安い）を
追加プレーンとして入れる選択肢もある。学習が速くなる見込みがあるが、まずは素の観測で
始めて、比較実験として足す。

## 3. 行動エンコード

AlphaZero（将棋）と同じ **139 枚 × 81 マス = 11,259 行動**:

- 移動元のマス × 移動の種類 139:
  - 8方向 × 距離 1〜8 = 64、桂の2方向 = 2、それぞれ不成/成 → 132
  - 打ち 7種（このとき「マス」は打ち先）→ 7
- 手番側を先手向きに正規化してから符号化する（後手でも「前」は常に同じ方向）

### 行動マスク

- `board.rs` の**自駒だけを見た候補手**（`move_targets` / `drop_targets` /
  `promotion_choice`。成り・不成・強制成りを展開）から、**今の手番で既に反則した手を除く**
- 見えている範囲で確定する反則（二歩・行き所のない駒・自駒のマスへの移動・自駒を
  飛び越える移動）はマスクで落ちる。見えない相手駒による反則はマスクに入らない
  （それを学ぶのがネットの仕事）
- **健全性の検査を常設**: ランダム対局の全局面で「真の合法手 ⊆ マスク」をテストする。
  マスクから真の合法手が漏れると、その手を永久に指せない方策になるため

#### 観測から確定する反則の除外（`MASK_VERSION` 2、2026-10-02〜）

本番の webhook 対局で rl_v20 が「王手を絶対に解消できない手」で反則を重ねていた
（39手目に 3九の金を取られて 7九玉に王手 → 同じ横の筋の 6九玉・8九玉、合駒にならない
8九銀・6八金で4反則。別局では1一玉の王手中に筋と無関係な竜・金・角で3連続反則して
反則負け）。結果が確定している反則は情報を何も生まず反則回数だけ使う＝常に劣るので、
ネットに報酬から覚えさせず（反則の損は反則負けの局からしか信号が来ない）マスクで落とす。

- 落とすのは**論理的に確定する手だけ**（「たぶん反則」はネットの領分）:
  1. 反則した手の成/不成の片割れ（合法性は盤上の占有だけで決まる）
  2. 直前に相手が駒を取ったマスへの打ちと、そこを飛び越える移動
  3. 王手中に、王手駒がいうるマスの集合 H のどの仮説に対しても王手を解消しない手。
     H は「玉の8方向の最初の自駒の手前まで＋桂の王手マス」。直前の相手の手が駒を
     取っていれば（直前の自分の手は合法＝それまで王手は無かったので）「取ったマスの着手駒」
     か「着手駒の元のマスが空いて通った開き王手の飛び駒」に絞れる。玉の手は、2マス以上
     離れた筋の上の仮説（＝飛び駒）に対して同じ筋の上へ逃げる手だけを落とす
  4. （2026-10-02 追加）**相手の駒がいると確定したマス**への打ちと飛び越え。根拠は直前に
     取られたマスに加えて、王手中でないときの歩以外の打ちの反則（原因は打ち先の占有しかない）、
     間が1マスの飛び越え反則（遮りは間の1マスにしかいられない）
  5. （同）**飛び越え反則の先**: 王手中でないときに2マス以上の直線移動が反則で、駒がピンされえない
     （玉の筋で最初の自駒でない、または移動がその筋と平行）なら原因は途中の遮りしかないので、
     同じ元から同じ方向へそれより先へ進む手も落とす
  - 反則から推論するのは自駒視点の候補手の反則だけ（候補外の反則は原因が成りの選択などでありうる）
  - 4・5 を足した後の規模: 記録で除外に当たる反則は arena 400局で 83 → 97、本番 83局で 35 → 37。
    打ちマス・経路封鎖は反則原因の1・2位だが、同じ手番で同じ遮りに2度ぶつかることは少ないので
    伸びは小さい。マスク1回のコストは記録の決定点平均で 21µs（旧マスク）→ 25µs
  - 動けないと確定している相手の歩（`deduce::immobile_opponent_pawns`）も占有の根拠に試したが、
    ログを毎回先頭から辿るのでマスクのコストが約2.5倍になる割に、記録483局で反則2件にしか
    効かなかったので入れていない（2026-10-02 ユーザー判断）
  - 王手中に「ピンされえない駒の1マス／桂跳びの移動が反則したマスは、別の駒が来ても王手が残る」
    （別の駒での取り直し・そこへの打ちを落とす）も健全だが、記録483局で反則7件（王手中の反則の
    約0.3%）にしか効かなかったので見送った（2026-10-02 ユーザー判断）。玉の隣の駒は「玉の筋で
    最初の自駒」になりやすく、ピン判定を「向こう側に空きがあるときだけ」と精密にしないと0件
- 除外で候補が尽きたら旧マスクへ戻す（健全なら起きない。指せなくなるより安全側）
- 健全性: 王手を優先する偏った乱択 4万局（合法手 8,900万・王手中 69万局面）と、
  実戦記録 483局（CI arena 400局＋本番 83局、合法手 280万）で違反 0
- 規模: 記録された反則のうち除外に当たるのは arena 400局で 3,818 中 83（王手中 2,043 中 67）、
  本番 83局で 764 中 35（王手中 427 中 29）。反則全体の 2〜5% と小さいが、残り反則が
  少ない終盤に連続して出ると反則負けに直結する
- arena（2026-10-02、rl_v20 の重みを新マスク `rl_policy:` と旧マスク `rl_policy_basic:` で、
  `match_seed=20261002`・各200局。run 36965825339 / 36965828025）:
  - vs rl_v20: 52.2% vs 50.7%、**局ごとのペア差 +1.5pt ±1.7**。乱数を共有するので手順が
    分かれたのは11局だけで、勝敗が変わった3局は**3局とも新マスクの勝ち**。
    反則/局 5.80 vs 5.89（ペア差 −0.09 ±0.08）
  - vs estimator_v14: 85.5% vs 84.5%（+1.0pt ±6.8。相手が壁時計予算で手順がほぼ全局で
    分かれるのでペアの効きは無い）。**王手中の反則/局 1.24 vs 1.50**
  - 回帰なし・効果は小さいが一貫して正。除外に当たる反則が全体の数%なので想定どおり
- 旧マスクは `basic_legal_mask`（戦略名 `rl_policy_basic:<path>`）。凍結版 rl_v15〜rl_v22 は

## 4. 報酬とエピソード

- **終局時だけ ±1、引き分け（200手）は 0**。反則・駒得・王手に途中報酬は付けない
  （反則を誘う攻めは勝敗だけから出てくるはずで、途中報酬はそこへ偏らせる）
- 反則した場合、次の手番も同じプレイヤーになる。R-NaD は一般の展開形ゲームを扱うので、
  同じプレイヤーが続けて行動しても問題ない
- 1局の長さは最大 200 手＋反則 18 回

### 報酬を勝敗だけにする理由（2026-09-27 ユーザーとの議論）

「惜しい負け」「辛勝」を報酬で区別したくなるが、区別の物差しは駒得や手数になり、
**駒得を報酬に混ぜると頓死を軽く罰する方向へ働く**（駒得して追い詰めた末の頓死は、
駒得分だけ「惜しい負け」になってしまう）。勝敗だけなら、駒得していようが頓死は −1 で、
方策は「駒得しても玉が危ないなら意味がない」を学ぶしかない。
「惜しさ」は価値ヘッドの出力（勝率の見積もり）として自然に表れるので、報酬に入れる必要はない。

ただし勝敗だけの報酬は信号が薄く、学習が遅い。そこで**目的は変えずに学習を速くする**
補助タスクを付ける（損失に足すだけで報酬には入れない。推論時には使わない）:

- **真の盤面の予測**: 相手駒の位置・駒種、相手玉の位置。学習時は審判が真実を知っているので教師にできる。
  入力は観測だけなので、推論時に情報が漏れることはない（信念ネット＝段階②の知見を、
  別のネットでなく共有の表現として取り込む形）
- **近い将来の詰みの予測**: 「N 手以内に自玉が詰まされるか / 相手玉を詰ませるか」（N=1,3,5）。
  頓死の手前で「危ない」という表現を早く作らせるため
- 駒の損得の予測（補助。報酬には入れない）

報酬の整形がどうしても要る場合は、最適方策を変えないことが保証されるポテンシャル型の
整形だけにする（今の時点では使わない）。

## 4b. 途中局面からの指し継ぎ（逆向きカリキュラム）

勝敗だけの報酬は終局で1回しか出ないので、序盤の手ほど信号が遠く、学習が遅い。
そこで**対局の終盤から指し継ぐ**エピソードを混ぜ、信号の近いところから学ばせる。
開始点を少しずつ手前へずらしていく（逆向きカリキュラム。一本の実演の終わり近くから
始めて開始点を戻していく手法が、報酬の疎な課題で有効だったのと同じ考え方）。

当初は「頓死した局面を拾う」形で考えたが、頓死の機械的な抽出は難しい
（`mate_economy` の定義は一手詰め基準で、長手数の頓死を拾えない）。**無作為に選んだ
対局の終盤から始めれば定義は要らず**、頓死も詰ませ損ないも反則負けの手前も
自然に含まれる（2026-09-27 ユーザー提案）。頓死の抽出は、後で重み付けとして足す選択肢に格下げする。

### 情報不完全ゲームでの「局面」

ついたて将棋では局面＝盤面ではなく、**真実の盤面＋両者の観測履歴**の組になる。
これは既に `selfplay::StartState`（真実の盤面・両者の観測ログ・累積反則数・手数）として
あり、checkpoint arena（issue #19）が同じ仕組みで途中から指し継いでいる。
記録からの復元は `truth_replay`（両者の観測列の再構成）が担う。
`Referee` を `StartState` から作れるようにすれば、そのまま使える。

### 開始点の選び方

- 開始点は「終局の k 手前」で決める。k は `[0, K]` から一様に選び、**K を学習の進み具合に
  合わせて広げる**（例: 開始時 K=20 → 終局付近の勝率予測が安定したら 40, 80, …、最後は
  対局の頭まで = 通常の対局と同じ）
- 同じ開始点から何度でも指し継げる（方策はサンプリングなので毎回違う展開になる）。
  1つの記録から多数のエピソードが取れる
- 反則数が9に達している開始点は、そこから数手で反則負けになりやすい。除かずに残すが
  （「あと1回で負け」の状態で指す練習になる）、比率が偏っていないかは監視する

### 開始点の出どころ

1. **既存の記録（初日から使える）**: arena-records（v14 の自己対局）
2. **自分の対局（学習が進んでから）**: 学習中の自己対局をそのまま記録して開始点にする

1. には偏りがある: そこに至る履歴は v14 の指し方で、**履歴から推測すべき隠れた情報の
分布も v14 の相手が作ったもの**になる。ネットは「この観測なら相手駒はこの辺」を
v14 の癖で覚えてしまう。これは開始点が情報不完全ゲームであることに固有の問題で、
完全情報ゲームなら起きない。なので 1. は立ち上げ用と割り切り、**自分の対局が溜まったら
2. へ切り替える**。2. なら履歴も隠れた情報も今の方策が作ったものなので偏りはない。

### 注意点

- **通常の対局と必ず混ぜる**（例: 通常 50% / 指し継ぎ 50% から始め、K が広がるにつれて
  指し継ぎの意味は薄れていく）。指し継ぎだけにすると序盤・中盤が育たない
- 頓死した側だけでなく、**詰ませた側の視点**も同じ指し継ぎから学べる
  （両者を同じネットで学習するので、攻め側の「頓死を狙う」力も同時に育つ）
- 価値ヘッドが育ったら、開始点を「予測が外れた対局」（勝勢の見込みから負けた＝頓死・逆転）
  に寄せる重み付けを足せる。手で頓死を定義しなくても、ネット自身の見込み違いで拾える

## 5. Python 環境（rl-env crate）

- `VecEnv(n)`: n 局を並列に持つ。`reset()`、`observe() -> (obs[n,C,9,9], mask[n,11259], player[n])`、

### codex レビュー（2026-09-27）で直したもの

- **終局手のフィッシャー加算漏れ**（退行）: 旧実装は受理手の適用直後・終局判定の前に加算して
  いたが、切り出し直後は `Accepted` にしか加算していなかった。`StepResult::Ended` に
  `move_accepted` を持たせて詰み・ステイルメイト・手数上限の手にも加算する。等価性ダイジェストは
  時計なしで回すので `selfplay::tests::終局手にもフィッシャー加算が付く` で別に固定
- **開始時点で終局済みの局面**: `Referee::from_start` が終局を判定して `ended()` に持ち、
  以後の `step` は何も記録しない（逆向きカリキュラムの k=0 は終局そのものを開始点に選びうる）
- **過去の反則で打ちの駒種と成りが消える**: 今の手番と同じ 3＋7 枚の形で持つ
- **履歴が欠けると誤った特徴を確定値として出す**: 相手の保有数を視界だけから出す形に変え、
  履歴の食い違いの印を足した
- 等価性ダイジェストは「終局手で追加された最後の観測」を採取しない（次の `choose` で採るため）。
  終局手も通常の受理手と同じ `accept` を通るので実害は低いと判断し、ダイジェストは据え置いた

### M2a の実装（2026-09-27、ブランチ `rl-deepnash-m2a`）

- **教師**: 日次の Mine tsume（現行 estimator 対 v14 の自己対局 160局/日、記録は90日保持）の
  `arena-records-mine-*`。`tsuitate-nn/rnad/fetch_records.py` が `data/rl_records/<run_id>/` へ取る
  （30日で 4,800局・試行 53万件）
- **`src/rl/records.rs`**: 真実（全手順＋反則試行）を**試行ごとに** `Referee` へ流し直し、各試行の
  直前の審判を渡す（反則した試行も教師にする）。観測は arena と同じコードで作られる。
  ランダム局で「再生 = 元の対局」、実記録 20局（2,212試行）で「再生した観測 = 記録された観測」
  を確認済み。`RecordDataset` は読み込み時にこの一致を全局で検査し、食い違う局は捨てる
- **`rl-env` の `RecordDataset`**: 局単位で並列にエンコードして numpy で返す（観測・マスク・
  教師の行動・手番・価値の教師＝手番側から見た終局の結果・反則だったか）
- **`tsuitate-nn/rnad/`**: `model.py`（ResNet。方策 [139,9,9]・価値 tanh）、`train_bc.py`
  （局単位で学習/検証を分ける。マスク付き交差エントロピー＋価値の MSE）、
  `export_weights.py`（BatchNorm を畳み込みへ畳み込んで `TSRLPV01` 形式で書く）
- **`src/rl/policy_net.rs`**: 手書きの forward pass（依存を増やさない）。小さいネット
  （BatchNorm の統計も乱数）で PyTorch の出力と一致することをフィクスチャ
  （`tests/fixtures/rl/tiny_policy.*`）で常時検査。64ch×6ブロックで 1手 約13ms
- **`src/rl/policy.rs`**: 方策ネットで指す戦略。`strategy::make("rl_policy:<重みのパス>")`
  （softmax からサンプリング）/ `rl_policy_greedy:<パス>`（最大の手）。重みはパスごとに1度だけ読む

**codex レビュー（2026-09-28）で直したもの**:
- [P0] 記録の勝敗を再生の裁定と照合していなかった（勝者を取り違えた記録・読めない結果文字列・
  途中で切れた記録が価値の教師を汚す）→ `records::verify_outcome`。審判が判定する終局
  （詰み・ステイルメイト・反則負け・手数上限）は勝敗と理由の完全一致、審判の外の終局
  （時間切れ・投了）は再生が未終局であることを求める。実データ 4,800局は全局通過
- [P0] 学習率スケジュール（OneCycleLR）の総更新数が実際の更新回数とずれていた（局の長さが
  不揃いで端数バッチが出る）→ 処理した標本数を進み具合にした warmup＋cosine
- [P1] 対局記録から使った重みを特定できなかった → 重みの内容の sha256 で識別し、`name()` を
  `rl_policy@<先頭12桁>` にした（同じパスを上書きしても別の戦略として記録される）。
  chose の debug にも sha256 を入れる
- [P1] 取得が途中で切れた run を取得済みと判定していた → 全 artifact を取り終えたら `.complete`
- [P2] 同じ棋譜（着手列＋反則試行列が完全一致する局。4,800局中13局ぶん）が学習と検証の両方に
  入りうる → 棋譜の署名でまとめて分ける
- [P2] エンコードのメモリ → 結合先を先に確保し、学習側はチャンクごとに手放す
- 特徴量・行動の並び・BatchNorm の畳み込み・Rust の畳み込みのインデックスの一致と、

### 重みの置き場所（2026-09-28 ユーザー判断）

重みは差分圧縮が効かず（学習し直すと全部の値が変わる）、コミットのたびに履歴が
約2MB（64ch×6ブロック）ずつ永久に増える。ネットを大きくすれば1個10MB を超える。
そこで次のように使い分ける:

- **実験中の重み → GitHub Release**（prerelease、タグは `rlw-<内容>-<日付>`）。arena では
  戦略名に `rl_policy:release:<タグ>/<ファイル名>` と書くと、arena ジョブが
  `scripts/ci/resolve_rl_weights.sh` で取ってきて手元のパスへ置き換える（候補・基準のどちらにも書ける）。
  例: `gh workflow run arena.yml --ref <ブランチ> -f candidate="rl_policy:release:rlw-bc-m2a-20260928/policy.bin" -f match_seed=...`
- **採用した版だけリポジトリへコミット**（`models/`、凍結版と同じ扱いでガントレットの基準にする）
- Git LFS は無料枠の転送量（月1GB）を CI のダウンロードが食うので使わない
- 使った重みは記録上の戦略名（`rl_policy@<sha256 先頭12桁>`）と Release のノートの sha256 で照合できる

M2a を先に置く理由: RL は「学習が進まない」ときに原因の切り分けが難しい。教師ありは
うまくいくはずの課題なので、ここでエンコーダや配管のバグを先に潰しておく。
M2a の模倣方策で R-NaD を初期化するかどうかは、M2b でゼロからの学習の伸び方を見て決める
（初期化すれば計算量は大きく減るが、v14 の癖を引き継ぐ）。

### M2b の実装と最初の計測（2026-09-28、ブランチ `rl-deepnash-m2b`）

- **`tsuitate-nn/rnad/rnad.py`**: R-NaD の PyTorch 実装。OpenSpiel の rnad.py（2025-05 に
  OpenSpiel から削除されたので、削除直前の d1dcdf5）の移植で、**損失と勾配が参照実装と一致する**
  ことを、参照実装（使い捨て venv の JAX）で乱数入力から計算したフィクスチャ2組で検査する
  （`rnad/tests/`。反則で同じプレイヤーが続く並び・長さの違う局・引き分けを含む）。
  参照との違いは持ち方だけで、行動数 11,259 の Q ベクトルを作らずアドバンテージを
  `−η(lpr_a − Σπ·lpr) + s(1[a=選んだ手] − π_選んだ手)` に分解して持つ
- **`rl-env`**: `VecEnv(auto_reset=False)`・`reset()`・`alive()`（1局を丸ごと集めるため。
  止まった局の行動は -1、マスクは空）
- **`train_rnad.py`**: 64局を最後まで自己対局 → 1更新（約7〜8秒）。進み具合は**錨（模倣ネット）との
  直接対戦**で測る（凍結版は1手1秒以上かかり学習ループに入れられない）

**1回目（参照の既定 β=2、300更新）は失敗**: 錨への勝率は横ばいに見えたが、評価に使っていた
ターゲットネットは現在のネットにゆっくり追従するだけで（300更新で約26%）、**現在のネットは錨に
23% まで弱くなっていた**。原因は **NeuRD のしきい値 β**（合法手の平均を引いたロジットが ±β を
超える方向へは押さない）。参照の既定 2.0 は小さいゲーム用で、模倣ネットの最善手は平均より
+6.6（中央値。99% 点 +14.9）にある。β=2 ではこれが押し下げられ、300更新で最善手 +3.7・
±2 の内側の合法手 67% → 90% と**方策が平らに潰された**。
→ **β=16**（模倣ネットの広がりより上）にし、評価は**現在のネットとターゲットの両方**を記録する。

**2回目（β=16、300更新・自己対局 19,200局、約45分）**: 劣化は止まった。錨への勝率（256局×12回の合算）は

  （自己対局の手数 56 → 46〜50・錨への勝率 0.50 → 0.61〜0.69）のような効き方は出なかった =
  **「速攻報酬で搾取役の伸びが速くなる」仮説は支持されない**（ただし対照の A すら伸びていない）
- **見立て: R-NaD は固定した相手への最善応答を学ぶ手法ではない**。正則化方策（＝少し前の自分）へ引き戻す項が
  相手の穴へ寄っていくのを抑える。普通の搾取役（AlphaStar の main exploiter、近似最善応答 ABR = Timbers ら 2020）は
  どれも**相手を環境の一部として固定した一人用の RL**（ナッシュ向けの正則化なし）で作る。したがってこの結果は
  「rl_v29branch_v1 に穴が無い」の証拠にはならない。搾取役を再挑戦するなら `--eta 0`（正則化を外した
  v-trace＋NeuRD の方策勾配に近い）か、PPO 等の一人用 RL の実装から
- この結果から、本線の R-NaD の回し方そのものを本家と突き合わせた（次節）

## 本家 DeepNash との設定の比較と今後の学習方針（2026-10-13）

搾取役が伸びなかったことと、本線が「直前の版には勝つが外の相手へは下がる」（25,000 で −2.1、30,000 で −4.0）ことを受けて、
DeepNash の論文（Perolat ら、Science 2022、arXiv 2206.15378）の学習設定を確認した。

**本家の作り方**:
- **完全な自己対局**。リーグ・搾取役・過去版との対戦は一切ない。外部 bot 8種に「どれとも学習中に対戦していないのに」
  97〜100% 勝ったことを強調している
- **搾取されやすさ（exploitability）は測っていない**（最善応答の推定はストラテゴでは計算上無理として見送り、
  頑健さの根拠はナッシュ均衡の理論に置く）。途中の版が外の相手に弱くなった報告や、忘却・非推移性の分析も無い。
  進み具合は固定の bot との対戦と、元世界王者 Vincent de Boer が版ごとに弱点を探すことで見ていた
- 実戦では後処理を入れる: 確率 0.03 未満の手を捨てて正規化し直す・確率を 1/16〜1/32 刻みに丸める・
  二手読みの価値の上界で明らかな悪手を消す（勝率の改善は大きくない、とある）

**学習の設定の比較**（論文の Table 3）:

| | DeepNash | 本線（main_from_speed3） |
| --- | --- | --- |
| 正則化方策の差し替え間隔 Δm | **1万更新**（最初の100回）→ **10万更新**（次の65回）→ 3.5万更新 | **200更新** |
| 総更新回数 | 721万 | 約3万（旧本線は 6.5万） |
| 1更新あたりの局数 | 768 | 256 |
| 学習率 | 5e-5 | 2e-4 |
| η | 0.2 | 0.2 |
| ターゲットネットの平均化係数 | 0.001 | 0.001 |
| α の補間 | min(1, 2n/Δm) | 同じ（`EntropySchedule`） |

**ここから言えること**:
- R-NaD の理論は「正則化方策を固定したゲームで**収束するまで**学習してから差し替える」ことの繰り返しを前提にする。
  本家は最初の段階だけで 1万更新 × 100回 = 100万更新をかけている
- 本線は 200更新ごとに差し替えている。ターゲットネットの平均化係数 0.001 では、ターゲットネットが追いつくのに約1,000更新
  かかるので、**ターゲットネットが追いつく前に正則化方策が5回差し替わる**。各段階が収束にほど遠いまま
  「少し前の自分」へ引き寄せられ続けているだけで、R-NaD が避けようとしている素朴な自己対局に近い可能性が高い。
  そうなら「前の版には勝つが外の相手へは下がる」循環が起きても不思議ではない
- 本線の総更新回数は、本家の差し替え1〜3回分にしかならない
- したがって「リーグが悪いのか」より先に、**R-NaD として正しく回っていない可能性**を確かめる。
  リーグ学習は 55,000更新で「外の相手への伸びが無い」形を解いた実績がある（上の rl_v25 の節）が、
  それも Δm=200 の上での話

**計測と凍結の間隔（2026-10-13 方針）**: **Δm の区切りに合わせる**。R-NaD の学習は「正則化方策を固定したゲームを解く」
段階の繰り返しで、区切りの直前がその段階の答えに一番近い状態、途中は α の補間（段階の前半は前の正則化方策が混ざる）の
最中で解きかけ。途中の版を測ったり凍結したりすると、版ごとに「どの段階のどこまで進んだ状態か」がばらばらになる。
これまでの「5,000更新ごと」は Δm=200 なら区切りと一致していたが、Δm=2,000 では 25,000 などが段階の途中に当たる。

| 用途 | Δm=2,000 のとき | Δm=10,000（本家寄り）のとき |
| --- | --- | --- |
| 学習中の錨への勝率 | 今どおり 50更新ごと（監視用。読むのは区切りの値だけ） | 同じ |
| CI のガントレット | **2,000更新ごと**（32,000, 34,000, …）。1段階はゲーム用 PC で約4時間（Δm=200 のリーグ込みの実測が 1更新 約7.1秒。自己対局だけならリーグの対局が無いぶん短くなりうる） | 1段階 = 10,000更新ごと |
| 凍結 | **10,000更新（5段階）ごとを目安**。条件は「直前の凍結版に負け越さず、外の相手を落とさない」（2026-10-17 に「有意に勝ち越し」から緩めた） | 1段階 = 10,000更新ごと |

- **凍結を間引く理由**: 近すぎる版どうしは差が出にくく「直前の版に有意に勝ち越す」の判定が苦しくなる。凍結版は既に23体で
  多くが本線の近い版なので、増やすほどガントレットが自分の系列で埋まり、「練習相手への慣れ」と外の強さの区別が
  さらに難しくなる。差し替えるより、別系統の相手（estimator_v14、rl_search のような系列の違う相手）を足すほうが効く
- **リーグを再開する場合も、新しい凍結版を加えるのは Δm の区切りでだけ**。段階の途中で相手を変えると、その段階で
  解いているゲーム自体が途中で変わる（これまでの本線は 5,000更新ごとに足していて Δm=200 の区切りとは一致していたが、
  Δm=200 では各段階が収束しきらないので、区切りに合わせる意味が薄かった）

## 中盤の信号の薄さと、ついたて将棋向けの学習の改善案（2026-10-13）

指し継ぎ実験（4b）のひっくり返り率を読み直すと、勝敗だけの報酬で中盤が育たない理由と、効きそうな対策・
効かなそうな対策が分かれる（コードは未変更。読みと提案だけ）。

**ひっくり返り率 = 完璧な V_真実 の値**: 指し継ぎは真実の盤面と両者の観測履歴を丸ごと再現し、同じ方策で
指し直している。ひっくり返り率は 2p(1−p) で、p はその局面の本当の勝率 = 完璧な V_真実 の値そのもの。
V_真実 で説明できる勝敗の分散の割合は E[(2p−1)²] = **1 − 2 × ひっくり返り率**（引き分けは無視）:

| 終局まで残っていた手数 | 0〜2 | 3〜5 | 6〜10 | 11〜20 | 21〜40 | 41〜 |
| --- | --- | --- | --- | --- | --- | --- |
| ひっくり返り率（rl_v28 同士） | 3% | 18% | 25% | 42% | 49% | 48% |
| 完璧な V_真実 で説明できる分散 | 94% | 64% | 50% | 16% | **2%** | **4%** |

- **中盤の手の信号が薄いのは、隠れた配置の運のせいではない**。原因はその後の展開（方策のサンプリングと、
  終盤の反則・詰みの揺れ）にある
- したがって **V_真実 をベースラインにする案（下の「案: 真実を見る価値ネット」）は中盤ではほぼ効かない**。
  その節の「先に測ること」は、このデータで答えが出ている（効くのは終局の約10手以内で、そこは V_観測 も
  AUC 0.76〜0.91 と当たっている）
- **λ-return や c<1 のブートストラップは、このデータだけでは効くとも効かないとも言えない**。これらは中盤の局面の
  価値に頼るのではなく、n手先の価値で「その後の展開の揺れ」を期待値に置き換えて目標の分散を減らすもの。
  終局の約10手以内は価値が当たる（上記 AUC）ので、そこまで先へ延ばして使えば終盤の反則・詰みの揺れ
  （残り3〜10手でひっくり返り率 18〜25%）は消せ、中盤の手の小さな信号の信号対雑音比は上がりうる。
  一方で区切りを近くに置くほど、中盤の価値はほぼ 0 なので信号ごと消える（偏り）。効き目は区切りの置き方次第で、
  測らないと分からない
- 勝敗だけの報酬では中盤の技術がノイズに埋もれる。「攻めを切るのが下手」の実測（取り返し rl_v27 55% 対
  相手 62%、見送った駒の 83% がと金）と合う
- 報酬の整形は避ける方針（4節）なので、中盤の密な信号は**目的を変えない補助損失**から入れる

**改善案（優先順）**:

1. **真実の盤面を予測する補助ヘッド**（4節で予定し、M2c で未実装のもの）

     w × 交差エントロピーを損失に足す。報酬にも R-NaD の目的にも触らない
   - 方策は今、相手駒の位置の信念を勝敗の ±1 だけから作るしかない。観測だけのネットで占有を当てられることは
     段階②で実証済み（対数損失 0.62 → 0.38）。ラベルは1決定点あたり81マス分あり、勝敗の1ビットより桁違いに密
   - 実装: `EnvGame` は `referee.position()` を既に持つ（`guard_fraction` が使う）ので、手番側へ向きを揃えた
     真実のラベルを `observe` と一緒に返すだけ。Python 側は 1×1 畳み込みのヘッドを1本。ヘッドを書き出さなければ
     Rust の推論・`export_weights`・凍結版は不変で、rl_v29 の checkpoint からそのまま始められる。リーグの局でも使える

4. **（仮説）ネットの容量**: 64ch × 6ブロック（約50万パラメータ）。「前の版に勝つが外の相手を忘れる」は
   容量不足でも起きる。arm 3 で直らなかったときの候補。rl_v29 を大きいネットへ蒸留してから R-NaD を続ければ
   安く試せる。本番の rl_search は1手約2.3秒の大半が推定器なので、推論の時間は問題になりにくい

**進め方**: arm 3（Δm=2,000）の判定を先に出す。補助ヘッドは arm 3 で勝った設定に足す新しい arm として回す
（同時に入れると交絡する）。線形プローブは学習を回さないので、arm 3 の実行中に準備できる。

**続き（2026-10-20）**: 学習方法どうしの速さの比べ方と、学習なしの診断（本線の勾配の雑音のほとんどが、まれにしか選ばれない手の
1/μ から来る）・CPU の代理実験・数式を変えない高速化は `docs/rl-learning-speed.md`。

## 手番局面の探索（rl_search、2026-10-05〜06）

Ataraxos（Stratego、arXiv 2511.07312 / Nature 2026-09-30）の test-time search を簡約して移植した（`src/rl/search.rs`）。
Ataraxos は信念ネットから隠れた局面をサンプルし、候補手×サンプルのロールアウトで手番局面だけ磁気ミラー降下を1ステップ回す。
ついたて将棋は駒の位置まで隠れるので、信念サンプルは粒子フィルタ（`Estimator`）、相手の応手は opp_move NN（`predict_opp_reply`）で代用し、
2手（自分の手 → 相手の応手）で打ち切って自分の次の決定点を方策ネットの価値ヘッドで評価する。反則は手番維持の遷移として評価し、
200手・反則上限・詰みは `Referee` と同じ裁定（一致はテストで検査）。選択は π'(a) ∝ π(a)·exp(η·Q(a))（上位 k=8 手、粒子 n=16）。

**方針（2026-10-06 ユーザーと合意）**: 探索は**学習ループに入れない**（Ataraxos・DeepNash と同じ。1手 12ms → 2.4秒で自己対局の量が死ぬ・
探索の伸びの多くは粒子の論理推論でネットが直接は学べない・η の大きい探索方策を蒸留すると混合戦略が崩れる）。
学習側でやるのは **勝敗だけを目標にした価値ヘッド**（今の価値ヘッドは R-NaD の正則化報酬込みで、探索の末端評価としては近似）と、
**凍結版の採否を探索ありの強さでも測ること**。

実測（vs rl_v25、200局、時計 1000+3）:

| 設定 | 勝率 |
| --- | --- |
| η=0（上位8手に切り詰めるだけの対照） | 52.0% |
| η=10 | 63〜67% |
| η=30（5本合算 1000局） | 74.1%（各 70.5〜80.5%） |
| η=100 | 74.5% |
| η=30・整合粒子が全滅した手番で探索をやめる | 66.5% |

- **同一設定でも run 間で 7.6pt 振れた**（80.5% と 72.9%。推定器の壁時計打ち切りで対局が揃わない）。η=30 の変種（ソフト救済粒子の有無 `soft`・
  応手モデルへ露見マスを渡すか `known`）の差は検出できていない
- 唯一の明確な負けは「物理不整合の粒子しか無い手番で探索をやめる」版（未探索の手番を含む39局で、同じ局の勝率 90% → 36%）。
  終盤・王手中など推定器が破綻した局面でも、不整合粒子で探索するほうが素の方策よりずっと強い → 既定は `taint=1`（不整合粒子へ退避）
- ガントレット（各100局、match_seed=20261005）で**全16体に上積み**: 合計 68.6% → 80.5%（+11.9pt）。特化版への伸びが大きい
  （防御 +23・速攻v1 +19・入玉 +17）。v14 85 → 95%。残る弱点は rl_speed_v2（34 → 46%）
- 本番時計 300+3（v14・rl_v25・rl_speed_v2 各100局）で時間切れ0・残り最小 280秒。1手 平均約2.3秒・p99 約4秒
- webhook のコールドスタート（80手の合成履歴）: 8.2〜8.6秒 → 推定器の更新（prewarm 込み）が `slow_ms`（既定4秒）を超えた手番は
  探索を省くガードで 6.5秒
- 2026-10-06 に本番2サービス（運営bot・webhook bot）を `rl_search:models/rl_v25.bin,eta=30` へ切り替えた

### 価値ヘッドの較正（2026-10-06）

探索の末端評価に使う rl_v25 の価値ヘッド V は、R-NaD の正則化報酬（自分の手番ごとに −η·KL(π‖π_reg)、相手の手番ごとに +η·KL、
η=0.2）込みの目標で学習している（`tsuitate-nn/rnad/rnad.py` の `v_trace_scalars`）。純粋な勝敗の期待値ではないので、
「勝敗だけを目標にした価値ヘッド」を足すべきかを判断するため、arena の記録（`debug.value`、手番ごとに最初の決定点だけ）と
終局の勝敗 z を突き合わせた。

自己対局に近いデータ（η=0 対照の rl_v25 同士 200局・ガントレット対照の rl_v25 同士 100局、計約9,300決定点）:

| V の帯 | V の換算勝率 | 実際の勝率（η=0 対照 / rl_v25 同士） |
| --- | --- | --- |
| −1.0〜−0.6 | 14% | 14% / 3% |
| −0.6〜−0.3 | 29〜30% | 28% / 23% |
| −0.3〜−0.1 | 40〜41% | 37% / 35% |
| −0.1〜+0.1 | 50% | 54% / 52% |
| +0.1〜+0.3 | 59% | 68% / 67% |
| +0.3〜+0.6 | 70〜71% | 81% / 79% |
| +0.6〜+1.0 | 84% | 98% / 100% |

- **偏りはほぼ無い**（平均 V と平均 z の差 ±0.07 以内）、**順序も正しい**（帯の逆転なし）
- **ただし控えめ**: z ≈ a + b·V の傾き b = **1.36〜1.41**（V=+0.4 で実際は +0.6 程度）。π'∝π·exp(η·Q) では Q の一律の縮みは
  η の倍率と同じなので、**η の実測で吸収済み**（η=30 は較正済みの価値なら η≈21 相当）
- **序盤はほぼ無情報**: 1〜20手目は |V| 平均 0.03・AUC 0.55〜0.56。中盤 0.68〜0.71、81手以降 0.76〜0.91。
  序盤の探索の Q は実質的に反則確率と詰みの判定だけで決まる。KL とは無関係の、序盤の信用割り当ての問題（上の「真実を見る価値ネット」の案）
- 自分と違う相手（対照ガントレットの15体、1500局）では V は平均ほぼ 0（−0.04〜+0.08）のまま、実際の z は相手により −0.15〜+0.76。
  V は相手を知らない自己対局の値なので想定どおりで、候補手どうしの差しか使わない探索には効かない
- **検出できていないこと**: KL の項が候補手ごとの順位を狂わせているか。自己対局では自分の KL と相手の KL が平均で打ち消し合うので、
  平均の偏りには出ない。学習ログにも KL の大きさは記録していない

**判断**: 勝敗だけの価値ヘッドは**優先度を下げる**（作り直しても縮みが取れる程度の見込みで、縮みは η で吸収済み）。
作るなら次に学習を回すときのついで（補助ヘッドを1本足して幹への勾配を止める）にし、そのとき**学習ログに KL の大きさも出す**。
価値ヘッドの強化としては序盤の弱さ（V_真実 の案）のほうが本筋。

### 案: 真実を見る価値ネットをベースラインにする（序盤の信用割り当て）

**問題**: 今の設定（集めた直後に1回更新 = π/μ ≈ 1）では v-trace の目標は実質モンテカルロで、
各手のアドバンテージは `最終結果 − V_観測(手を選ぶ前)` になる。1局の全部の手が同じ ±1 を
浴び、手ごとの差はベースラインだけから生まれる。序盤ほど終局が遠く、隠れた配置の運による
分散も大きいので、序盤の手の信号が薄い。逆向きカリキュラム（4b）は終盤・中盤から効くが、
序盤には最後に届く。

**当初の案（採らない）**: 中盤（駒がぶつかり始めて10手後など）で、真の盤面と残り反則数から
優劣を判定する手書きの審判で打ち切り、その判定を報酬にする。採らない理由:
- 序盤の方策が審判の物差し（駒得・反則数）の最大化へ育つ。4節で駒得を報酬に混ぜないと
  決めた理由の再来で、手書きの「有利」が勝率と噛み合わない実例もある（駒得 +340点/50局で
  勝率不変、評価項10件が勝率に変換されず）。R-NaD の収束先も打ち切った代わりのゲームの均衡になる
- 真の盤面には「誰が何を知っているか」が無い。ついたて将棋の序盤の価値の多くは情報
  （駒の隠し方・探り・玉位置を掴ませないこと）にあり、それを数えない審判は情報のための手を
  過小評価させる

**採る形**: 真実を見る価値ネット V_真実 を学習し、報酬ではなくアドバンテージのベースラインに使う。

```
s(t) = 最終結果 − V_真実(t の局面)     （今は V_観測(t)）
```

- 入力: 真の盤面＋**両者の観測履歴**＋残り反則数（= `StartState` と同じ、局面の完全な状態。
  両者の観測履歴を入れるので情報面の優劣も入力に含まれる）。教師は実際の勝敗
- 手は観測だけから選ばれるので、隠れた状態に依存するベースラインでも期待値ではゼロの項 =
  **不偏**。報酬は勝敗のまま
- 隠れた配置の運による分散を差し引けるので、序盤の雑音が減る
- 学習時だけ使い、推論（方策ヘッド）には入らない（非対称 actor-critic）。公平性の構造は不変
- 足りなければ、V_真実 で中盤に打ち切ってブートストラップする（v-trace の c < 1 や打ち切り点）。
  序盤の信号は最も強くなるが、V_真実 が未熟なうちは偏りが入るので、**ベースラインだけ → 打ち切り**の順で試す

**2026-10-13 追記: 中盤では効かない見込み**。指し継ぎ実験のひっくり返り率から、終局21手以上前では
完璧な V_真実 でも勝敗の分散の2〜4%しか説明できない（「中盤の信号の薄さと、ついたて将棋向けの学習の改善案」の節）。
下の測定は不要で、優先度は補助ヘッド（真実の盤面の予測）より下げる。

**先に測ること**（当初の計画）: arena-records（4,800局）で V_真実 だけを教師ありで学習し、手数ごとに
最終結果の予測精度（対数損失・AUC）を測る。`records.rs` の再生と `RecordDataset` を流用できる。
- 30手目でも十分当たる → 序盤で勝敗がかなり決まっている。ベースラインが序盤に強く効く見込み
- 30手目でほぼ当たらない → 序盤はまだ勝敗に効いていない。序盤より終盤・中盤を優先する判断材料
- 対照として同じ手数の V_観測（観測だけの価値）も測り、差 = ベースラインで削れる分散の目安にする

### 案: 報酬を変えたスタイル特化モデル（入玉特化から）

**狙い**: 報酬に戦法のボーナスを足して、特徴を持つモデルを作る。用途は2つで、両方を1本の系統で賄う。
- **本命を強くする練習相手（リーグ）**: 本命を「自分自身＋スタイル特化モデルの混合」と対戦させ、
  特定の戦法への穴を塞ぐ。入玉は相手に玉の位置を掴ませにくく、ついたて将棋では実戦的な戦法
  （quest_20260731 のレビューにも「今入玉を目指すと相手はこちらの王様の位置を見つけられない」）。
  自己対局だけでは試されにくい戦法ほど、練習相手としての価値が高い
- **人間向けの個性ある bot**: サイトで選べる相手など。こちらはある程度の強さも要る

**前提**: 入玉は今の自己対局ではあまり起きていない（ユーザーの感覚的な予想。未計測）。
`referee.rs` に入玉宣言の裁定は無く、終局は詰み・ステイルメイト・反則負け・200手の引き分け（`max_plies`）だけ。

**報酬の形**:

```
報酬 = 勝敗(±1) + λ(t) · 入玉ボーナス
```

- 入玉だけを報酬にしない。勝敗を無視して玉を突進させ、詰まされるモデルになる。
  **勝敗の報酬は最初から残す**（詰みを無視する癖と、入玉を過大に見る価値ネットを育てないため）
- 入玉の定義（敵陣3段目以内に到達した時点で1回だけか、終局時にいれば付けるか）で挙動が変わる。最初に決める
- R-NaD はゼロ和2人ゲームが前提で、片側だけにボーナスを足すと収束保証が外れる。選択肢:
  - ゼロ和のまま足す（入玉した側 +λ・された側 −λ）。相手も入玉の止め方を覚えるので、
    できるのは「入玉を巡る攻防が強いモデル」
  - 本命を固定し、その相手への最善応答として学習する（1人用 RL になり理屈がきれい。
    `rl/env.rs` の評価モードを NN の相手にも広げる）
  - 両側ともボーナス付きの自己対局（動くと思うが保証なし）
- 本命（M2b 以降の重み）から微調整すると安い。π_reg を本命に固定すれば、η が
  「本命からどこまで個性を出してよいか」のつまみになる

**λ のアニーリング（発見 → 使いどころの判断）**: 入玉は隠れた敵陣を抜けて玉を6段ほど運ぶ長い手順で、
サンプリングした方策が偶然やり切ることはまずない。そのため勝敗の報酬が「入玉すると勝てるか」を
評価する機会自体がない。λ を大きく始めて入玉を安定して実行できるようにし（技術の獲得）、
λ を下げて使いどころを勝敗に判断させる。
- λ を変えるのは正則化方策の差し替え（`EntropySchedule` の区切り）に合わせる。各区間は
  「固定したゲームで収束させる」前提なので、区間の途中で報酬を動かさない
- λ を下げると、勝敗で得でなければ入玉を捨てる（自己対局では相手も止め方を覚えるのでなおさら）。
  本命にとっては正しい判断で、発見の段階は無駄にならない
- **同じ学習を途中で分岐させる**: λ が高い段階の重みを練習相手に、λ に下限（例 0.3）を残して
  止めたものを個性 bot に、λ を下げ切った先を本命にする
- 入玉は引き分けに流れやすい（入玉宣言が無く、勝ち切れなければ200手で報酬0）。λ を下げた段階で
  「入玉して寄せる」まで学ばないと入玉の価値は勝敗から見てゼロに近く、捨てられやすい。
  入玉した局の終局理由の内訳を監視する
- 報酬を変えずに発見を助ける手段として、逆向きカリキュラム（4b）の開始点に「玉が中段まで出ている
  局面」を混ぜる方法もある。ただ記録に入玉が少なければ開始点が集まらないので、
  **アニーリングで作った入玉局を開始点に再利用する**組み合わせが現実的

**確かめ方**:
1. 入玉の頻度を数える: 現在の R-NaD の自己対局と v14 の記録で、入玉率と入玉した局の勝率を比べる。
   稀なら「発見が律速」の前提が立つ
2. 同じ計算量で3つの arm を比べる。A: 勝敗のみ / B: 固定の小さい λ / C: λ のアニーリング（大 → 小）。
   見るのは入玉率・入玉局の勝率と終局理由・錨（または v14）への勝率。
   C が A より錨に強ければ「発見を先にすると学習が早い」、C が入玉を保ったまま A と同等の強さなら
   個性 bot の候補

**1. の計測結果（2026-09-28）**: 入玉 = 玉が敵陣3段目以内に一度でも入った局（対局記録の真実 `end.moves` から
玉の位置を追って数えた）。

| --- | --- | --- | --- | --- |

玉の1局の最大前進段数（初期位置 = 0、敵陣1段目 = 8）:

| 記録 | 自陣から出ない（0〜2段） | 中段（3〜5段） | うち5段（敵陣の一歩手前） | 敵陣（6段以上） |

  来る玉も 1〜2% しかない = **「発見が律速」の前提は立つ**。λ のアニーリングで入玉を安定して
  実行させる段階が要る
- 入玉した局はほぼ全部が反則負けで終わっていて、詰みで終わる局はほとんど無い（入玉した玉は
  詰まされにくい一方、入玉した側も勝ち切るには相手の反則を待つ形）。件数が少なく勝率は判断できない
- R-NaD の2,000更新で入玉率がわずかに上がっている（0.3% → 1.0%、玉が中段まで出る割合も 16.7% → 23.3%）
  が、件数が少なくノイズの範囲

**arm C（初入玉だけにボーナス、λ 1.0 → 0.5 → 0.25 → 0、手元で 3,000更新 = 約19万局、2026-09-28）**:

### 案: 防御特化（玉の周りの固め）モデル（2026-09-28 ユーザー提案から）

**狙い**: ついたて将棋には「自玉の周りに駒を打ちまくる」戦法がある。打った駒で玉の周りのマスを
埋めると、(a) 相手がそこへ駒を打とうとして反則する（打ちマスの反則を誘う）、(b) 自分の打ちが
反則すれば相手の駒がそこにいると分かり（検知）、取りに行ける。この戦法を使う練習相手を作り、
**本命がこの戦法に勝ち切れるように**リーグで鍛える（入玉案と同じ「本命を強くする練習相手」の用途）。

**最初に考えた「負けた局の手数が短いほど追加ペナルティ」は採らない**（2026-09-28 の議論）:
- 「遅く負けろ」は手段を指定しないので、逃げる・攻めを控えて200手の引き分けを狙う・反則を減らす
  など他の方法でも満たせる。玉の周りに打つ戦法に行き着くかは運次第
- この戦法の勝ち筋は相手の反則負けで、終局の大半も反則負け。詰み負けの手数を見る報酬とは噛み合わない

**報酬の形**: 入玉案と同じく、戦法そのものに付ける。

```
報酬 = 勝敗(±1) + λ · 対局を通した玉の周りの占有率の平均
```

- **占有率** = 自玉から距離 r 以内の盤上のマス（玉のマスを除く）のうち、玉以外の自駒がいる割合
  （`rl::env::guard_fraction`。r=1 は8近傍、r=2 は24マス）。盤端の玉はマス数が減るので割合で数える。
  初期局面は r=1 で 0.4（5九玉の盤上の近傍5マスに金2枚）
- **利き（`king_hole_w`）ではなく占有**で数える。利きを通すだけで減る指標だと、打って埋める戦法を
  名指しできない
- **打った回数に報酬を付けない**。打っては離れる手で稼げてしまうので、状態（占有）を見る
- **対局の平均**にする（開始局面と受理手の直後ごとに標本を取る。相手の手の後も数える）。
  合計にすると長い対局ほど得になり、200手の引き分けへ逃げる動機になる
- **ポテンシャル型の整形にはしない**。最適方策を変えないことが保証される形なので、スタイルを作れない
- **勝敗の報酬は残す**。練習相手として価値があるのは「強い固め」で、勝敗が無いとただ打ちまくって
  反則負けする相手になる（自分の打ち反則は10回負けに数えられる。打ちすぎとの釣り合いは勝敗に任せる）
- 入玉と違い、玉の周りに打つ手は今の方策でも普通に出る（ランダム方策でも8近傍の占有率は平均 0.45）
  ので、**発見が律速ではない**。λ のアニーリングは要らず、固定の λ から始めてよい

**学習の構造**: 入玉案の選択肢のうち、**本命を固定して、その相手への最善応答として学習する**のが素直
（`VecEnv(opponent="rl_policy:<本命の重み>", guard_bonus=λ)`。報酬は学習側の列だけを使う）。
自己対局に λ を入れると両者ともボーナス付きになり、零和でなくなる（R-NaD の収束保証が外れる）。
できた固めのモデルを本命の対戦相手の混合（自分自身＋固めのモデル）に入れる。

**環境側の実装（2026-09-28）**:
- `EnvGame::style()`（`rl::env::StyleStats`）が1局ぶんを集計する。学習側・相手側の両方の手が
  `EnvGame::play` を通るので、評価モードの相手の手も数える
- `VecEnv(..., guard_bonus=λ, guard_radius=1|2)` で終局の報酬に λ × 占有率の平均を**両者それぞれ**
  足す（既定 λ=0 で従来と同一）
- `pop_finished()` に監視用の集計を足した（[先手, 後手]）: `guard_r1` / `guard_r2`（占有率の平均）、
  `near_drops`（自玉から距離2以内への打ち）、`near_drop_fouls`（同じ範囲への打ちの反則のうち、打った
  マスに相手の駒がいたもの＝相手の駒の検知。王手を防がない打ち・打ち歩詰めのようにマスが空いていた
  反則は、行動マスクでは落とせないが検知ではないので含めない。環境は真実の盤面で判定する）、`near_captures`（同じ範囲での駒取り）
- 検査: `cargo test rl::env`（初期局面の値・標本の数え方・値域・評価モード）と
  `rl-env/smoke.py` の `check_guard_bonus`（同じ行動列で λ=0 と λ=0.5 を回し、報酬の差 = λ × 集計）

**確かめ方**:
1. λ を 0 / 0.5 / 1.0 程度で振り、`guard_r1`・`near_drops`・`near_drop_fouls`・相手の反則数・
   本命への勝率と終局理由を見る。**狙いどおりなら占有率と相手の反則数が上がり、勝率は大きく
   落ちない**。占有率だけ上がって勝率が崩れるなら λ が大きすぎる（ただ固めるだけのモデル）
2. 本命をこのモデルと当て、勝率が低ければ（穴が実在すれば）混合に入れて本命を鍛える。

### 案: 速攻特化（決着の速さのボーナス）モデル（2026-10-03 ユーザー提案から）

**狙い**: 防御特化の次のスタイル特化。**決着までの手数が短いほど勝ちの報酬を上げる**ことで、
早く寄せに行く（王手・駒を前に出す・反則を誘う圧力を早く掛ける）モデルを作る。用途は他の特化と同じで、
本命のリーグの練習相手（速攻を受け切れるか）と、人間向けの個性ある bot。

**報酬の形**:

```
報酬 = 勝敗(±1) + 勝った側に λ · 速さ
速さ = max(0, (H − 手数) / H)      （手数 = 受理手の数。反則は数えない）
```

- **勝った側にだけ付ける**（`speed_sum="own"`、既定）。負けた側の報酬は勝敗のまま。
  零和にする（負けた側から同じ額を引く、`speed_sum="zero"`）と、負けそうな側に「手数を延ばせ」という
  動機が生まれる。これは防御特化の議論で採らなかった「遅く負けろ」そのもので、手段を指定せず
  200手の引き分け狙いや攻めの手控えでも満たせてしまう。自己対局では学習側が両方の役を持つので、
  零和だと速攻と遅延が打ち消し合う。零和の選択肢は R-NaD の収束保証を保ちたいときのために残した
- **入玉・固めと違い、特定の戦法を名指ししない**。速さ自体が狙いのスタイルなので、勝ち方（詰み・
  相手の反則負け）は区別しない。相手の反則を早く誘う圧力も速攻の一部とみなす（ついたて将棋の終局の
  多くは反則負け）。詰みだけに絞りたくなったら、終局理由で絞るオプションを足す
- **勝敗の報酬は残す**。速さのボーナスは勝ったときしか貰えないので、無理攻めで負けると 0 も取れない =
  無謀な突撃は勝敗の側で抑えられる
- **引き分け（`max_plies`）には付けない**。決着していない
- 線形で、手数 H 以上は 0（負にしない）。既定の H は `MAX_PLIES`（200）。本線の自己対局の手数は平均 70〜90手
  なので、H=200 だと 50手の勝ち 0.75・100手の勝ち 0.5 で、差は λ の 1/4 程度。差を強めたいなら H を
  縮める（H=120 なら 50手 0.58・100手 0.17）
- **λ の大きさ**: 入玉特化では λ=1 が勝敗 ±1 と1局のばらつきに埋もれて動かず、λ=4 で初めて動いた。ただ入玉は
  発見が律速だったのに対し、手数は全ての勝ち局で自然にばらつくので信号は最初から届く。λ=1〜2 から始めて、
  勝ち局の平均手数が動かなければ上げる
- 価値の頭が tanh なので、報酬が ±1 を超える（λ=2 なら最大 +3）と入玉特化と同じく loss_v が大きくなる。
  報酬を (1 + λ) で割って ±1 に収めるかは学習側（tsuitate-nn）で決める
- **ポテンシャル型の整形にはしない**（防御特化と同じ理由。最適方策を変えないのでスタイルを作れない）

**学習の構造**: 入玉特化の 3,000 → 4,000更新と同じく、本線 55,000更新（`checkpoint_55000.pt`）から初期化して
自己対局＋リーグ（凍結版 rl_v15〜v24 との PFSP）で回す想定。`speed_sum="own"` は非零和なので、
入玉特化の `--nyugyoku-sum own` と同じく収束保証は外れる。

**環境側の実装（2026-10-03）**:
- `rl::env::Outcome::speed` / `speed_bonus` と `SpeedSum`（`own` / `zero`）。検査は
  `cargo test rl::env`（`速攻ボーナスは勝った側に速さに比例して付く`）
- `VecEnv(..., speed_bonus=λ, speed_horizon=H, speed_sum="own"|"zero")`（既定 λ=0 で従来と同一）。
  `guard_bonus` と併用すると両方が足される
- 監視は `pop_finished()` の既存の `winner` / `plies` / `reason` / `fouls` で足りるので、集計は足していない
- `rl-env/smoke.py` の `check_speed_bonus`（同じ行動列で λ=0 と own / zero を回し、報酬の差が手数から
  計算した値と一致すること・zero が零和であること・不正な指定を拒否すること）

**確かめ方**:
1. λ を 1 / 2 程度で振り、**勝ち局の平均手数**・詰みで終わる局の割合・自分の反則/局（無理攻めで
   増えていないか）・錨（本線 55,000更新 = rl_v24）への勝率を見る。狙いどおりなら勝ち局の手数が縮み、
   勝率は大きく落ちない。手数だけ縮んで勝率が崩れるなら λ が大きすぎる
2. CI の全版ガントレットで本線とペア比較し（入玉特化と同じ表）、勝ち局の手数の分布を本線と並べる。
   本命をこのモデルと当て、勝率が低ければ（速攻への穴が実在すれば）リーグの混合に入れる
