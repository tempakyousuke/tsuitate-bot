# 既存のモデルを相手にゼロから学習する: 報酬の整形とハンデの梯子（2026-11-10）

> 種類: 設計/記録。状態: **道具の実装（どれも既定オフ）と、CPU のパイロット**（2026-11-10。4節）、**駒得に足す信号の比較**
> （2026-11-11。8節）、**エンコーダ v4 の入力の比較**（2026-11-11。8.7節）。GPU の本番規模の比較は未実施。
> 本線（MMD の自己対局）は変えていない。学習側のコードは tsuitate-nn のブランチ `claude/vigilant-rubin-dyxzy2`、
> 環境側は tsuitate-bot の同名のブランチ。計測はクラウドの CPU 4コア（GPU なし）。

ある程度モデルが揃ったので、**既存のモデルを対戦相手にして乱数初期化から学習し、早くその相手に勝てるようになる学習方法**を探す。
ねらいは2つ（2026-11-10 ユーザー提案）:

1. 最新のモデルにゼロから当たっても勝てないのが当たり前なので、**勝敗以外の報酬**（駒得・負けるまでの手数の長さなど）で
   学習を立ち上げる
2. 勝ちが出てくるところまで行けば、**勝利報酬以外に学習に役立つ指標**が見つかるかもしれない（本線にも持ち帰れる）

## 要点

1. **勝敗だけの報酬では、1局も勝てない間は学ぶ信号が実質的に無い**（2節・4.2節）。全局の結果が −1 なので価値が −1 に
   張り付き、アドバンテージが 0 になる。乱数初期化から rl_mmdopen_v15 に当てた対照は、約 28,900局のあいだ勝率 0.0〜0.1%
   （偶然の勝ちが 2,000局に1局）のままで、反則も手数も動かなかった
2. **駒得の報酬を足した腕の1本が、約 19,000局で離陸して 38,400局で最新版に五分になった**（4.2節。32ch×3 のネット・
   CPU 約1時間）。学習中の勝率は 0.0% → 0.8% → 2.0% → 27% → 38% → 51%、**アリーナ（Rust・凍結版そのもの）でも
   rl_mmdopen_v15 に 53.0% ± 9.8**（4.3節）。**ただし同じ設定の 4 seed のうち離陸したのはこの1本だけ**（ほかは
   2.2万〜5.1万局で 0〜1%）。駒を取ることはどの seed も覚えるが、詰みまでつながるかは運に左右される。
   **この「4本中1本」は、整形の上限を 0.5 にしていたことの影響を受けている**（下の 10。8.3節）
3. **勝ちが出てから整形を 0 へ下げても、勝敗だけの報酬で五分を保った**（`--shape-decay`。アリーナ 53.0% ± 9.8）。
   「整形で最初の勝ちを作り、その後は勝敗だけに戻す」は成り立つ
4. **強くなったのではなく、その相手への特化**（4.3・4.4節）: 同じ系列（mmdopen・mmdhand）には 25〜33%、
   別系統（rl_mmd_v4・rl_deduce_v10・rl_v30）には 0〜2%。勝ち方は**決まった1本の手順**（見えない △5五角から、
   ▲7六歩で開いた筋で 8八の角をただ取りして詰ます）で、相手の手を 1割乱数手にするだけで勝率が 33% → 8% に落ちる。
   rl_mmdopen_v15 がほぼ決定的に指すこと（序盤の固まり）の裏返しで、**ゼロからの搾取役は本線の穴を安く見つける診断になる**
5. **ほかの腕は、1本ずつの試行では離陸しなかった**（4.2節）: 負けるまでの長さ（3万局）、駒得 ＋ 反則 ＋ 長さ（2.6万局）、
   駒得のポテンシャル型（2.6万局）、相手の手の 2割を乱数手にした駒得（2.6万局。ゆっくり伸びてはいる）。離陸の前の勝ちは
   どれも対照の 2〜10倍あるが、駒得の seed 違いのばらつき（20倍）の内で、**腕の優劣はこの本数では言えない**。
   はっきり言えるのは2つ: **反則のペナルティだけは逆効果**（「反則する前に早く詰まされる」ほうが得になり、反則が
   8.4 → 9.8回に増えた）、**ハンデの梯子（勝敗だけ）は最下段の引き分けに配分が張り付いた**
6. **勝ちを先取りしていた量**（5節）: 途中の時点（20〜40手）で勝ち局と負け局を分けていたのは、駒得・駒割りと
   相手玉の周りへの利き。反則は終局時にしか差が出ない。次に報酬として試す候補は相手玉の周りへの利きと王手
   （**試した結果は下の 11**）
7. **道具**（3節。どれも既定オフ）: 局の信号（17 個。8節で 3つ足した）と重みを学習側で振る報酬の整形（`--shape`。plain / potential）、
   負けるまでの長さ（`--lose-len`）、ハンデつきの相手 `<名前>@<ε>`、相手を固定した PPO 型の学習（`--algo mmd --league`）と
   アドバンテージの正規化（`--mmd-adv-norm`）、ハンデの梯子の ε50、勝ち局と負け局を分ける信号の表
8. **`--league-device gpu` の v-trace の不具合を直した**（3.5節）。相手の手番を記録しない局で、終局の報酬が各局の最後の
   学習側の手番にしか届いていなかった（`rl-learning-speed.md` 9.8 で見つけて未修正だったもの）。**搾取役の実験
   （`rl-deepnash-design.md`「rl_v29branch_v1 の搾取役」）の「ほぼ伸びない」は、この不具合で説明できる可能性がある**
9. **GPU での手順は 6節**: 多くの seed での追試（離陸の時期の分布を腕ごとに測る）、相手を増やして乱数手を混ぜた学習
   （一般の強さへ）、搾取役のやり直し
10. **整形の上限は 1.0 にする**（8.3節。2026-11-11）。上限 0.5 では駒得が +25 点で頭打ちになり、200更新ごろには 2〜6割の局が
    上限に張り付いていた。駒得だけの腕は、上限 0.5 で 4本中1本・上限 1.0 で 6本中2本（打ち切り 25,600局）
11. **駒得に「相手玉の周りへの利き」と「相手の反則」を足すと、離陸が増えて速くなった**（8.3節）: 両方を足した腕は **6本中6本**が
    1.2万〜2.3万局で離陸し、片方ずつ足した腕は 6本中5本ずつ（駒得だけは 6本中2本・1.7万〜1.8万局）。王手は 6本中4本。
    利きか相手の反則を入れた 4腕を合わせて 24本中21本 対 6本中2本（Fisher の片側 p = 0.02）。離陸はアリーナでも確認した
    （28本中27本が rl_mmdopen_v15 に 10〜90%）。**一手詰め・詰めろの信号と、王手を外す報酬は効かなかった**（1本ずつ）
12. **駒得は無くても離陸する**（8.3節）: 利き ＋ 相手の反則だけで 6本中5本、離陸までの局数の中央値は 1.36万局でいちばん少ない
    （駒得つきの組み合わせ 1.50万局）。**ゼロからの方策に足りなかったのは、駒を取ることではなく玉へ向かうこと**だった。
    ただし駒得なしで片方だけ（利きだけ・相手の反則だけ）は 4本中1本で、その1本も続かなかった（2本ずつの試行）
13. **勝ち方は「詰み」と「遠くからの王手で相手を反則負けに追い込む」の2通りで、報酬に入れたもので決まる**（8.4節）:
    駒得と利きの両方があると詰み、どちらかが欠けると相手の反則負けに寄る。離陸の直後の勝率は駒得つきの組み合わせのほうが高い（アリーナの
    rl_mmdopen_v15 に平均 32% 対 17%。いちばん高い 1本は 17,600局で 58.3% ± 12.5）。反則負けの筋のいちばん高い 1本は
    14,400局で 66.7% ± 11.9（勝った 40局のうち 39局が相手の反則負け。相手の反則は 1局 8.4回、うち王手中 7.0回）。
    **本線の最新版は、見えない駒からの王手を外せずに反則を重ねる**。どちらの勝ち方も学習の相手への特化（別系統には 0〜8%）
14. **いちばん早く勝ち越した 1本は、ゼロから 19,200局（CPU 約 36分）でアリーナの rl_mmdopen_v15 に 84.5% ± 5.0**（8.4節。
    駒得＋王手の腕の seed 6。60局の別の計測では 90.0% ± 7.6）。離陸から 2,000局で勝率が 3% → 88% に立ち上がった。
    先手・後手それぞれ決まった1本の手順（角のただ取りから、打った角の王手と馬で玉を追い回して銀打ちで詰ます）で、
    rl_mmdhand_v1 に 55%・rl_mmdopen_v14 に 43%・rl_mmd_v4 に 23%・rl_v30 に 0%。1本だけの結果
15. **エンコーダ v4 の入力（玉の移動で反則したマス。`--king-foul-planes`）は、離陸を早くしなかった**（8.7節。2026-11-11）:
    駒得＋利き＋相手の反則の腕で v2・v4 とも 8本中7本が離陸、離陸までの局数は打ち切り込みの平均 1.67万局 対 1.50万局
    （片側 p = 0.27）。駒得だけの腕は 6本中2本 対 6本中1本。**最初の 6 seed では 1.61万局 対 1.30万局（p = 0.09）と
    差があるように見え、seed を 2つ足したら縮んだ**。ネットはこの入力をまだ読んでいない: 前に玉で反則したマスへの
    繰り返しは v2 と同じ割合（玉の反則の 22〜26%）で、プレーンを 0 にしても方策はほとんど変わらない（全変動距離 0.02〜0.07。
    確定事実の 5枚は 0.22〜0.32）。この入力で減らせる反則はもともと 1局に 1回ほど。本線で効くかどうかはこの実験からは言えない

## 1. これまでの方針との関係

- `rl-deepnash-design.md` 4節の方針は「報酬は勝敗だけ。駒得を混ぜると頓死を軽く罰する方向へ働く。整形が要るなら
  最適方策を変えないポテンシャル型だけ」。**本線の自己対局はこのまま**で、ここは「相手を固定・ゼロから」という別の実験系
- 整形は2つの形を選べるようにした。**potential**（終局で累計を差し戻す）は 4節の方針どおり最適方策を変えない。
  **plain**（差し戻さない）は目的そのものを変えるので、勝ちが出てきたら倍率を 0 へ下げる（`--shape-decay`）前提の足場
- 相手を固定した学習は**一人用の RL**（相手は環境の一部）で、零和の2人ゲームの均衡を求める R-NaD・MMD の枠の外。
  できるのは「その相手への最善応答」に近い方策で、ほかの相手に強い保証は無い（特化しうる）。本線へ持ち帰るのは
  方策そのものではなく「どの信号・どの手順が学習を速くするか」の知見

## 2. 勝敗だけでは信号が無い

乱数初期化の方策（マスクの中で一様）を rl_mmdopen_v15 と対戦させると、64局で 0勝。負け方は反則10回が約8割、
詰みが約2割（1局の反則 8.7回、うち7回前後が王手を受けている手番）。

勝敗だけの報酬（＝全局 −1）で PPO 型の学習器を回すと（パイロット0、`out_rnad/pilot0/fx_base`）:

| 更新 | 価値の損失 | A の絶対値の平均 | 勾配ノルム（中央値） | 1局の反則 | 手数/側 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0.084 | 0.064 | 0.36 | 8.7 | 22.7 |
| 21 | 0.000 | 0.0003 | 0.0003 | 8.8 | 22.5 |
| 81 | 0.000 | 0.00015 | 0.00008 | 8.7 | 22.6 |

価値が「どの局面も −1」を20更新で覚え、以後は A = G − V ≈ 0 で方策の勾配が消える。期待値でも
E[∇log π(a) × (−1)] = 0 なので、基準線を使わない方策勾配でも情報は無い（雑音だけが残る）。
反則負けと詰みを区別する理由も、長く粘る理由も、勝敗だけの報酬には無い。

厳密には、乱数に近い方策でも約 0.05% は勝つ（2,000局に1局。4.2節の `base`）。その1局が唯一の信号で、
アドバンテージを正規化した設定（3.4節）でも約 28,900局のあいだ立ち上がらなかった。

## 3. 道具

### 3.1 局の信号（`src/rl/signals.rs`・`VecEnv.signals()`）

env は各側の信号 `[局, 2, 17]` をそのまま出すだけで、**どれにどんな重みを付けて報酬にするかは学習側の引数で振る**。
信号を1つ足すのは `signals.rs` の名前と計算だけ。

| 種類 | 名前 | 中身 |
| --- | --- | --- |
| 累積 | `moves` / `fouls` / `fouls_in_check` | 受理された手 / 反則 / 王手を受けている手番での反則 |
| 累積 | `captures` / `capture_value` | 取った駒の数 / 価値の合計（歩 = 1。成駒は盤上と持ち駒の価値の平均 = `strategy::exchange_value` と同じ式） |
| 累積 | `promotions` / `checks` / `drops` | 成った回数 / かけた王手 / 打った回数 |
| 累積 | `evasions` | 王手を受けている手番で受理された手（王手を外した回数。2026-11-11 追加） |
| 状態 | `material` / `hand_value` | 自分の駒の価値の合計（盤上＋持ち駒）/ 持ち駒の価値 |
| 状態 | `king_attack` | 相手玉のマスと8近傍への、自駒の利きの数の合計 |
| 状態 | `king_guard` / `king_advance` / `camp_pieces` | 自玉の8近傍の自駒の割合 / 玉の前進段数 / 敵陣の自駒の数 |
| 状態 | `king_escape` / `mate_threat` | 自玉の8近傍のうち、自駒がいなくて相手の利きも無いマスの数 / 相手玉に一手詰めがある（手番なら一手詰め、手番でなければ打ちの詰めろ）なら 1（どちらも 2026-11-11 追加。8.2節） |

真実の盤面を読む信号がある（`king_attack` は相手玉の位置を使う）。報酬と監視は学習時にしか使わないので情報は漏れないが、
**方策の入力には使わない**（`VecEnv.truth()` と同じ扱い）。

### 3.2 報酬の整形（tsuitate-nn の `rnad/shaping.py`、`train_rnad.py --shape`）

    Φ_p(s)  = Σ_k ( own_k × 信号[p, k] + opp_k × 信号[相手, k] )          （p から見た形勢の目安）
    Φc_p(s) = clip(Φ_p(s) − Φ_p(初期局面), −cap, cap) × 倍率
    r_p(s → s') = Φc_p(s') − Φc_p(s)

- 重みは `--shape 'd_capture_value=0.02,fouls=-0.05'` のように書く。鍵は信号の名前（自分）・`opp_<名前>`（相手）・
  `d_<名前>`（自分 − 相手。零和を保つ）
- **plain**（既定）: 差分をそのまま足す。1局の合計は Φc(終局)。目的が変わる
- **potential**: 終局の Φc を 0 とみなす（終局の遷移で累計を差し戻す）。1局の合計は必ず 0 で、最適方策は変わらない
  （Ng ら 1999）。価値の頭に「Φ が形勢」という事前知識を与えるのと同じで、価値が育つまでの信用の割り当てに効く。
  **1局も勝てない間は、potential の信号は過渡的なものだけ**（どの手を選んでも合計が −1 なので、価値が Φ を覚えると
  A が 0 に戻る。パイロットでも駒得は一度伸びてから戻った。4.2節の `matpot`）
- `--shape-cap`: 1局の Φ の変化の上限（勝敗 1 に対する整形の大きさの上限）。`--shape-decay 始め:終わり`: 倍率を
  更新回数で 1 → 0 へ下げる
- **負けるまでの長さ** `--lose-len 'λ[:H]'`: 負けた側の終局の報酬に λ × min(手数, H) / H。λ < 1 なので
  「負け < 引き分け < 勝ち」は保つ。目的は変わる（plain と同じ扱いで倍率が掛かる）
- 1局の報酬は ±(1 + cap + λ) に収まるので、この値で割って価値の頭（tanh）の範囲に収める（`reward_scale`。
  学習の全体で固定。MMD は磁石の温度と近い方策への KL の係数も同じ倍率で縮める）

### 3.3 ハンデつきの相手と、進み具合の物差し

- **`<名前>@<ε>`**（`VecEnv` の相手の名前・`--league`）: 相手の手番ごとに確率 ε で、相手の戦略の手の代わりに
  **真実の盤面の合法手から一様に選んだ手**を指させる。ε = 1 は全部が乱数手、0 が本物。雑音の手は合法手なので
  反則にはならない（相手の反則負けで勝たせない。弱さは悪手として出る）
- **梯子**: `--league X@1,X@0.6,X@0.3,X@0.1,X --league-weighting even`。勝率が五分前後の段に多く当てる（PFSP の even）ので、
  強くなるにつれて当たる段が自然に上がる。勝敗だけの報酬でも最下段には勝ち・引き分けが出るので信号がある
- **ε50**（tsuitate-nn の `rnad/ladder_eval.py`）: 書き出しを各段と対戦させ、得点が 0.5 になる ε を補間で出す。
  小さいほど強く、本物に五分なら 0。**勝ちが出る前から、同じ相手への近さを1つの数で追える**。整形の腕は
  それぞれ別の量を最大化するので、駒得や手数で比べると循環する。腕どうしは ε50 と本物への得点で比べる
- **パイロットで分かった注意**: 最下段を ε = 1（全部が乱数手）にすると引き分けが増え、even の配分がそこに張り付いた（4.2節）。
  1体の決定的な相手に特化した方策は「相手を弱めるほど勝てない」ので、ε50 は特化の検出にはなるが強さの物差しにはならない（4.4節）

### 3.4 学習器

- **`--algo mmd` で `--league`（相手を固定した局）を使えるようにした**。相手を固定した学習は一人用の RL なので、
  磁石は一様（`--mmd-magnet uniform` = エントロピーの正則化）にし、温度は小さく置く（0.01）
- **`--mmd-adv-norm <下限>`**（既定 0 = しない）: その更新の A を max(std(A), 下限) で割る。1局も勝てない間は
  |A| が 0.005〜0.02 しかなく、本線の設定（1更新 4歩・正規化なし）では方策が動かなかった（パイロット0: 87更新で
  1更新の KL が 0.00001 未満、エントロピーも反則も初期値のまま）。正規化と `--mmd-steps 8 --mmd-epochs 2`（1更新 16歩）で
  1更新の KL が 0.01〜0.02 になり、信号を最大化し始める。本線（勝率が五分前後で |A| が 0.1〜0.3）には付けない
- R-NaD（既定の学習器）でも同じフラグで回る（`--league` ＋ `--shape`）
- 相手のネットをまとめて推論する経路（`--league-device gpu`）で、**入力の版が違う相手（v1 86枚・v2 91枚・v3 101枚）を
  混ぜられるようにした**（それまでは積み重ねで落ちた。いちばん広い版にそろえて積む）。ハンデつきの相手もこの経路で使える
  （`VecEnv.random_legal_actions`）

### 3.5 `--league-device gpu` の v-trace の修正

`collect` は相手のネットに指させる局（`--league-device gpu`）で相手の手番を無効な行として記録しない。`v_trace_scalars` は
無効な行で carry を 0 に戻していたので、**終局の報酬が各局の最後の学習側の手番にしか届いていなかった**
（`rl-learning-speed.md` 9.8 で確認済み・未修正だったもの）。無効な行では carry をそのまま通すようにした。

- 自己対局と `--league-device rust` の batch には局の途中の隙間が無く、後ろの埋め草では carry が初期値のままなので、
  値は変わらない（OpenSpiel の参照との一致 `tests/test_rnad.py`・既存のテスト一式が通る）
- 隙間のある batch が、隙間を詰めた batch とビット単位で同じ値になることを `tests/test_shaping.py`（S3）が検査する
- **影響を受けていた可能性のある過去の実験**（9.8 の一覧）: 55,050→60,000 のリーグ学習の半分の局、速攻特化の2回目、
  **搾取役の実験**（`--league-frac 1 --league-device gpu`、1,000更新で 0.488 → 0.506）。搾取役の「R-NaD は固定した相手への
  最善応答を学ぶ手法ではない」という見立ては、この不具合と切り分けられていない。**搾取役は直した版でやり直す価値がある**

### 3.6 見る道具

- 学習ログの `signals`: 勝ち局・負け局・引き分けごとに、終局時と途中（両者の受理手の合計が 20 / 40 / 60 に届いた時点）の
  信号の平均と標準偏差
- `rnad/signal_report.py <run>`: 更新の窓ごとの得点と主な信号（何が先に動くか）
- `rnad/signal_report.py <run> --split`: 信号ごとの「勝ち局の平均 / 負け局の平均 / 標準化した差 d」。終局時の値は詰み・
  反則負けそのものを映すので、**途中の時点の d が大きい信号**が「勝ちを先取りする量」の候補になる
- `rnad/ladder_eval.py <run> --opponent X`: ハンデの梯子の得点と ε50

- **`matdecay`（seed 1 を 300更新で分岐し、整形を 300→500更新で 0 へ）は、勝敗だけの報酬に戻した後も五分前後を保つ**:
  500更新以後 48.2% → 47.1% → 50.5% → 53.4%。**「整形で最初の勝ちを作り、勝ちが出たら勝敗だけに戻す」は成り立つ**。
  整形を下げると駒得は +20 → +13 に減り、勝率は下がらない（勝ちに要る分だけ取るようになる）
- **`len`（負けるまでの長さ）は 474更新（約3万局）で離陸しなかった**。離陸の前の勝ちは `base` の約5倍（0.26%）あり、
  201〜300更新で一度 0.6% まで上がって戻った。手数は伸びていない（片側 22〜27手）
- **`foul`（反則のペナルティだけ）は逆に動いた**: 反則が 8.4 → 9.8回に増えた（132更新で止めた）。全局が負けの間は
  「反則10回で負ける」より「反則が少ないうちに詰まされる」ほうが報酬が高く、**早く負ける方向の動機**になる。
  反則のペナルティは、負けの長さや駒得と組まないと単独では使えない
- **`all`（駒得 ＋ 反則 ＋ 長さ）は手数と駒得は伸びたが、400更新では離陸しなかった**（手数 27 → 42手、反則 8.7 → 7.2回、
  駒得 +25。勝率 0.1〜0.7%）
- **`matpot`（potential）は 400更新で離陸しなかった**（0.4% → 0.9% → 0.2% → 0.1%）。1局の整形の合計は 0 だが、
  価値が Φ を覚えるまでの過渡の信号で駒得は −2.6 → +11 まで動き、最初の 200更新の勝ちは plain の seed 2 より多い（0.6%）。
  その後は駒得も勝ちも戻った（価値が追いつくと信号が消える、という理屈どおりの動き）
- **`matnoise`（相手の手の 2割が乱数手）は 400更新で離陸しなかったが、ゆっくり伸び続けた**: 相手（ε = 0.2 の版）への勝率は
  0.0% → 0.1% → 0.3% → 0.4%、引き分けも 0 → 3 → 17 → 119局と増え、手数は 27 → 53手（片側）、反則は 9.4 → 8.2回。
  相手が決定的でないので「手順を1本覚える」近道が無く、粘る・駒を取るといった一般的な技術から入っている形。
  立ち上がりは遅いが、決まった手順への特化にはなりにくい（6節の実験 2 の目安）
- **`ladder`（勝敗だけ・ハンデの梯子）は最下段で止まった**: 全部が乱数手の段（ε = 1）への得点は 0.19 → 0.42 → 0.47 と
  上がったが、勝ちではなく引き分け（200手）が増えた結果で、上の段（ε = 0.6 以下）には 0〜0.09 のまま（153更新で止めた）。
  **PFSP の even は引き分けを 0.5 と数えるので、「引き分けばかりの段」を五分の相手とみなして配分の 93% を回し続ける**。
  梯子を使うなら、最下段を ε = 1 にしない・引き分けを負けと数えて配分する、のどちらかが要る（未実装）

### 4.4 勝ち方: 決まった1本の手順

400更新のアリーナの 100局（学習側は先後 50局ずつ）を棋譜で見ると:

- **学習側の最初の4手は先後とも全局同じ**（後手なら △2四歩 △2五歩〔取る〕△3四歩 △5五角）
- 相手（rl_mmdopen_v15）が先手の 50局のうち **46局で、相手の最初の6手が同じ**（▲2六歩 ▲2五歩 ▲5八飛 ▲7八銀 ▲7六歩 ▲7五歩）
- 勝ち筋: △5五角と出ておき、**▲7六歩で 5五〜8八の筋が開いた瞬間に △8八角と角をただで取る** → △9九角成（香も取る）→
  持ち駒を打って詰ます。相手からは 5五の角が見えない
- 100局のうち 17局は、ほかの局と**全手順が同じ**。勝った 21局の棋譜は 11種類（同じ40手の棋譜が最大4局）

つまり、ほぼ決定的に指す相手の決まった序盤に対して、勝てる手順を1本覚えた形。
ハンデの梯子で測ると、これが一般の強さでないことがはっきり出る（`mat` 500更新、各段64局）:

| 相手 | 本物（ε = 0） | ε = 0.1 | ε = 0.3 | ε = 0.6 | ε = 1（全部が乱数手） |
| --- | --- | --- | --- | --- | --- |
| 得点 | **0.328** | 0.078 | 0.000 | 0.000 | 0.023 |

**相手を弱くするほど勝てなくなる**（相手の手が 1割ずれるだけで 33% → 8%、乱数手だけの相手には反則 9.9回で負ける）。
ε50 は「相手を弱めれば得点が上がる」ことを前提にした物差しなので、特化した方策には使えない（一般の強さを育てる
学習の物差しとして使う）。

**本線への含意**: rl_mmdopen_v15 は「▲2六歩〜▲5八飛〜▲7八銀〜▲7六歩」の形で、見えない △5五角に 8八の角を
ただで取られる。自己対局では相手も同じ序盤しか指さないので、この筋を一度も見ていない（`rl-opening-diversity.md` の
序盤の固まりと同じ根）。**ゼロからの搾取役は、数万局・CPU 1時間で本線の穴を1つ見つける安い診断**になる。

## 5. 勝ち局と負け局を分ける信号（勝利報酬以外の手がかりの候補）

`signal_report.py --split` で、信号ごとに「勝ち局の平均 / 負け局の平均 / d」を出す（d = 平均の差 ÷ 合わせた標準偏差）。
終局時の値は詰み・反則負けそのものなので、**途中の時点**（両者の受理手の合計が 20 / 40 手）の d を見る。
値は「自分 − 相手」。

**`mat` の離陸の前後**（本物の rl_mmdopen_v15 との対局）:

| 信号（自分 − 相手） | 離陸の前（100〜300更新、勝ち 180局）40手時点 | 離陸の後（`matdecay` 500〜548更新、勝ち 1,455局）20手時点 |
| --- | --- | --- |
| 王手を受けている手番の反則 | −1.06 / +0.06 / **d −0.85** | 0.00 / +0.04 / −0.09 |
| かけた王手 | +0.32 / −0.22 / **+0.59** | 0.00 / +0.45 / −0.87 |
| 相手玉の周りへの利き | +1.23 / +0.10 / **+0.53** | 0.00 / −1.00 / **+1.09** |
| 駒割り（駒の価値の合計） | +18.3 / +11.9 / +0.46 | +21.0 / +4.9 / **+1.59** |
| 取った駒の価値 | +17.1 / +14.0 / +0.43 | +14.5 / +4.8 / **+1.81** |
| 反則 | +1.78 / +2.50 / −0.32 | +0.99 / +3.07 / **−1.48** |
| 敵陣の自駒の数 | +0.50 / +0.53 / −0.02 | +1.77 / −0.30 / **+1.80** |

**`ladder`**（30〜153更新。ほぼ全部が乱数手の相手との対局、勝ち 466局・負け 2,233局）の 40手時点:
打ちの数の差 +0.43、敵陣の自駒の数 +0.42、自玉の周りの自駒 +0.38、相手玉の周りへの利き +0.33、駒得 +0.25、
王手中の反則 −0.22。

読み方:

- **どの相手・どの時期でも勝ちを先取りしていたのは「駒得・駒割り」と「相手玉の周りへの利き」**。反則は終局時には
  最大の差（d −2〜−3）になるが、途中の時点では小さい（負け局の反則は終盤にまとめて出る）
- 離陸の前は「王手をかけている・相手が王手を受けて反則している」局が勝ち、離陸の後は「20手までに駒を取っている・
  敵陣に駒がいる・自分の反則が少ない」局が勝っている。後者は 4.4節の手順そのもの（20手までに角と香を取っている局が勝つ）
- **これは相関で、因果ではない**。「その量を報酬にすると学習が速くなるか」は A/B で確かめるしかない。駒得は実際に
  報酬にして離陸した（4.2節）。次の候補は**相手玉の周りへの利き**（`--shape d_king_attack=...`）と**王手**（`d_checks`）で、未実施
- 整形の腕の中の値は、その整形が動かした結果でもある（`mat` の駒得は報酬そのもの）。候補を探すなら、
  報酬に入れていない信号の d を見る

## 6. GPU（3070）での手順

パイロットは 32ch×3・64局/更新・CPU で、seed は 4節が腕ごとに 1本（駒得だけ 4本）、8節が主な腕ごとに 6本。腕の優劣・本線の規模で同じことが
起きるか・一般の強さへつなげられるかは GPU で確かめる。**どれも本線とは別の out で回す**（本線の再開には影響しない）。

```sh
# 0. 両方のリポジトリをこのブランチにして rl-env を入れ直し、テストを回す（CPU でも動く。約5分）
VIRTUAL_ENV=$PWD/.venv .venv/bin/maturin develop --release -m ../tsuitate-bot/rl-env/Cargo.toml
.venv/bin/python rnad/tests/test_shaping.py && .venv/bin/python rnad/tests/test_league_gpu.py \
    && .venv/bin/python rnad/tests/test_mmd.py && .venv/bin/python rnad/tests/test_rnad.py

# 共通の引数（PPO 型・相手固定・ゼロから）
COMMON="--algo mmd --init none --anchor none --eval-every 0 --planes 91 --compact-legal --league-frac 1 \
  --league-device gpu --mmd-magnet uniform --mmd-temp 0.01,0,0.01,0.01 --mmd-lr 3e-4,0,3e-4,3e-4 \
  --mmd-steps 8 --mmd-epochs 2 --mmd-adv-norm 0.001 --export-every 100 --export-current --checkpoint-every 50"
X=rl_mmdopen_v15
```

**実験 1: 離陸の時期の分布を腕ごとに測る（搾取役）** — 8節の比較（腕ごとに 6 seed）を、本数を増やして確かめる。
離陸は確率的な出来事なので、腕の優劣は「何局で何割の seed が離陸するか」で比べる。小さいネットなら 1本が軽いので、
まず 32ch×3・64局で腕ごとに 10 seed 以上、そのあと本線と同じ 64ch×6 で上位の腕だけを確かめる。
回し方は 8.6節（`rnad/takeoff.py run` / `report`。上の `COMMON` と同じ設定を既定で持っている。GPU なら `--common` で
`--device cpu --threads 1` を `--device cuda` に替える）。

- 腕: `mat1`（駒得だけ）/ `mat_katk_ofoul`（＋相手玉の周りへの利き ＋ 相手の反則）/ `katk_ofoul`（駒得なしで利き ＋ 相手の反則）と、
  重み違い・王手を足した腕（8.6節の「次に試すこと」）。**整形の上限は 1.0**（0.5 は駒得が頭打ちになる。8.3節）
- 見るもの: 腕ごとの離陸した run の数と、離陸までの局数。8節は `mat_katk_ofoul` が 6本中6本（1.2万〜2.3万局）、
  `katk_ofoul` が 6本中5本（1.2万〜1.9万局）、`mat1` が 6本中2本。1更新は CPU 1スレッドで約 5〜9秒
- 離陸した run は、同じ out を `--shape-decay <今の更新>:<今の更新 + 200> --steps <...>` を付けて再開すると勝敗だけの報酬へ
  戻せる（倍率の予定は再開で変えてよい。4.2節の `matdecay`）
- 書き出しはアリーナで確かめる: `gh workflow run arena.yml -f games=100 -f candidate="rl_policy:release:<タグ>/current_600.bin"
  -f baselines="rl_mmdopen_v15 rl_mmdhand_v1 rl_mmd_v4 rl_deduce_v10 rl_v30 estimator_v14" -f match_seed=...`
- **見つかった勝ち方は本線の穴の一覧になる**: アリーナの記録（`arena-records`）で勝ち局の手順と終局理由を数える（4.4節・8.4節）

**実験 2: 一般の強さへ（相手を増やす・決定的でなくする）** — 1体への特化を避ける。

```sh
# 入力が v2 以下の凍結版を混ぜ、どの相手も手の 1割を乱数手にする（同じ手順の繰り返しを崩す）
L="rl_mmdopen_v15@0.1,rl_mmdopen_v10@0.1,rl_mmd_v4@0.1,rl_deduce_v10@0.1,rl_selfplay_v4@0.1,rl_v30@0.1,rl_v20@0.1"
.venv/bin/python -u rnad/train_rnad.py $COMMON --channels 64 --blocks 6 --batch 256 --seed 1 \
    --league $L --league-weighting hard --shape d_capture_value=0.02,king_attack=0.03,opp_fouls=0.05 --shape-cap 1.0 \
    --panel <固定パネル.json> --panel-every 100 --panel-games 128 --panel-which current \
    --steps 2000 --out out_rnad/fx_league_mat
```

- 物差しは固定パネルの Elo（`rl-learning-speed.md` 2節）とアリーナのガントレット。1体への勝率は使わない
- 入力の版が違う相手（v1 86枚・v2 91枚）は混ぜられる（`OpponentPool` が広い版にそろえる）。v3（rl_mmdhand_v1）を
  相手にするなら学習側も `--opp-hand-planes` を付ける
- この実験が「相手1体・乱数手なし」と同じ速さで立ち上がる保証は無い。パイロットの `matnoise`（相手1体・ε = 0.2）は
  2.6万局で勝率 0.4% だが、手数・引き分け・駒得は伸び続けていた（4.2節）。ここは「勝ちが出るまでが長い」ので、
  報酬の整形の比較（駒得・長さ・玉への利き）が本当に効いてくる場所になる

**実験 3: 搾取役のやり直し（R-NaD の続きから）** — `rl-deepnash-design.md` の搾取役の実験を、v-trace を直した版で。
`--init <本線の checkpoint> --league <その版> --league-frac 1 --league-device gpu` を R-NaD（`--eta 0.2` のまま）と
`--algo mmd` の両方で 1,000更新。前回は 0.488 → 0.506 だった。

## 7. 分かっていないこと・次にやること

- **seed のばらつきがいちばん大きい**: 4節の駒得の腕は 4本中 1本だけが離陸し、離陸の前の勝ちの数は seed で 20倍以上違った。
  ほかの腕は 1本ずつなので、「`len`・`all`・`matpot` は離陸しない」は「この1本では 2.6万〜3万局までに離陸しなかった」
  という意味。しかもどれも上限 0.5 の設定で回している（8.3節）ので、**上限 1.0 でやり直すと結論が変わりうる**。
  8節の比較も腕ごとに 6本で、6本中6本と 6本中5本の差は誤差の内。腕の順位を言い切るには 10本以上が要る（実験 1）
- **ネットの大きさと局数**: 32ch×3・64局/更新の結果。64ch×6・256局で同じ局数で離陸するかは未確認
- **一般の強さ**: 相手1体・決定的な相手への特化しか見ていない。相手を増やして乱数手を混ぜたとき（実験 2）に、駒得の整形が
  どれだけ効くかは未確認（`matnoise` は 2.6万局では離陸していない）
- **駒得以外の整形**: 相手玉の周りへの利き・相手の反則・王手を駒得に足す比較、その組み合わせ、駒得なしの腕は 8節。
  重みの振り方は 8.6節の「次に試すこと」。負けるまでの長さ・自分の反則のペナルティを上限 1.0 でやり直すことも未実施
- **整形を下げる時期**: `matdecay` は離陸の直後（勝率 2% の時点）から下げて保てた。勝ちが出る前に下げ始めた場合は見ていない。
  勝率を見て自動で下げる形（例: 直近の勝率が 10% を超えたら 200更新で 0 へ）は未実装
- **梯子の配分**: 引き分けの多い段に配分が張り付く（4.2節）。直すなら `league.py` の even で引き分けを負けと数える
- **本線への持ち帰り方**:
  - 搾取役の見つけた手順を、本線の自己対局の序盤の強制（`rl_openings.json`）や練習相手（`--league rl_policy:<重み>`）に入れる。
    本線は `--pipeline` の自己対局だけで回しているので、リーグと併用する形は別に決める必要がある
  - 自己対局に駒得のポテンシャル型の整形を入れる A/B（零和を保つ `d_` の重み）。今の実装は `--pipeline`・`--fast-collect` と
    一緒に使えない（速い収集が信号を読まない）ので、本線の速さで回すには収集側の対応が要る
- **学習器の設定**: 正規化の下限・1更新の歩数・学習率は最初に動いた組み合わせで、振っていない

## 8. 駒得に何を足すと離陸が増えるか・速くなるか（2026-11-11）

4節のパイロットは「駒得の報酬で 4 seed 中 1本が離陸」だった。**駒得以外の何を足せば離陸の率と離陸までの局数が良くなるか**を、
腕 × seed の形で測った（2026-11-11 ユーザー依頼）。設定は 4.1節と同じ（32ch×3・64局/更新・相手 rl_mmdopen_v15・PPO 型）。
効いた信号は組み合わせた腕と、**駒得を外した腕**でも測った。

### 8.1 測り方

- **離陸** = 直近 50更新（3,200局）の勝率が 10% 以上になった最初の更新。**打ち切りは 400更新（25,600局）**。
  離陸した run は 30更新だけ続けて止める（tsuitate-nn の `rnad/takeoff.py`。`run` が腕 × seed を並列に回し、`report` が表にする）
- 腕どうしは同じ seed（1〜6）で比べる。seed は初期値と対局の乱数を決めるので、最初の更新までは腕によらず同じ局になる
- **離陸の前の勝ちの数は当てにならない**（4.2節の `matpot` は最初の 200更新で 82勝して離陸しなかった）。比べるのは離陸そのもの

### 8.2 足した信号

離陸の前のログ（4節の `mat` の 4 seed）を見ると、どの seed も駒は同じように取れていて（駒得 +14〜+21）、ほぼ全局が自分の
反則負け（1局 9.2〜9.8回）で終わっていた。離陸した seed 1 だけが、離陸の前から「王手で相手に反則させる」回数が多かった
（相手の王手中の反則 0.7〜0.8回/局、ほかの seed は 0.1〜0.25回）。**分かれ目は「取った駒を詰み（か相手の反則負け）へつなげる」
ところ**なので、候補は詰みへ向かう量を中心に選び、足りない信号を env に 3つ足した（`src/rl/signals.rs`）:

| 信号 | 中身 |
| --- | --- |
| `mate_threat` | 一手詰めがあるか（0 / 1）。自分の手番なら全合法手の一手詰め、相手の手番なら相手が王手を受けていないときの打ちの詰めろ |
| `evasions` | 王手を受けている手番で受理された手の数（王手を外した回数） |
| `king_escape` | 自玉の8近傍のうち、自駒がおらず相手の利きも無いマスの数（今回は報酬に使っていない。監視用） |

腕（整形の上限はどれも 1.0。下の3行以外は、駒得 `d_capture_value=0.02` に足す）:

| 腕 | 足したもの | 引数（`--shape` の追加分） |
| --- | --- | --- |
| `mat1` | なし（対照。駒得だけ・上限 1.0） | — |
| `mat_katk` | 相手玉の周りへの利き | `king_attack=0.03` |
| `mat_ofoul` | 相手の反則 | `opp_fouls=0.05` |
| `mat_chk` | かけた王手 | `checks=0.05` |
| `mat_mate` | 一手詰め・詰めろ | `mate_threat=0.3` |
| `mat_evade` | 王手を外す ＋ 王手中の反則のペナルティ | `evasions=0.03,fouls_in_check=-0.03` |
| `mat_katk_ofoul` | 相手玉の周りへの利き ＋ 相手の反則（効いた2つの組み合わせ） | `king_attack=0.03,opp_fouls=0.05` |
| `katk_ofoul` | **駒得なし**で、相手玉の周りへの利き ＋ 相手の反則 | `--shape king_attack=0.03,opp_fouls=0.05`（駒得の重みを外す） |
| `katk` / `ofoul` | 駒得なしで、利きだけ / 相手の反則だけ（seed 2・3 の 2本ずつ） | `--shape king_attack=0.03` / `--shape opp_fouls=0.05` |

### 8.3 結果: 離陸の率と、離陸までの局数

打ち切り 25,600局（400更新）。太字は離陸までの局数、「>」は打ち切りまで離陸しなかった run。
`mat05` は 4節の `mat`（上限 0.5）を同じ基準で数え直したもの（seed 3・4 は 400更新まで延ばした）。

- **整形の上限 0.5 が足を引っ張っていた**（`mat05` 1/4 → `mat1` 6本中2本）。上限 0.5 では、1局の駒得が +25 点
  （0.02 × 25 = 0.5）で頭打ちになる。`mat05` は 200更新ごろには **2〜6割の局が上限に張り付いて**いて（駒得 +15〜21 点）、
  そこから先は駒を取っても失っても報酬が動かない。上限 1.0 では張り付かず、駒得は +26〜49 点まで伸びた。
  4節の「4 seed 中 1本」はこの設定の影響を受けている。**上限は既定の 1.0 を使う**（上限を変えると報酬の縮め方も
  1.5 → 2.0 に変わり、エントロピーの正則化が相対的に 0.75倍になる。頭打ちとどちらが効いたかは分けていない）
- **駒得に「相手玉の周りへの利き」「相手の反則」「王手」を足すと、離陸する run が増えた**: `mat_katk` 6本中5本、

  p = 0.03。離陸までの局数は片方ずつの腕と大きくは変わらず（打ち切りを上限にした平均で 1.61万局。`mat_katk` 1.73万局・
  `mat_ofoul` 1.90万局・`mat1` 2.29万局）、**良くなったのは速さより率**
- **駒得は無くても離陸する**（`katk_ofoul`。駒得の重みを外して、利きと相手の反則だけ）: **6本中5本**が 1.15万〜1.94万局で離陸し、
  中央値 1.36万局は全部の腕でいちばん少ない。4節で立てた「駒得で最初の勝ちを作る」は必要条件ではなかった。
  ただし勝ち方が変わる（8.4節。駒得があると詰み、無いと相手の反則負け）。seed 4 だけ離陸しなかった
  （駒得つきの上限 1.0 の 5腕は全部この seed で離陸している）
- 利きか相手の反則を入れた 4腕（`mat_katk`・`mat_ofoul`・`mat_katk_ofoul`・`katk_ofoul`）を合わせると 24本中21本（88%）、

### 8.5 まとめ

1. **整形の上限は 1.0 にする**（0.5 は駒得が頭打ちになり、離陸を妨げた）
2. **足すなら「相手玉の周りへの利き」と「相手の反則」の両方**（`king_attack=0.03,opp_fouls=0.05`）。離陸した run は、
   駒得に両方を足して **6本中6本**、片方ずつで 6本中5本ずつ、駒得だけは 6本中2本。王手（`checks=0.05`）は 6本中4本
3. **駒得は無くても離陸する**: 利き ＋ 相手の反則だけで 6本中5本、離陸までの局数の中央値は 1.36万局でいちばん少ない
   （駒得つきの組み合わせ 1.50万局・駒得だけ 1.75万局）。ただし勝ち方が相手の反則負けに寄り（詰みで勝つのは駒得と利きの
   両方を入れた腕）、離陸の直後の勝率は駒得つきの組み合わせのほうが高い（平均 32% 対 17%）。**率と離陸の後の伸びを
   取るなら駒得つきの組み合わせ、最初の勝ちまでの速さだけなら駒得なし**
4. **駒得なしで片方だけ（利きだけ・相手の反則だけ）では足りなかった**（2本ずつ。4本中1本で、その1本も続かなかった）。
   駒得を外すなら 2つを合わせる
5. **一手詰め・詰めろの信号と、王手を外す報酬は、この重みでは効かなかった**（1本ずつ）
6. **いちばん早く相手に勝ち越したのは、駒得＋王手の 1本**（19,200局でアリーナの rl_mmdopen_v15 に 84.5% ± 5.0。8.4節）。
   4節の最初の離陸（38,400局で 53%）の半分の局数だが、1本だけの結果で、決まった1本の手順への特化
7. 足した信号は「駒を取る」から「玉へ向かう」へ方策を寄せる。**ゼロからの方策に足りなかったのは、駒を取ることではなく
   玉へ向かうこと**で、離陸は「王手をかける → 相手が反則する（か詰む）」が偶然つながったところから始まる
8. **エンコーダ v4 の入力（玉の移動で反則したマス）は、離陸を早くしなかった**（8.7節。率は同じ・局数の差は誤差の内・
   ネットはまだこの入力を読んでいない）
9. 離陸は相変わらず確率的。離陸した 28本のうち 24本は 2万局までに離陸しているので、**2万〜2.5万局で離陸しない run は
   見切って seed を変える**のが、同じ計算量で多く離陸させる回し方になる（`takeoff.py` の打ち切り）

### 8.6 回し方と、次に試すこと

```sh
# rl-env を入れ直してから（信号 mate_threat / evasions / king_escape が要る）
X=rl_mmdopen_v15
.venv/bin/python rnad/takeoff.py run --root out_rnad/tk --opponent $X --seeds 1,2,3,4,5,6 --steps 400 --jobs 4 \
    --arm mat1='--shape d_capture_value=0.02 --shape-cap 1.0' \
    --arm mat_katk_ofoul='--shape d_capture_value=0.02,king_attack=0.03,opp_fouls=0.05 --shape-cap 1.0' \
    --arm katk_ofoul='--shape king_attack=0.03,opp_fouls=0.05 --shape-cap 1.0'
.venv/bin/python rnad/takeoff.py report out_rnad/tk --horizon 400
```

- `run` は途中で止めても、同じコマンドで続きから回る（終わった run は飛ばす）。`--queue 腕:seed,...` で回す順を指定できる。
  GPU なら `--common` で `--device cuda` と大きいネットに替える（既定の `COMMON` はこのパイロットの CPU の設定）
- **次に試すこと**（未実施）:
  - **seed を増やす**: 腕ごとに 6本では、6/6 と 5/6 の差は誤差の内。上位の腕（`mat_katk_ofoul`・`katk_ofoul`・`mat_katk`）と
    対照（`mat1`）を腕ごとに 10本以上で確かめる
  - **重みを振る**: 今回はどの信号も重み1点だけ。`king_attack` を 0.02 / 0.05、`opp_fouls` を 0.03 / 0.1 など
  - **王手も足す**: `checks=0.05` は駒得に足して 6本中4本で、いちばん伸びた run（19,200局で 85%）もこの腕から出た。
    組み合わせ（利き ＋ 相手の反則）に足して、率を保ったまま離陸の後が速くなるか
  - **離陸の後を揃えて測る**: 今回は離陸の 30更新後で止めている。離陸から 100〜200更新続けて、勝率 50%・80% に届くまでの
    局数を腕ごとに比べる（`takeoff.py run --after 200`）
  - **離陸の後**: 整形を下げて勝敗だけに戻した後の伸び（4.2節の `matdecay`）が、足した信号・勝ち方（詰み / 相手の反則負け）で
    変わるか。駒得なしの腕は離陸の後に駒得を足すと詰みの筋も覚えるか
  - **大きいネット・乱数手を混ぜた相手**（6節の実験 1・2）で同じ順位になるか
  - **本線への含意**: 「遠くからの王手で反則負けに追い込まれる」穴を、本線の学習の相手（搾取役）として使う

### 8.7 エンコーダ v4 の入力（玉の移動で反則したマス）は離陸を早くするか
