# 入力プレーンの A/B を CI の大きさで回す（Input A/B）

2026-11-22。方策ネットの入力（エンコーダのプレーン）を足したときの効果は、これまで本番の大きさ
（64ch×6・1更新 256局）で乱数初期化から 26,500〜50,000更新を GPU で数日回して確かめてきた。
これを **GitHub Actions の CPU だけで回る大きさ**に縮めて比べる道具と、その道具が信用できるかの確かめ方をまとめる。

**早い段階から効く入力の差は検出できる。強くなってから効く入力の差は見えない**（下の「較正」。2026-11-23）。
確定事実の 5枚（v2 対 v1）は 600・1,200・1,800更新のどの時点でも 58〜62% で検出できた。取った駒・取られた駒の一覧
（v5 対 v4）と、相手の持ち駒の上界・反則の時系列（v3 対 v2）は、本番の大きさでは効くのに、最後の時点で 49〜52% だった。
使い方は片側: **「差がある」と出たら有望、「分からない」は判断材料にしない**（本番の大きさで差が無いことの根拠にならない）。

## 何を回すか

腕（入力の版）× seed ごとに、小さいネットを乱数初期化から自己対局だけで育てる。学習の型は scratch の系列
（`rl_scratch_v1` / `rl_scratch5_v1`。`docs/frozen-versions.md`）と同じで、大きさだけを縮める。

| | 本番の大きさ（scratch の系列） | Input A/B |
| --- | --- | --- |
| ネット | 64ch × 6ブロック | 32ch × 3ブロック |
| 1更新の局数 | 256 | 64 |
| 更新の数 | 26,500〜50,000 | 既定 1,600（通算 約10万局） |
| 学習法 | MMD・一様な磁石・自己対局だけ | 同じ |
| 序盤 | 定跡（`rl_openings.json`）を 100% 強制 | 同じ |
| 報酬の整形 | 駒得と玉への利き（途中で切る） | 同じ重み（短いので最後まで切らない） |
| 計算 | GPU で数日 | CPU の 1スレッドで 1本 数時間。1ランナー 4本 |

腕は入力の版の名前（`v1`〜`v6`）か、`extra_arms` で足す好きな組み合わせ（`train_rnad.py` の引数）。
学習の設定の一次資料は tsuitate-nn の `rnad/input_ab.py`（`COMMON` と `ARMS`）。

## 回し方

`.github/workflows/input-ab.yml`。**通常のコード push では走らない**。

```bash
gh workflow run input-ab.yml --ref <ブランチ> -f arms="v4 v5" -f control=v4 -f treat=v5 -f seeds=8
```

`gh` が無ければ `.github/ci/input-ab.request.json` を書いて push する（例は `input-ab.request.example.json`。
削除の push は何もしない）。

| 引数 | 既定 | 中身 |
| --- | --- | --- |
| `arms` | `v4 v5` | 入力の版（スペース区切り） |
| `extra_arms` | `{}` | 追加の腕 `{"名前": "train_rnad.py の引数"}`。新しい組を試すときはここに足す |
| `control` / `treat` | `v4` / `v5` | 判定の対照と候補 |
| `seeds` | 8 | 腕ごとの本数。1ランナー 4本なので、2腕 × 8本 = 4ランナー |
| `steps` | 1600 | 通しの更新回数の上限 |
| `stages` / `stage_minutes` | 2 / 290 | 学習のジョブを何段つなぐか（1〜3）と、1段の時間。GitHub のジョブは 6時間までなので、届かなければ次の段が checkpoint から続ける |
| `export_every` | 100 | 重みを書き出す間隔（比べられる時点の刻み） |
| `games` | 100 | 総当たりの 1対の局数 |
| `horizons` | 4 | 比べる時点の数（全部の run に共通の書き出しから等間隔。最後は必ず入る） |
| `refs` | `heuristic rl_v15` | 基準の相手（絶対的な強さの目安） |
| `nn_ref` | `main` | tsuitate-nn の ref（新しい組のフラグが main に無ければそのブランチ） |

流れは plan → train1〜3（学習）→ horizons（比べる時点を選ぶ）→ crossplay（時点ごとに総当たり）→ report。
結果はジョブサマリーと artifact `input-ab-report`（表・対局の集計・入力の読み方）、学習の状態は
`iab-train-s<段>-<シャード>`（重みと checkpoint とログ。後の段ほど進んでいる）。

リポジトリは公開なので Actions の分は無料。CI のランナーでは 4本並列で 1更新 12〜18秒（学習の初めの実測。局が長くなると
遅くなる）なので、1段（290分）で進むのは 1,000更新前後。既定の設定で、学習が 4ランナー × 最長 約10時間、
対局と集計が 1〜3時間。流れだけを確かめる小さい設定（2本ずつ・30〜40更新・1段 3〜4分）は全体で 20〜26分。

## 比べ方と表の読み方

重みは `<腕>_s<seed>/current_<更新>.bin`。**同じ更新どうし**を `bin/arena` で総当たりにする
（両側とも序盤は定跡から = 学習と同じ条件。戦略名は `open:book:rl_policy:<パス>`）。対局と集計は
`scripts/ci/input_ab.py`。

| 表の数字 | 意味 |
| --- | --- |
| 腕 A の、腕 B への勝率 | A の各 seed と B の各 seed の勝率の平均 |
| かっこ内の幅 | **seed を取り直したとき**の 95% の幅（両方の腕の seed を復元抽出するブートストラップ）。1局ごとのぶれではなく「別の seed で回し直したらどれだけ変わるか」 |
| 対角（同じ腕） | seed ごとの、同じ腕のほかの seed への勝率の最小〜最大。**入力が同じでも seed だけでこれだけ散る**という目安 |
| 名札の入れ替え検定 p | 腕の名札を run の間で入れ替えても同じ差が出る確率（片側）。量は「ほかの全部の run への平均勝率」の腕ごとの平均の差 |
| 基準の相手への勝率 | 絶対的な強さの目安（腕どうしの勝率は相対的なので、両方とも弱いままでも 50% 前後になる） |
| 入力の組をどれだけ読んでいるか | その組のプレーンを 0 にして渡したときの方策の変化。**足した組をネットが読んでいなければ、勝率の差は入力のせいではない** |

判定は最後の時点で、「幅の下端が 50% を超え、かつ p < 0.05」なら候補が強い、「幅の上端が 50% 未満」なら弱い、
どちらでもなければ「この規模では分からない」。

集計の統計は差の分かっている合成データで確かめてある（8本 対 8本・1対 100局、seed ごとの強さのばらつきつき）:
差なしで「強い」と出たのは 40回中 2回、勝率 57% 相当の差で 18回、69% 相当の差で 37回。
**小さい差（勝率で 55% 前後）は 8本ずつでは半分も検出できない**ので、「分からない」は「差が無い」ではない。

## 較正（答えの分かっている組で差が再現するか）

本番の大きさでは、v5（取った駒・取られた駒の一覧つきの 124枚）は v4（102枚）より強い:
本線の相手 `rl_mmdhandex_v2` への勝率が、20,000更新で 54% 対 67.3%、26,500更新で 62.7% 対 72.3%、
直接対決でも `rl_scratch5_v1` が `rl_scratch_v1` に 62.3%。

同じ向きの差が Input A/B の大きさで出るかを、v4 対 v5 で見る。

| 結果 | 読み方 |
| --- | --- |
| v5 が強いと出る | この道具で、同じ種類の入力（駒の一覧のように早い段階から効くもの）の採否を先に見られる |
| 分からない・逆向き | この大きさでは入力の差が見えない。更新の数を増やす（`steps` と `stages`）か、ネットを大きくするか、本番の大きさの短い比較（既存の checkpoint を広げて続ける）に戻る |

注意が 2つある。

- **小さいネットは入力を読まないことがある**。相手を固定した小さい学習で v4 の `king_fouls` を試したときは、
  組を 0 にしても方策がほとんど変わらなかった（`docs/rl-fixed-opponent.md` 8.7）。表の「入力の組をどれだけ読んでいるか」で
  毎回確かめる
- **学習の早い段階の差しか見えない**。通算 約10万局は、局数では本番の大きさの 400更新ぶんにあたる
  （小さいネットは 1局あたりの更新が多いので同じ局数でも先へ進むが、どこまで進んだかは基準の相手への勝率で見る）。
  強くなってから効く入力（終盤の読みに使うものなど）は、この道具では見えない

### 較正の結果（2026-11-23）: v5 対 v4 は再現しなかった

run 45035010022（v4 対 v5・12本ずつ = 6ランナー・2,400更新・1対 100局）。学習は 3段で 11時間40分、総当たりと表まで
入れて 13時間24分。24本とも 2,400更新に届いた。

| 更新（通算の局数） | v5 の v4 への勝率 | seed を取り直したときの幅 | 入れ替え検定 p | `rl_v15` への勝率（v4 / v5） | 1局の反則（v4 / v5） |
| --- | --- | --- | --- | --- | --- |
| 600（3.8万） | 54.3% | 50.2%〜58.5% | 0.034 | 18.0% / 17.9% | 5.81 / 5.58 |
| 1,200（7.7万） | 52.4% | 47.0%〜57.7% | 0.189 | 28.8% / 29.7% | 5.53 / 5.38 |
| 1,800（11.5万） | 53.1% | 47.8%〜58.0% | 0.121 | 38.3% / 40.8% | 5.33 / 5.03 |
| 2,400（15.4万） | **49.4%** | 44.6%〜53.9% | 0.601 | 46.9% / 46.8% | 4.93 / 4.93 |

読み方:

- **最後の時点で差が無い**。600更新の 54.3%（p = 0.034）は、4つの時点を見たうちの 1つで、その後は縮んで消えた。
  「v5 が強い」の再現とは言えない
- **道具の分解能は足りていた**。最後の時点で、同じ腕の seed ごとの勝率の散らばりは 39%〜63%、12本ずつの幅は ±4.7pt。
  本番の大きさの直接対決（62.3%）と同じ大きさの差があれば検出できた。**この大きさ・この強さでは差そのものが無い**
- **読んでいないわけでもない**。2,400更新の v5 のネットは足した組を読んでいる（組を 0 にしたときの方策の変化:
  `lost_fresh` 0.195、`pawn_files` 0.152、`cap_roles` 0.077、`lost_roles` 0.051。最善手が変わる割合は 6〜21%。
  参考に、確定事実 0.47、`opp_hand` 0.29、`king_fouls` 0.07、`opp_fouls` 0.05）。読んではいるが、強さに変わっていない
- **学習は進んでいる**。`rl_v15` への勝率は 18% → 47% とまっすぐ上がり、まだ伸びている。ただし本番の大きさで v5 の差が
  測れたのは、本線の相手 `rl_mmdhandex_v2` に 5割を超える強さになってから（20,000更新〜）で、ここで育つネットは
  そこから遠い

**結論**: v5 のように「強くなってから効く」入力の採否は、この道具では決められない。**「差が無い」と出ても、
本番の大きさで差が無いことの根拠にならない**。「差がある」と出たときに信用できるかは、効果の大きい組での
確認（次の節）で分かる。

### 効果の大きい組での確認（v1・v2・v3）

道具が入力の差を 1つも検出できないのか、早い段階から効く入力なら検出できるのかを分けるための run。
本番の大きさで効果が大きく、早く出た組を使う。

| 比べる組 | 足した入力 | 本番の大きさでの結果 |
| --- | --- | --- |
| v2 対 v1 | 確定事実の 5枚（相手玉の候補・王手駒の候補など） | 既存のネットを広げて 2,000更新で、前の版に 66.5%（`rl_deduce_v1`） |
| v3 対 v2 | 相手の持ち駒の上界と、相手の反則の時系列 | 持ち駒の上界だけを足して 12,000更新で、同じ更新数の本線に 57.2%（`rl_mmdhand_v1`） |

| 結果 | 読み方 |
| --- | --- |
| v2 が v1 より強いと出る | 早い段階から効く入力は検出できる。新しい入力で「差がある」と出たら有望、「分からない」は判断材料にしない、という片側の使い方ができる |
| v2 と v1 も分からない | この大きさでは入力の差が見えない。この道具は入力の採否に使わない |

### 効果の大きい組の結果（2026-11-23）: v2 対 v1 は検出できた。v3 対 v2 は最後の時点で消えた

run 45117492546（v1・v2・v3・12本ずつ = 9ランナー・1,800更新・1対 60局）。学習は 3段で 9時間57分、総当たりと表まで
入れて 12時間13分。36本とも 1,800更新に届いた。

| 更新（通算の局数） | v2 の v1 への勝率（幅・p） | v3 の v2 への勝率（幅・p） | v3 の v1 への勝率（幅・p） | `rl_v15` への勝率（v1 / v2 / v3） | 1局の反則（v1 / v2 / v3） |
| --- | --- | --- | --- | --- | --- |
| 600（3.8万） | **60.9%**（56.7%〜65.0%・p < 0.001） | 55.0%（50.0%〜59.3%・p = 0.017） | **66.0%**（62.7%〜69.4%・p < 0.001） | 12.0% / 11.9% / 13.8% | 6.45 / 5.63 / 5.31 |
| 1,200（7.7万） | **62.3%**（57.8%〜66.7%・p < 0.001） | 49.8%（44.5%〜55.0%・p = 0.527） | **62.7%**（58.2%〜67.4%・p < 0.001） | 21.9% / 34.0% / 30.9% | 6.14 / 5.27 / 5.19 |
| 1,800（11.5万） | **58.5%**（53.9%〜63.4%・p = 0.002） | 51.5%（45.9%〜57.0%・p = 0.308） | **60.1%**（55.2%〜65.2%・p = 0.001） | 33.8% / 42.8% / 42.4% | 5.79 / 5.02 / 4.91 |

かっこ内は seed を取り直したときの 95% の幅と、名札の入れ替え検定の片側 p。

読み方:

- **v2 対 v1 は、どの時点でも検出できた**。確定事実の 5枚を足したネットは、足していないネットに 58〜62% で勝ち、
  幅の下端はどの時点でも 53% を超える。基準の相手への勝率（1,800更新で `rl_v15` に 42.8% 対 33.8%）と 1局の反則
  （5.02 対 5.79）も同じ向き。**この道具は、早い段階から効く入力の差を検出できる**
- **v3 対 v2 は、600更新で少し出て、その後消えた**（55.0% → 49.8% → 51.5%）。較正の v5 対 v4（54.3% → 52.4% → 53.1% → 49.4%）と
  同じ形。本番の大きさでは、相手の持ち駒の上界だけで 12,000更新・57.2% の差が出ている
- **足した組は読んでいる**（1,800更新。組を 0 にしたときの方策の変化と、最善手が変わる割合）: 確定事実 0.46（47%）、
  `opp_hand` 0.27（28%）、`opp_fouls` 0.05（5%）。`opp_hand` は読んでいるのに強さの差になっていない = v5 のときと同じ
- **600更新だけ差が出る形が 2回続いた**（v5 対 v4 の 54.3%・p = 0.034、v3 対 v2 の 55.0%・p = 0.017）。足した入力が
  学習の立ち上がりを少し早めて、その後に追いつかれている可能性がある。ただし、どちらも見た時点のうちの 1つで、
  この道具の判定（最後の時点）では「分からない」のまま
- 同じ腕の seed どうしの勝率は、1,800更新で 37%〜65% に散る。12本ずつの幅は ±5pt 前後で、較正の run と同じ

**結論**: この道具は**片側にだけ使える**。

| 出た結果 | 扱い |
| --- | --- |
| 最後の時点で「候補が強い」 | 有望。確定事実（v2）と同じ「早い段階から効く入力」にあたる。本番の大きさで確かめる候補にする |
| 「分からない」 | 判断材料にしない。v3・v5 の組は本番の大きさで効くのに、ここでは最後の時点で 49〜52% だった |

- **見えるもの・見えないものの分かれ目**（3組だけからの見立て）: 見えた v2 は、盤のどこに何がいうるかを直接渡す入力
  （相手玉の候補・王手駒の候補）で、乱数初期化に近いネットでもすぐ使える。見えなかった v3・v5 は、持ち駒や取った駒の
  記録で、ネットが強くなってから（本番の大きさで本線の相手に 5割を超えてから）差になった
- **相手を固定した離陸の実験も、同じ分かれ方をした**（`docs/rl-fixed-opponent.md` 8.8節。2026-11-23）: 既存の版 1体に
  ゼロから当てる学習で、v3〜v5 の組を足しても離陸は早くならず（片側 p = 0.14）、v6 の組まで足すと早くなった（p = 0.015）。
  小さいネット・短い学習で見えるのは、どちらの道具でも「早い段階から効く入力」
- **v6 の組をこの道具で見る価値はある**。v6 の組（締めた相手玉の候補・王手からの手数・自駒の利きなど）は v2 の確定事実と
  同じ種類で、離陸の実験では読まれていて効いた。`arms="v5 v6" control=v5 treat=v6`（`nn_ref` は v6 のフラグがあるブランチ）で、
  「強い」と出れば本番の大きさで確かめる前の裏付けになる。「分からない」と出ても、v6 を入れない理由にはしない

## 手元で回す

```bash
# 学習（tsuitate-nn で。4本を並列に）
.venv/bin/python rnad/input_ab.py run --root out_rnad/iab --arms v4,v5 --seeds 1,2 --steps 300 --jobs 4 \
    --book ../tsuitate-bot/rl_openings.json --export-every 50
.venv/bin/python rnad/input_ab.py status out_rnad/iab
# 対局と表（tsuitate-bot で）
cargo build --release --bin arena
python3 scripts/ci/input_ab.py crossplay ../tsuitate-nn/out_rnad/iab --step 300 --games 100 \
    --arena target/release/arena --out /tmp/iab/step300.jsonl --refs "heuristic"
python3 scripts/ci/input_ab.py table /tmp/iab --control v4 --treat v5
```

手元（4コア）の実測: 4本並列で 1更新 8〜11秒（学習の初め。局が長くなると遅くなる）、総当たりは 200局で 18秒。
