## 0. 要点

1. **Ataraxos の学習は R-NaD ではなく「PPO の比クリップ ＋ 収集方策への逆KL ＋ 磁石への逆KL×温度」**。
   - アドバンテージは GAE λ=0.5、価値は TD(λ=0.8) で作る。学習に使うのは、|A| が全体の 75%点以上の標本だけ。
   - **1/μ はどの式にも無い**【一次】。
   - 1回の収集を最大200回の Adam の歩に分ける。学習率と温度は、収集回数 t のべき乗で下げる【一次】。
2. ついたて将棋で新しく要るデータは2つだけ。
   - **行動側の価値 `v_actor`** と、**合法手全体の対数確率 `mu_logp`**（CSR の並び）。
   - 768局で約19MB【実測】。
3. **手番の構造は、既存の `v_trace_scalars` を η=0・π=μ=1・c=λ で呼べば扱える**【実測: 素直なループとの差 ≤2.4e-7】。
   - λ は**試行ごと**にかかる。反則の試行も1回と数える。
   - 受理された手ごとにする版は、c を [T,B] のテンソルにすれば作れる（2.3）。
4. **改訂の中心: Ataraxos の絞り込み（全体の 75%点で切る）は既定にしない**。
   - クーンで標本なしの期待値の更新を回すと、75%点で切る絞り込みは均衡から離れた点で止まる（NashConv 0.46〜0.68）。
     絞り込みなしなら α-QRE に収束する【実測・批判側】。
   - v7 でも、選ばれる行は局面の価値と結果の向きに偏る。価値を選んだ行だけで学ぶと、確信のある局面の価値が 0 へ縮む【実測・批判側】。
   - 既定は**比例確率の不偏な間引き（pps）**にする。
     - 行を確率 p = clip(|A|/c, 0.05, 1) で残す。
     - 全項に重み s̄/p を掛ける（s̄ = 残す割合）。
     - 期待値は「絞り込みなし」と同じなので、固定点は変わらない。
   - 【実測】v7 では、割合 0.25 で雑音（2次モーメント）が全行の 1.6〜1.8倍、計算は 1/4。割合 0.5 なら雑音は 1.07〜1.11倍。
   - 割合（0.25 / 0.5 / 1 = 全行）は、3070 で「更新が収集に隠れる最大」に決める（6.0c）。
   - Ataraxos どおりの絞り込みは、`--mmd-preset ataraxos` の腕として残す。
5. **磁石は「出発点の方策と一様の混合（ε=0.03）」を既定にする**（判断）。
   - 合法手に一様な磁石は、質量の 39% を打ちに置く。二段の一様は 34% を歩、10% を香に置く【実測・批判側】。
   - どちらも、強い方策をそちらへ引き戻してしまう。
6. **λ_A の既定は 0.8**（判断）。
   - λ_A=0.5 だと、「次の手番の価値の誤差の半分」を手の良し悪しとして学んでしまう。
   - CPU の診断 (a) で 0.5 を支える結果が出たときだけ 0.5 にする。
7. **A/B の学習率は固定する**（1e-4、または P2 と Phase A で下げた値）。
   - Ataraxos の学習率の減衰を入れると、焼きなましの効果が A/B の差に混ざる。
   - 温度だけ t で下げる。起点は 2,000 ずらす（α₀ ≈ 0.005）。
8. `--pipeline` では **decoupled PPO** にする。
   - クリップと KL の中心を「更新の頭の方策」にする。μ との比は外側の重みにする。
   - 1更新の Adam の歩数は **8 に固定**する（端数のバッチを作らない）。
9. 3070 の A/B では、本線を次の Δm の区切り（例 108,000。98,000 は 2026-10-25 に rl_deduce_v8 として凍結済み）で止めて MMD を回す。対照は本線の続き。
   - **先に本線の log.jsonl を `rnad/stage_log.py` にかけて、律速が収集か更新かを決める**。本線を止めずにでき、費用は0。
   - 判定の標準誤差に学習の揺れ τ を入れると、SE は 1.0〜1.2pt になる【計算】。τ は未計測なので 0.8pt と仮定する。
   - この A/B で決められるのは2つだけ。「MMD が明らかに悪くないか」と「Δ ≥ +2pt の大きい効きがあるか」。
   - +2pt は、壁時計の速さに直すと ×1.7〜5 にあたる。その間の結果は「保留」として扱う（6.4）。
10. 【実測】v7 では、ミニバッチ ≤1,024 の方策の勾配はほぼ雑音（ノルムが 1/√m で減る）。
    - 1回の収集を何歩にも分けても、利得は √k 程度にとどまる恐れがある。
    - CPU の診断 (a) で先に確かめる。

## 1. Ataraxos の学習の仕様（一次資料）

### 1.1 損失

ミニバッチは「1時刻・1手番側・全 env」の1行【一次】`pyengine/core/buffer.py:254-285`。
標本の集合 S は、終局後のダミーでなく、`adv_mask` が真のもの。
順伝播は S にだけかける【一次】`pyengine/core/rl.py:528-538`。B = |S|。

```
r_i   = exp(log πθ(a_i|x_i) − log μ(a_i|x_i))                                   rl.py:543-547
L_pol = −(1/B) Σ_i min(A_i·r_i, A_i·clip(r_i, 0.8, 1.2))                         rl.py:549-551
L_kl  = (1/B) Σ_i Σ_a πθ(a)·(log πθ(a) − log μ(a))        = KL(πθ‖μ)、合法手の全分布   rl.py:553-554
L_v   = 3クラス（負・分・勝）の交差エントロピー  −(1/B) Σ_i Σ_c ξ_i(c)·log pθ(c|x_i)   rl.py:557-561
        （スカラーの経路は MSE                                                    rl.py:562-564）
L_mag = (1/B) Σ_i KL(πθ(·|x_i) ‖ ρ(·|x_i))                                        rl.py:566-572
L     = 1.0·L_pol + α_t·L_mag + 1.0·L_v + 0.1·L_kl                                  rl.py:574-579
```

- 【一次】A は**正規化しない**。価値の単位（p勝−p負 ∈ [−1,1]）のまま使う（rl.py:541）。
- 【一次】μ は、収集時に保存した**合法手全体の対数確率**。
  最大100手を前に詰めて保存し、学習時に −1e10 で埋めて元の並びに戻す（`buffer.py:140, 293-322, 325-348`）。
- 【一次】磁石 ρ は、学習側の既定 `uniform_magnet: True` で**合法手に一様**（rl.py:105, 567-568）。
  二段の一様は `pyengine/utils/helper.py:20-36` にある。
- 【二次】論文の式も同じ形（v2 p44 の式(5)(6)）。
  ただし**論文の磁石は「動かす駒を一様に選び、その駒の手を一様に選ぶ」二段**（v2 p13、表 S6）。
- 【一次】勾配ノルムを 0.267 でクリップしてから、AdamW を1歩進める（rl.py:580-585）。
  AdamW は betas (0.9, 0.999)・eps 1e-8・weight decay 0（`pyengine/core/train_container.py:22-38`、rl.py:69）。
- 【一次】**絞り込みは全項にかかる**。順伝播が S だけなので、価値・KL・磁石も上位25% の標本だけで学ぶ（rl.py:530-538）。
- 【一次】落とし穴: 現行の MoveTransformer は、非合法手を `finfo.min` で埋める（`pyengine/networks/move_transformer.py:143`）。
  - 温度＋kl_coef が1前後を超えると NaN になる（train_reader の `loss_check2.py` で再現）。
  - 既定値では起きない。

### 1.2 アドバンテージと価値の目標

- 【一次】手番側ごとの系列で計算する。
  - `view(traj_len, 2·num_envs)` で、列を「env×プレイヤー」にする。
  - 自分の次の手番は行+2、という前提で書かれている（buffer.py:166, 200-217）。
  - 相手の手は環境の遷移として扱う（solipsistic）。
- 【一次】終局の報酬は2行に書く（buffer.py:141-162）。
  - 終局させた手の行に、指した側から見た報酬 r を書く。
  - 相手の直前の手の行に −r を書く。
  - 両方の行に終局の印を付ける。
- 【一次】λ-return を2種類使う（buffer.py:194-230, 351-357。γ=1）:
  - TD(λ=0.8): 価値の目標 ξ。3クラスの分布の凸結合。
  - GAE(λ=0.5): A。期待値 [-1,0,1] で集約したスカラーの δ を累積する。
- 【一次】価値と μ は、**収集時の値を再計算しない**。
  - 行動するネットと学習するネットは同じ（rl.py:157-158）。
  - そのため1回の収集の中では、後のミニバッチほど比の分母が古い（最大 199 歩）。
- 【一次】env は回をまたいで続く。区切りの末尾は、最新の組の価値で 1-step bootstrap する（buffer.py:221-230, 354）。

### 1.3 絞り込み

- 【一次】`threshold = max(quantile(|A|, 0.75), 0.01)`、`adv_mask = ¬終局後 ∧ |A| ≥ threshold`（buffer.py:232-241）。符号は見ない。
- 【一次】分位点の母集団は、**環状バッファ全体**。
  - 中身は約21回分の収集、両プレイヤー、古い価値で計算し直した行、立ち上がりの 0 の行。
  - rank ごとに計算し、all-reduce はしない（rl.py:510-512 でそろえるのは n_batch の MIN だけ）。
- 【実測（data_path 担当の模擬）】準備済みの行のうち通る割合は、最初の約5回が約98%、約21回目から約25% で安定（玩具の env）。
- 【実測・批判側】この絞り込みは、クーンポーカーで期待値の更新の固定点を均衡から外す。仕組みと本線での扱いは 2.6。

### 1.4 収集とミニバッチ

- 【一次】1回の収集は、全 env が 200 手番進む分（初回は 202）。
  - 1行を1ミニバッチにする。行はシャッフルして1回ずつ使う（1エポック）。
  - 1回あたり最大 200 歩（buffer.py:186-192, 254-285、rl.py:510-518）。
  - **1回の歩数を固定し、1歩の標本数のほうが変わる**。
- 【一次】EMA（評価用、0.999）は、**収集1回に1回**だけ更新する（rl.py:612）。
- 【二次】論文: GPU あたり 1,536 局、202 手、16 GPU。フィルタ後のバッチは「1/4 以下」（v2 p41, p44-45、表 S3・S7）。
  コードの既定は `num_envs=1600`（`scripts/train/rl_main.py:46`）で、論文と少し違う。

### 1.7 論文から分かったこと・分からなかったこと

分かったこと【二次】:

- 中心の考えは「正則化の強さと更新幅を連動させる。序盤は強く大きく、終盤は弱く小さく」（v2 p4, p13）。
  - 論文は「軌跡の重要度の重み付けや、方策の平均化が要らなくなる」と書く（p13）。
  - R-NaD という語は本文に無い。
- 更新幅は4つで抑える: 収集方策への逆KL・比のクリップ・勾配ノルムのクリップ・学習率（p13）。
- 絞り込みの効果（p13、p20）:
  - 1回の壁時計が約2.5分の1になり、サンプル効率と最終性能も上がった（p13）。
  - 外すとエントロピーが大きく上がり、サンプル効率が大きく下がる（Ext Data Fig. 5 のキャプション、p20）。
- アブレーション（1 H100、約48時間。p20）:
  - フィルタなしは 43h で Elo 1320。対照は同じ時刻で約1680。
  - 正則化の係数を減衰させないと、全区間で得点 −1.0。
  - 学習率を減衰させないと、後半でやや劣る。
- 学習中の記録（Fig. S3/S4、p51-52）:
  - 収集方策への KL: 0.013 → 0.002 nats
  - クリップ率: 15% → 2.5%
  - クリップ前の勾配ノルム: 0.7〜1.4 → 約0.28。上限が 0.267 なので、終盤も多くの歩でクリップが効く
  - エントロピー: 1.8 → 1.2
  - 磁石への KL: 1.75 → 2.6

### 2.3 手番の構造と GAE・TD(λ) の定義

- プレイヤー k の決定点を、時刻の順に i = 1..n とする（時刻 t_i、局 b）。
- 次の自分の決定点を t_{i+1} とする。反則なら t_i+1、通常は t_i+2、相手が反則を重ねればもっと後になる。
- V_i = `v_actor`（t_i）。γ = 1。

```
r_i   = Σ_{t = t_i}^{t_{i+1} − 1} reward[t, b, k]      （最後の決定点は局の終わりまでの和）
δ_i   = r_i + [i < n]·V_{i+1} − V_i
A_i   = δ_i + λ_A·[i < n]·A_{i+1}                         λ_A = 0.8（既定。2.3 の末尾と 5(a)）
G^λ_i = r_i + [i < n]·((1 − λ)·V_{i+1} + λ·G^λ_{i+1})     λ = 0.8（価値の目標）  ＝ A^λ_i + V_i
```

- **反則で同じ側が続く**: 反則の行の次の自分の決定点は t_i+1（指し直し）。その間の報酬は 0。
  反則の損は、指し直しの局面の価値の下がりとして入る。
- **λ は試行ごとにかかる**（既定、判断）。
  - 反則の試行も1つの決定点として、λ が1回かかる。
  - 反則を2回挟む手番では、その前の手番へ届く信用が λ² だけ余分に減る。
  - 【実測・批判側】96局 seed 5 と 192局 seed 7 で測った。
    - 反則の行の前後で、V は平均 −0.090〜−0.096 下がる。
    - 反則の行は全体の 11.9〜12.7%。
    - 75%点で選ばれる率は、反則の行 33%、他の行 24%。
  - 別案 `--mmd-lambda-unit turn`: 受理された手ごとに λ を1回かける。
    - 反則の行だけ c=1 にした [T,B] のテンソルを `v_trace_scalars` に渡せばよい。
    - c はテンソルを受け付ける（`rnad/rnad.py:213` の説明、`:554` の使用例）。新しい再帰は要らない。
    - その代わり、反則の行の A に指し直しの手の A が全部入る。反則した手の信用に、指し直しの雑音が混ざる【推測】。
  - 既定は試行ごとにする。
- **両者の終局報酬**: 本線の格子は、終局の行に両者の列で零和の報酬を入れる（`tsuitate-bot/src/rl/env.rs:124-130`、【実測】全局で検査）。
  - 終局の手を指さなかった側は、相手の手番の行に入った報酬を、自分の最後の決定点の r_i で受け取る。
  - Ataraxos の「相手の直前の手に −r を書く」書き換え（buffer.py:152-161）は要らない。
- **局の途中で切らない**: 最後の決定点は bootstrap しない（報酬だけ）。200手の引き分けは報酬 0 の終局。
- **実装**: `v_trace_scalars(v_grid, valid, player, 1, 1, 0, reward[:,:,k], k, eta=0, c=λ)` の vt が、G^λ_i そのものになる。
  - π=μ なので w=1・w_c=λ になる。相手の行は :246-250 で報酬を次の自分の手番へ運ぶ（`rnad/rnad.py:204-253`）。
  - 【実測】合成データ（反則の確率 0.15〜0.5・途中の報酬あり・長さ1の局）で、素直なループとの最大差は ≤2.4e-7。
  - 2つの λ × 2プレイヤーで4回呼ぶ。CPU・2スレッド・T=260・B=768 で約0.2秒【実測】。
- **自己対局に限る**: `v_trace_scalars` は、有効でない行で carry を 0 に戻す（:246-250）。
  - GPU リーグの局では相手の手番が隙間になり、途中の手番が終局扱いになる。
  - `tsuitate-bot/docs/rl-learning-speed.md:688-698` の不具合と同じ形。MMD は自己対局だけで使う。
- **λ_A の既定を 0.8 にした理由**（判断）:
  - 【一次・数式】価値の誤差を e とすると、A^λ = A_真 − e_i + (1−λ)·Σ_k λ^{k−1}·e_{i+k}。
    手に依存するのは後ろの項。λ=0.5 なら次の手番の価値の誤差の 0.5、λ=0.8 なら 0.2 を、手の良し悪しとして学ぶ。
  - 【一次】本線の R-NaD は c_vtrace=1.0（`rnad/rnad.py:305`、`rnad/train_rnad.py:190`）。
    π≈μ なので目標はほぼモンテカルロ（λ=1）で、価値の誤差は基準として入るだけ。λ<1 は、本線に無かった種類の偏りを持ち込む。
  - 【二次】序盤の V はほぼ無情報（|V| 平均 0.03・AUC 0.55、`tsuitate-bot/docs/rl-deepnash-design.md:1340-1341`）。
    R-NaD で c=0.9 の λ-リターン（V2）を試したときも、序盤のまれな手で A の符号が反転した（`tsuitate-bot/docs/rl-learning-speed.md:577, 588`）。
  - 【推測】Ataraxos で 0.5 が効くのは、価値ネットが 1,478万パラメータと大きいからかもしれない。本線は 54.5万（probe_scale.json の nparams）。
  - 【実測】雑音の面では、0.8 は 0.5 より少し不利。pps 0.25 の2次モーメント比は、0.8 で 1.83〜1.84、0.5 で 1.61〜1.64（2.6.2）。
  - 0.5 にする条件は 5(a) に書く（同じ局での期待勾配のコサイン）。

### 2.5 磁石: 出発点の方策と一様の混合（判断）

```
ρ(a|x) = (1 − ε)·π_init(a|x) + ε / |L(x)|        ε = 0.03、π_init = 始めたときの ck['target'] を凍結した写し（magnet_net）
```

- **一様と二段を既定にしない理由**【実測・批判側】（v7・192局 seed 7、`probe_bias_v7.py`）:
  - 合法手に一様だと、質量の 39% が打ちに乗る（π では 21%）。とくに銀打ちが 14%（π では 4%）。
  - 二段の一様だと、歩に 34%（π では 23%、一様では 10%）、香に 10%（π では 0.04%）が乗る。打ちの偏りを、歩と香の偏りに替えただけ。
  - 磁石の項のうち向きのそろった部分は、α=1 あたり一様 1.27、二段 2.73。m=256 と m=1,024 のノルムから外挿した。
    - 同じ α でも、二段は約2.1倍強く引く。
    - Ataraxos の α の値は、合法手に一様な磁石（rl.py:105）で作られている。
  - 今の π を磁石の固定点のままにするのに要る Q の差を測った（最善手と2番手、log-odds×α）。
    - α=0.05: 中央値 0.14、90%点 1.3〜2.0。価値の幅は 2 なので、90%点はありえない値。
    - α=0.005: 中央値 0.014、90%点 0.13〜0.20。
  - 【推測】一様・二段の磁石は、強い方策を始めから一様（二段なら歩と香）の側へ系統的に引く。
    - α=0.005 で、向きのそろった引きは 0.006〜0.014。
    - 方策の項の期待勾配が R-NaD 並みに小さければ、同じ桁になる（5(a) で測る）。
  - 【二次】Ataraxos の学習の終わりでも、磁石への KL は 2.6（論文 Fig. S4）。v7 は始めから 3.5〜3.7（一様・二段）。
- **混合を推す理由**:
  - 始めた時点では π ≈ π_init なので、磁石の勾配はほぼ 0。学習の頭で方策を引き戻さない。
    π が動くと引き戻す。信頼領域に近い働きをする。
  - 固定点は π ∝ ρ·exp(Q/α)。α=0.005 なら、Q の差 0.01 で log-odds が 2 動く。
    意味のある大きさの A（|A| 平均 0.12）には、事実上縛られない【推測】。
  - 【二次・推測】MMD 論文の定理3.4 は、正則化項が鏡写像に対して強凸であればよい。内点にある固定の磁石への KL は、これを満たす。ε>0 で内点になる。
    docs の T8（`tsuitate-bot/docs/rl-learning-speed.md:573`、固定の磁石＋η の減衰）と同じ形。
  - 費用: 残した行で、凍結したネットの順伝播が1回増える（2.12）。magnet_net は checkpoint に入れる（4.4）。
- 別案（`--mmd-magnet`）:
  - `twostage`（論文の形）: 使うなら、α を一様のときの約半分に読み替える（引く強さが約2.1倍のため）。
  - `uniform`（Ataraxos のコードの既定）: ataraxos preset で使う。
  - `target`（現在のネットの EMA = 動く磁石）: MMD 論文 H.5 の形で、R-NaD の段階に近い。証明は無い（MMD 論文 p41）。
- **「現在の方策」を磁石にはしない**。
  - KL(π‖π_現在) は、収集方策への KL と同じ近接項になり、固定点への引きが消える。
  - MMD の正則化が無い鏡像降下は、ゲームで周回しうる。MMD 論文の定理3.4 は α>0 が必須。
- 【推測】混合の磁石は、A/B の間（約1.4万更新）、方策を v7 付近につなぎとめる側に働く。
  採用した後に磁石をいつ入れ替えるか（固定のまま・段階ごと・EMA）は、まだ決めていない（7節）。

| なし（一様から） | 0.038 | 0.011 | 0.0053 |
| 全体の 75%点（一様から） | 0.665〜0.670 | 0.668〜0.676 | 0.674〜0.679 |
| 全体の 75%点（均衡から） | 0.013〜0.48 | 0.46〜0.53 | 0.48〜0.53 |
| 全体の 50%点（一様から。最後 / 後半の平均） | 0.022 / 0.022 | 0.057 / 0.008 | 0.15 / 0.004 |
| 情報集合ごとの 75%点（一様から / 均衡から） | 0.009 / 0.009 | 0.317 / 0.004 | — |

- 範囲には、しきい値で硬く切る版と、滑らかに切る版（幅 0.02）の両方を含む。
- 絞り込みなしは、α に比例して下がる（α-QRE）。75%点は、α を下げても下がらない。
- 50%点は平均では悪くない。しかし α=0.01 では最後の点が振れている（周回）。
- 情報集合ごとのしきい値も、α=0.02 を一様から始めると 0.317 で止まる。
- 仕組み【実測・批判側】:
  - K を持つ側の手番は、どれも |A| が全体のしきい値 0.61 に届かない。選ばれないので、方策も磁石も動かずに凍る。
  - 先手の J では、check の A=+0.47（毎回同じ値）が切られる。残るのは、bet が通った稀な局の A=+1.47 だけ。
    真の価値は check のほうが 0.47 高いのに、方策は bet 100% へ進む。
- 一般の形【推測・数式】:
  - ソフトマックスの期待勾配は dz_b = π_b·(g_b − Σ_a π_a g_a)、g_a = E[A·1{選ばれる} | I, a]。
  - 全部の手に同じだけかかる偏りは、この式で消える。
  - 消えないのは、**手によって A のばらつきが違うとき**。ばらつきの小さい（確実な）手の A は切られ、ばらつきの大きい手の外れだけが残る。
  - 本線では、反則や駒取りのように結果が大きく振れる手ほど選ばれやすい（反則の行 33%、他の行 24%）。
- v7 での非対称【実測・批判側】（96局・192局）:
  - 選んだ行のうち A>0 の割合は、V>0.1 の帯で 41〜48%、V<−0.1 の帯で 50〜61%。
  - 勝っている局面では悪い結果だけが、負けている局面では良い結果だけが残りやすい。
- 初版は「選んだ決定点が ΣA² の 91% を持つ」を利点として書いた。
  - 実際には**雑音の 91% を残す**という意味になる。雑音はほとんど減らない。
  - かわりに、小さく確実な信号のほうを捨てうる。
- 【推測】固定パネルとガントレットは、「搾取されやすい点に落ちた」ことを測れない。
  偏った絞り込みは、物差しに出ない形で悪くなりうる。

#### 2.6.2 既定: 比例確率の不偏な間引き（pps）

```
p_i = clip(|A_i| / c, floor, 1)        floor = 0.05
c   : mean_i p_i = rate になる値を二分法で決める（その更新の全決定点・両者。決定的）
残す : 学習器の乱数で Bernoulli(p_i)
重み : w_i = s̄ / p_i、s̄ = mean_i p_i（= rate）
```

- **不偏**【数式】:
  - E[Σ_残す w_i·ℓ_i] = s̄·Σ_全行 ℓ_i、E[残す数] = s̄·N。
  - よって、残した行の重み付き平均（÷ 残した数）は、期待値で全行の平均と同じ（比の推定なので O(1/N) の差を除く）。
  - 方策・KL・磁石・価値の全項に同じ重みを掛ける。だから更新は、期待値で「絞り込みなし」と同じになる。
  - クーンの固定点（α-QRE）は変わらない。
- **重みは有界**:
  - w ≤ s̄/floor = 5（rate 0.25 のとき）。
  - 方策の項の1標本は |A|·w ≤ s̄·max(c, |A|)。1/μ のような際限のない項は無い。
- **考え方は、本線の S7（不偏な間引き、`tsuitate-bot/docs/rl-learning-speed.md:576`）と同じ**。
  Ataraxos の「大きい |A| に計算を寄せる」利点は残し、固定点は動かさない。
- 【実測】v7 で測った（`rl_deduce_v7.bin`、96局 seed 5 / 192局 seed 7、CPU 2スレッド、`probe_pps.py`）:

| λ_A | rate | c | p=1 の行 | 下限の行 | 2次モーメント比 R | 残る確率: 残り80手番以上 / 0〜10 | 反則の行 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0.5 | 0.25 | 0.45〜0.47 | 3.8〜3.9% | 26〜28% | 1.61〜1.64 | 0.13〜0.16 / 0.49〜0.50 | 0.30 |
| 0.8 | 0.25 | 0.69〜0.72 | 2.9〜3.0% | 22〜23% | 1.83〜1.84 | 0.12〜0.15 / 0.52〜0.54 | 0.31〜0.32 |
| 0.95 | 0.25 | 1.60〜1.65 | 0.0〜0.2% | 9〜10% | 2.74〜2.78 | 0.12 / 0.33〜0.34 | 0.28 |
| 0.5 | 0.5 | 0.16 | 25% | 10% | 1.07 | 0.31 / 0.78 | 0.63 |
| 0.8 | 0.5 | 0.26 | 23% | 9% | 1.11 | 0.28 / 0.81 | 0.63 |

  - rate 0.5 の行は 96局だけで測った。
  - R = Σ A²/p ÷ Σ A²。「行ごとの勾配の大きさが同じなら、全行を使う場合の何倍の雑音か」を表す。
  - 計算は rate 倍になる。だから計算あたりの雑音は、rate 0.25 で全行の 0.40〜0.46倍（比は実測、勾配への当てはめは推測）。
- 75%点で切る絞り込みと比べると:
  - 75%点が選ぶ「残り80手番以上」の行は、0.08〜0.12（λ 0.5）・0.06〜0.10（λ 0.8）・0.02〜0.03（λ 0.95）しかない。
  - pps は 0.12〜0.16 を残し、しかも重みで戻す。
- 序盤の行は重みが大きく、その分だけ雑音を持つ。偏りは無い。

#### 2.6.3 割合 rate の決め方（判断）

- 候補は 0.25 / 0.5 / 1（= 全行、絞り込みなし）。
- 6.0c の bench で、割合ごとに MMD の1更新の秒を測る。
  「更新の秒 ≤ 0.9 × 収集の busy の秒」を満たす**最大の割合**にする。
- 理由: 更新が収集に隠れるなら、計算を減らしても壁時計は縮まない。雑音だけが増える（R が 1.6〜1.8倍）。
- どの割合も満たさなければ 0.25 にする。
- CPU の診断と P2 は 0.25 で回す。CPU では更新が律速なので、計算の得がそのまま出る。

#### 2.6.4 価値の損失を取る行（判断）

- 既定は `auto`。
  - pps なら、方策と同じ行・同じ重みで学ぶ（不偏）。
  - quantile なら、無作為の 25%（`uniform:0.25`）で学ぶ。
  - Ataraxos どおりの `filtered`（選んだ行だけ）は、ataraxos preset だけで使う。
- 根拠【実測・批判側】（`probe_bias_v7.py`）: v7 の V の帯ごとの mean(G_td0.8 − v)（96局 seed 5 / 192局 seed 7）

| V の帯 | 全行 | 75%点で選んだ行 |
| --- | --- | --- |
| > 0.6 | −0.036 / −0.024 | −0.134 / −0.071 |
| < −0.6 | +0.022 / +0.014 | +0.180 / +0.123 |

  - 中間の帯でも、選んだ行の残差は全行の 2〜5倍で、0 の側を向く。
  - 選んだ行だけで学ぶと、確信のある局面の価値が 0 へ縮む。
- 玩具【実測・批判側】（`value_filter_bias.py`。MC・表形式、結果 ±1）:
  - 決着の付いた状態（真の |値| > 0.6、平均 0.89）で、選んだ行だけで学ぶと V は 0.26 まで縮んだ。
    A に雑音 0.2 を足すと 0.41、0.4 なら 0.54。
  - 絞り込みなしなら 0.89 のまま。
  - それでも全体の傾き（結果を V へ回帰）は 1.16〜1.53 で、初版の門 [0.7, 1.6] の中に収まった。**全体の傾きでは見張れない**。
- 【推測】λ_A<1 の GAE は、δ = r + V′ − V を通して V の偏りを A に直接入れる。期待値で消える基準値の偏りとは違う。
  - TD(0.8) は次の価値で継ぐので、終盤の縮みは中盤の目標へも伝わる。
  - rl_search の η=30 の較正（`tsuitate-bot/docs/rl-deepnash-design.md:1338-1339`）もずれる。
- 【推測】不完全情報では、選ばれ方が隠れた局面と相関する。
  偏った行で学ぶと、V(I) は E[G | I] ではなく E[G | I, 選ばれた] を学ぶ。
- 見張りは帯ごとの較正にする（4.5 の `calib_band_*`）。
  初版の `calib_bias`（両プレイヤーの (z − v) の平均）は外した。自己対局ではほぼ打ち消し合い、対称に縮んでも 0 のままになるため。

#### 2.6.5 分位点の窓（quantile のときだけ）

- 既定は1更新だけ（`--mmd-filt-window 1`）。Ataraxos の「約21回分」は traj_len の副作用に見えるので、写さない。
- 窓を使うなら、過去 W 回の |A| を学習器が持ち、checkpoint に入れる（20回×6.5万×4B ≈ 5MB）。
- pps は窓を持たない。c はその更新の |A| だけで決まる。

#### 2.6.6 方策の項の倍率（判断）

- フラグは `--mmd-pol-scale`、既定は 1。
- 【推測】Ataraxos の絞り込みには、方策の項を強める働きもある。
  - 方策の項を「選んだ行（平均 |A| が全体の 2.7倍）」で平均する。
  - 正則化の項（磁石・KL）の1行あたりの大きさは変わらない。
  - そのため、正則化に対して方策の項を約 2.7〜4倍強める。外すとエントロピーが上がる、という Ext Data Fig. 5 とも整合する。
- pps は全行の平均の尺度になる。同じ α・kl_coef なら、Ataraxos より正則化が 2.7〜4倍強く効く。
- 既定は 1 にする。初期の動きを小さくする側に倒すため（2.7 と 6.1 の歩幅の懸念）。
  倍率を変えても、固定点が α/pol_scale の QRE になるだけで、偏りは生まれない。

### 2.7 ミニバッチと歩数（判断）

- 既定: **1更新の歩数 k = 8 に固定**（`--mmd-steps 8`）。
  - 残した行を無作為に並べ替え、ほぼ同じ大きさの8個に分ける（`array_split` と同じ割り方）。端数のバッチは作らない。
  - 理由1: Adam は、1歩の大きさをバッチの大きさによらずほぼ一定にする。端数の小さいバッチがあると、その標本だけ数倍の重みで動く。
  - 理由2: 行の数（局の長さ）は学習で変わる（117手から 60手台まで縮む）。歩数が行の数に連動すると、1更新あたりの実効の学習率が揺れる。
  - Ataraxos も、1回の歩数（行の数）を固定し、1歩の標本数のほうを変えている（1.4）。
  - 1歩の標本は、残した行 ÷ 8。rate 0.25 で約2,000、0.5 で約4,000、1 で約8,000。
- **逆伝播はチャンクに分ける**（`--mmd-chunk 2048`）。チャンクごとに逆伝播して勾配を足し、最後に1歩進める。
  - 【実測・批判側】（`act_mem.py`）: 64ch×6・91枚で、逆伝播のために保存する量は 0.65MB/標本。2,048 で約1.3GB、8,192 で約5.3GB。
  - これに pipeline の収集・残した行の観測・cuDNN の作業領域・WSL の表示が重なると、8GB を超えうる。
  - bench で `torch.cuda.max_memory_allocated` を出す。
- 2,048 の根拠: Ataraxos の1歩の標本は、1 GPU のアブレーションで約384、最終 run（16 GPU 合計）で約6,100【二次からの計算】。2,048 はその間。
- k=1 にはしない。1歩だと π=μ なので、KL とクリップの勾配が 0 になり、信頼領域の項が働かない【一次・数学】。
- 並びは無作為にする（判断）。Ataraxos の「1時刻・1プレイヤー」は、infostate を行ごとに作り直す計算の都合と見る【推測】。
- 【実測】v7・ミニバッチ m での方策の項の勾配ノルム（π=μ、3回の平均、BN を畳んだ `.bin` の形）:
  - m=256 で 1.02、512 で 0.67、1,024 で 0.46。
  - 1/√m にほぼ比例するので、**この大きさのミニバッチの勾配はほぼ雑音**。
  - Adam では、雑音が律速のとき k 歩 ≈ 学習率 √k 倍になる（`tsuitate-bot/docs/rl-learning-speed.md:580` の V4 の棄却理由）。
  - k は CPU の診断 (a) の B_noise で決め直す（5節）。
- 別案: k=32（Ataraxos の 1 GPU に近い）、k=2。`--mmd-epochs 2` も選べる（Barrage は2、dou dizhu は4）。

### 2.8 損失の実装

- 合法手に詰めた [m, K] で計算する（`_pack_csr`、`rnad/rnad.py:125-137`）。
  - 非合法手は列に現れないので、Ataraxos の NaN の罠は起きない。
  - 対数確率は `legal_log_policy`（`rnad/rnad.py:105-108`、マスク外は 0）。
- 残した行は飛び飛びになる。CSR を行ごとに拾い直す `gather_csr`（integration 担当の案）を足す。μ の対数確率も、同じ並びで [m, K] に散らす。
- **decoupled PPO**（`--mmd-decoupled`、既定 on。pipeline なしでは何もしない）:
  - 【一次】pipeline の batch は、1更新前のネットで集める（`rnad/rnad.py:1311, 1351`）。
  - μ をクリップと KL の中心にすると、問題が2つ出る。
    - 更新 t の頭では θ_t ≠ θ_{t−1}。KL の項が、前の更新を戻す向きの勾配を持つ。
    - 信頼領域も1つ古い方策の周りになる。前の更新ですでに比が 1±0.2 を出た標本は、勾配が消える。
  - 【二次・この作業では本文を読んでいない】Hilton ら 2021（Batch size-invariance for policy optimization）の decoupled PPO を使う。
    「近い方策」π_prox をクリップと KL の中心にし、μ との比は外側の重要度の重みにする。
  - 更新の頭で、残した行の log π_{θ_t} を勾配なしで1回求める（rate 0.25 なら 0.25 回分の順伝播）。
- 式（ミニバッチ m 行。重み w は 2.6、価値の行の重み w_v は 2.6.4）:
  ```
  # 更新の頭（勾配なし、残した行だけ）
  lp_prox = log π_{θ_t}(·|x)                       # pipeline なしなら mu_lp と同じなので計算しない
  log ρ   = log((1 − ε)·π_init(·|x) + ε/|L|)       # mix の磁石（magnet_net を1回）
  is      = min(exp(lp_prox[a] − mu_lp[a]), 2.0)   # 外側の重要度。上限 2 に当たった割合をログ

  # 各歩
  ratio = exp(lp[a] − lp_prox[a])
  pol   = −Σ w·is·min(A·ratio, A·clip(ratio, 1−0.2, 1+0.2)) / m
  kl    = Σ w·Σ_a p·(lp − lp_prox) / m              # 合法手の全体。中心は θ_t
  mag   = Σ w·Σ_a p·(lp − log ρ) / m
  lv    = Σ w_v·(v − G_td)² / m_v
  loss  = pol_scale·pol + α_t·mag + vf·lv + kl_coef·kl
  ```
- pipeline なしなら lp_prox = mu_lp・is = 1 になり、Ataraxos の式（重み w を除く）と同じになる。
- 上限 2（`--mmd-prox-cap`）は判断。上限に当たる割合が数% を超えるなら、古さが想定より大きい。

### 2.9 最適化器と勾配ノルムのクリップ

- Adam（β1 0.9、β2 0.999、eps 1e-8、wd 0）。
  R-NaD の Adam（β1 0、eps 1e-7、`rnad/rnad.py:354`）とは別物。状態は持ち込まない（3節）。
- 勾配ノルムのクリップ。決めるまでの仮の値は 0.267（忠実）。
  - 【実測】v7 の `.bin` の形では、m=1,024 の全損失の勾配ノルムは約0.8（α=0.005）。0.267 だと**毎歩クリップされる**。
  - ただし `.bin` は BN を畳み込んだ形で、学習に使う `checkpoint.pt` の形とはノルムが違う。
    測った対象もターゲットで、A/B で学ぶ `ck['net']` ではない。
  - **6.0c で checkpoint.pt の net から測って決める**。目安は「クリップされる歩が 10〜50%」。論文の終盤は中央値 0.28 で、約半分の歩がクリップされる。
  - Adam は1歩の大きさを正規化するので、常時クリップでも壊れはしない。効くのは、スパイクへの頑健さ【推測】。

### 2.10 学習率と温度の予定

```
t     = (step_count − mmd_t0) × t_scale          # MMD を始めてからの更新（= 収集）回数。t_scale 既定 1
lr    = A/B では固定（--mmd-lr <lr>,0,<lr>,<lr>）
        ataraxos preset は clip(0.5 / (t + 1)^1.1, 5e-6, 1e-4)
α(t)  = clip(0.05 / (t + temp_t_off + 1)^0.3, 0.001, 0.1)       temp_t_off 既定 2000
```

- **A/B の学習率は固定する**（判断）:
  - 【計算】Ataraxos の学習率は、MMD の t=2,304 から下がり始める。
    13,000更新で 1.5e-5（本線の 1e-4 の 1/6.7）になり、約35,000更新（約50時間）で下限の 5e-6 に着く。
  - 【二次】本線の docs には「雑音の多い領域で、後半に効いたのは学習率を下げるほう」とある（`tsuitate-bot/docs/rl-learning-speed.md:160`）。
  - 15時間の A/B に減衰を入れると、MMD の効果と焼きなましの効果が混ざる。焼きなましは R-NaD にもかけられる（T7、同 :579）。
  - 固定の値は 1e-4（本線と同じ）。P2 の学習率の腕（5(c)）か Phase A の歩幅の検査（6.1）で下げることになったら、その値で固定する。
  - 学習率の減衰は、MMD を採用した後の別の A/B で決める。
- **t の数え方と、Ataraxos との連動のずれ**:
  - t は「収集の回数」。本線の `step_count`・書き出しの名前・パネルの横軸と同じ数え方。
  - 【一次】Ataraxos の1回は最大 200 歩（rl.py:510-518）、本線は 8 歩。
    温度を同じだけ下げる間の Adam の歩数は約1/25 になり、「正則化と更新幅の連動」（論文 p4, p13）からずれる。
    【推測】ずれは安定な側に出る（正則化が下がる間に動ける量が少ない）。
  - ただし起点を 2,000 ずらすと、A/B の窓（約1.4万更新）の中で温度はほとんど動かない。
    - t_scale 1: 0.0051 → 0.0028
    - t_scale を「歩数÷200 ≈ 0.04」にした場合: 0.0051 → 0.0049
  - A/B の結果は t_scale にほとんど依らない。`--mmd-t-scale` は残す。
- **温度の起点を 2,000 ずらす**（判断）:
  - 2.5 の「今の π を固定点のままにする Q の差」を見ると、α=0.05 では 90%点がありえない大きさ。α=0.005 なら妥当。
  - 混合の磁石では、始めの磁石の勾配がほぼ 0 なので、起点の効きは小さい。一様・二段の腕と予定をそろえるために残す。
  - 上限の条件（5(a)）: 方策の項の期待勾配 |G_pol| が α·|G_mag| の数倍（目安 3倍）以上ある α を上限にする。
    満たさなければ、起点をさらにずらす。
  - 別案: 起点 0（忠実。論文は序盤の強い正則化を「エネルギーの蓄え」と書く、p13）。P2 の ataraxos preset の腕で見る。
- **採用した後の予定**（先に決める）:
  - t は戻さない。段階が無いので、戻す理由がない。
  - 温度は t^-0.3 で下限 0.001 まで下げる（約46万更新）。
  - 学習率は A/B と同じ固定値で続け、下げ方は別の A/B で決める。

- **配線**: 学習率は、`train_rnad.py` の `set_warmup_lr`（`rnad/train_rnad.py:448-458`）で決める。
  学習器の中で書くと、`--lr-warmup` と :630 のログが食い違うため。

    - **毎更新かならず lr を書く**。再開時の戻しも予定の値にする。

  深層版の学習率は定理の η そのものではない【推測】。A/B の固定の学習率では、この連動は無い。

### 2.11 ターゲット（書き出し用の EMA）・磁石のネット・BN

- ターゲット = 現在のネットの EMA（`target_avg 0.001` = 0.999）。
  - 更新は**1更新に1回**（Ataraxos の rl.py:612 と同じ。歩ごとではない）。
  - BN の buffers は写す（`rnad/rnad.py:445-448` と同じ）。
  - 書き出しはターゲット（`rnad/train_rnad.py:707`）。`--export-current` なら現在のネットも書き出す。
- MMD の学習はターゲットを使わない。R-NaD はターゲットを v-trace の価値と磁石に使う（`rnad/rnad.py:496`）。
- 磁石のネット（magnet_net）は、始めたときの ck['target'] を凍結した写し。学習も EMA もしない。
- BN は eval のまま。Ataraxos の `assert net.training`（rl.py:488）は写さない。
  train モードにすると BN の統計が動き、行動時と学習時がずれる。

## 3. R-NaD の checkpoint（rl_deduce_v7 相当）から始める手順

1. **区切りちょうどで止める**:
   - 【一次】`train_rnad.py` は checkpoint.pt を上書きするだけで、区切りごとの checkpoint は無い。
     `save_all` は `rnad/train_rnad.py:405`、ループの終わりの保存は `:715`。
   - 手で止めると、最後の `--checkpoint-every` の倍数まで戻る。pipeline で集めかけた batch も捨てる。
   - だから本線を `--steps 108000` で再起動し、自然に止まるのを待つ（最後に :715 で保存される）。
   - 別の方法: 区切りで `checkpoint_<step>.pt` を残す O1（`tsuitate-bot/docs/rl-learning-speed.md:557, 636-638`、5〜10行）を先に入れる。
2. **入口をそろえる**: 止めた直後の `checkpoint.pt` を写す。
   - `.bin` は使わない。BN を畳んだ形で、Adam の歩幅の幾何が違うため。
   - step を確かめる（`torch.load(...)['step']`）。
3. **ネットは3つ分けて読む**:
   - MMD の `net` ← `ck['net']`（行動していた現在のネット）
   - `target` ← `ck['target']`（書き出していた EMA）
   - `magnet_net` ← `ck['target']` の凍結した写し
   - こうすると、行動する方策が R-NaD の続きと同じになる。
   - `--pipeline` の収集の seed は `seed*1_000_003 + 17 + step`（`rnad/train_rnad.py:493`）。
     同じ `--seed` で step の番号を続ければ、**最初の batch が両腕で同じ**になる（収集に足すものは乱数を使わない【実測】）。
   - 最初の書き出しも、両腕で同じ版になる。
   - 今の `load_net`（`rnad/train_rnad.py:53-67`）はターゲットしか読まないので、読み込みを足す。
   - 【一次】`out/checkpoint.pt` があると、ネットの形は checkpoint から作り、`--init` は使わない（`rnad/train_rnad.py:318-324`）。
     MMD でも同じにし、`--init*` を無視したことを表示する。`mmd_t0` も checkpoint から読む。
4. **step の番号は続ける**: `step_count ← ck['step']`、`mmd_t0 ← ck['step']`。
   - 予定と warmup は `step − mmd_t0` で引く（2.10）。
   - 書き出しの名前（`policy_<step>.bin`）とパネルの横軸が、本線と同じ番号になる。
   - 取り違えを防ぐため、Release のタグには `mmd` を入れる（4.1）。
5. **読まないもの**:
   - `opt`: R-NaD の Adam は β1=0 で、2次モーメントが 1/μ のスパイクの大きさを覚えている（`rnad/rnad.py:799-802`）。
   - `prev` / `prev_`、`rng`。
   - 新しい Adam と `--lr-warmup 100` で始める。新しい Adam の最初の数十更新は大きく動く（`tsuitate-bot/docs/rl-learning-speed.md:240-241`）。
6. **価値の合わせ直し**（判断）:
   - 6.0c で、checkpoint.pt の **net と target の両方**について、帯ごとの較正を測る。
     - |v| の帯（0.6 以上など）ごとの mean(z·sign v) と mean|v|
     - 終局までの手番数の帯ごとの傾き
   - net で次のどちらかが起きていたら、`--mmd-value-warmup 200` で始める。
     - |v| ≥ 0.6 の帯の mean|v| が、mean(z·sign v) より 0.15 以上小さい（縮んでいる）
     - 残り80手番以上の帯の傾きが 0.5 未満
   - 助走では、幹と方策の頭を止め、価値の頭だけを**全行**の TD(0.8) で学ぶ。方策はビット単位で変わらない。
   - どちらも起きていなければ助走はしない。数字は判断なので、6.0c の結果を見て直してよい。
   - 【一次】R-NaD の価値の目標は、自分の手番で −η·KL、相手の手番で +η·KL を含む（`rnad/rnad.py:224-225, 236, 246`）。
     相手側の項は手に依存するので、A に入る。
     【推測】大きさは1手あたり 0.003 以下（η 0.2 × 段階の KL 約0.015）で、選ぶ行の |A| の約1%。無視してよい。
7. **温度の起点**: `--mmd-temp-t-off 2000`（2.10）。学習率は固定（`--mmd-lr <lr>,0,<lr>,<lr>`）。

#### 4.1.1 speedlab の追加（6.3 の物差しに要る）

【一次・実行で確認（批判側）】初版のコマンド `speedlab.py report out_rnad/deduce_s10000 out_rnad/mmd_ab --control deduce_s10000` では、対照との比較が1行も出ない。理由は次のとおり。

- run の名前の読み方が合わない。
  - `arm_of` は `deduce_s10000` を腕「deduce」・seed「10000」と読み、`mmd_ab` を腕「mmd_ab」・seed「0」と読む（`rnad/speedlab.py:364-366, 433-434`）。
  - `--control deduce_s10000` は腕の一覧に無いので、対照の節がまるごと飛ぶ（:508, :550）。
  - 腕名が合っても、seed が違うとペアにならない（:387）。
- `paired_section` は、同じ step 番号どうしでしか対にしない（:391）。主な物差しの「同じ壁時計」では比べられない。
- 最後の 4,096局を、学習ループの外で測る道が無い。
  - `speedlab eval` は CPU 固定（:44 の `DEV`、:298 で device を渡さない）。
  - スレッドは `OMP_NUM_THREADS`（既定 1、:589）だけ使う。
- 局数が違う結果は比較から外れる（:394）。ループ内の 1,024局と、後から測る 4,096局は対にならない。
  また `eval` は、(step, which, 相手) が済んでいれば飛ばす（:283, :292）。
- 起点の step（108,000）は両腕で同じネットなので、差 0 のペアが「step > 0 の全体」に入る（:391 で除くのは step 0 だけ）。
- 壁時計の累積は `collect_sec + update_sec` をそのまま足す（:346）。
  WSL の一時停止のような外れ値（1回 941秒、`tsuitate-bot/docs/rl-learning-speed.md:346`）も入る。

### 4.4 checkpoint の形

```
{"algo": "mmd", "net", "target", "magnet_net", "opt", "step", "mmd_t0", "cfg": dict(MMDConfig), "config": dict(net.config),
 "rng": rng_state(device), "filt_hist": [...]（quantile で窓 > 1 のときだけ）, "init_from": {"path", "step", "sha256"}}
```

- `load_net`（`rnad/train_rnad.py:53-67`）は、`"config"` と `"target"` があれば読める。
  そのため `--init`・`--anchor`・`distill.py` からそのまま使える。
- 再開時に `ck.get("algo", "rnad") != args.algo` なら止める。R-NaD の checkpoint を MMD として黙って再開しないため。
- 行の間引き（Bernoulli）とミニバッチの並べ替えには、学習器の乱数を使う。
  `rng` を checkpoint に入れて、再開を再現させる（pipeline なしのとき。4.6 の T8）。

### 4.5 ログの項目（log.jsonl、1更新1行）

- 既存のキーとの互換（`rnad/stage_log.py:121,130,154,166` が読む）:
  - `samples` は**集めた決定点の数**のまま。stage_log の「1,000標本あたり」を比べられるようにするため。
  - `loss_v`、`loss_nerd`（方策の損失を入れる）、`alpha`（1.0 固定）、`reg_update`（False 固定）、`lr`、`collect_sec`・`update_sec`・`collect_busy_sec`。
- MMD の項目:
  - 予定: `mmd_t`、`temperature`、`lr`（予定 × warmup と一致するかをテストで見る）
  - 行の選び方:
    - `rows_kept`・`keep_rate`（実際に残した割合）、`pps_c`、`w_max`、`adv_thr`（quantile）
    - `adv_abs_mean_all`・`adv_abs_mean_kept`
    - `kept_share_far`（終局まで80手番以上の行の残る割合）
  - 信頼領域:
    - `kl_mu`（歩の平均と最後の歩）
    - `kl_mu_unkept`（残さなかった行の無作為な 1/16 で測る、更新の後の KL(π_new‖μ)。勾配なしの順伝播）
    - `clip_frac`（|r−1| > clip の割合）
    - `ratio_dev_first`（最初の歩の |π_θ/μ − 1| の平均。本線の `ratio_dev_mean`（`rnad/rnad.py:459`）と同じ量）
    - `prox_is_capped`（外側の重要度が上限に当たった割合）
  - 勾配: `grad_norm_p50`・`grad_norm_p90`・`grad_norm_max`（クリップ前）、`clip_rate`（クリップした歩の割合）、`minibatches`
  - 方策: `entropy_mean`・`pi_top_mean`・`pi_top_gt_0999`（R-NaD と同じ定義）、`magnet_kl`
  - 価値:
    - `vf_change`（Ataraxos の rl.py:561-564 と同じく、学習後と v_actor の差）、`v_target_mean`

    - **`calib_slope_by_remain`**: 終局までの手番数の帯（0〜10・10〜40・40〜80・80 以上）ごとに、z を v へ回帰した傾き
    - **`resid_band`**: V の帯ごとの mean(G_td − v)。全行と、価値に使った行の両方
    - どれも batch の値から作るので、追加の計算はほぼ無い。初版の `calib_bias` は外した（2.6.4）
  - 時間: `gae_sec`、`train_sec`、`prox_sec`（近い方策と磁石の順伝播）

## 5. CPU での診断計画

- 規約: torch のスレッドは2まで。1回の実験は10分以内（長い代理は背景のキューで回す）。
- 順番: (b) の T0（数分）→ (a) → (a2) → (b) → (c)。

### (a) 学習なしの勾配の雑音と期待勾配の向き（`gradsnr.py` に `mmd:` 変種を足す）

- 変種の書き方: `mmd:lam=<λ_A>,filter=<none|pps:0.25|q:0.75>,temp=<α>,magnet=<mix|twostage|uniform>,part=<pol|val|mag|all>`。
- 中身:
  - 行動側の価値は、そのネットの価値を使う（:113 と同じ）。A は `v_trace_scalars(eta=0, c=λ)` で作る。
  - 行の選び方は、全局の |A| で1回だけ決める。
  - 局ごとに「その局の残した行の重み付き損失 ÷ 全体の残した行の数 × 局数」で逆伝播する（:167 の単位とそろえる）。
  - π=μ なので、PPO の項の勾配は −w·A·∇log π(a)、KL の勾配は 0。
- 規模: `rl_deduce_v7.bin`、256〜1,024局。|G|² が出なければ増やす。
- 出すもの:
  - trΣ・|G|²・**B_noise（局）**。B_noise は損失の定数倍によらない。`cos_ref` と `eff_snr` は目的が違うので読まない。
  - **変種どうしの期待勾配のコサイン**（新規）。
    - 同じ局の雑音は変種の間で相関するので、標本平均どうしの内積は使わない。
    - かわりに U 統計量 (Σ_i g_a,i · Σ_j g_b,j − Σ_i g_a,i·g_b,i) / (n(n−1)) で G_a·G_b を推定する。
      局ごとの勾配の内積から、同じ局どうしの項を除いたもの。
    - |G_a|²・|G_b|² も同じ形で出す。和だけを積み上げるので、局ごとの勾配を持たなくてよい。
- 腕（同じ局で並べる）:
  - 参照: `ref`（NeuRD、既存）、`pg`（既存）、`mmd:lam=1,filter=none,temp=0,part=pol`（MC）。
    MC の腕は `pg` と |G|・B_noise が近いはずで、実装の検算になる。
  - λ: `lam ∈ {0.5, 0.8, 0.95}` × `filter=none`、`part=pol`
  - 選び方: `lam=0.8` × `filter ∈ {pps:0.25, q:0.75}`、`part=pol` と `part=val`
  - 磁石: `part=mag`（`magnet ∈ {mix, twostage, uniform}`、α=1）
- 比べる相手（`tsuitate-bot/docs/rl-learning-speed.md:10-12, 112-131, 685`）:
  - R-NaD の参照は、v4 で B_noise 9,000〜17,600局。
  - v7 では、段階の頭で |G|² を検出できない（≥約7×10⁴局）。
- **判定**（k = 1更新の歩数 = 8）:
  - **k**:
    - B_noise ≤ 768/k ≈ 100局: ミニバッチの勾配が信号で決まる。k 歩の利得は k 倍に近いので、8 のまま。
    - 100 < B_noise ≤ 768: k を 2〜4 に減らす。
    - B_noise > 768: 雑音が律速のまま。利得は計算とスパイクの無さだけと見込む。それでも (b)(c) が良ければ A/B は回す。
  - **λ_A**: λ=0.5 と 0.95 の |G| がどちらも検出でき（|G|² が標準誤差の2倍以上）、コサインが 0.8 以上なら 0.5 にする。
    検出できない、またはコサインが低いなら 0.8 のまま。
  - **行の選び方**:
    - `pps` と `none` のコサインは、期待値で 1 のはず。|G| が検出できて 0.9 未満なら、実装を疑う。
    - `q:0.75` と `none` のコサインが 0.8 未満なら、本線でも絞り込みの偏りが出ている証拠になる（pps の既定を支える）。
  - **温度の起点**: `part=pol` の |G_pol| が、α·|G_mag|（向きのそろった部分）の 3倍以上ある α を上限にする（2.10）。
  - |G| が検出できなければ、λ と選び方の判定は保留し、既定（λ 0.8・pps）のまま進む。
  - 初版の「選んだ行が ΣA² の 91% を持つ」は判定に使わない。雑音の量であって、信号の量ではない。

### (a2) 価値の行の偏りの玩具（批判側の `value_filter_bias.py` を TD(0.8) の形に直す）

- 中身: 鎖の状態（終盤寄りと中盤を混ぜる）、結果 ±1、TD(0.8) の目標。
  価値の行を `filtered`・`uniform:0.25`・`pps`（重み付き）・`all` の4通りで回す。
- 出すもの: 決着の付いた状態の mean|V| と真の値の比、帯ごとの残差、全体の傾き。
- **判定**: `pps` と `uniform:0.25` が `all` と同じ値（±0.02）に着けば、2.6.4 の既定でよい。`filtered` の縮みは記録だけする。
- 費用: CPU で数分。

### (b) クーンポーカーの厳密な NashConv（`toy_kuhn.py` に MMD を足す）

- 先に T0（標本なしの期待値の更新）を回す。確かめるのは2つ。
  - 絞り込みなしが α-QRE に着くこと（実装の健全性）。
  - quantile 0.75 が既知の点で止まること。
- 足すもの:
  - `collect_kuhn` に `v_actor`（表の価値）と `mu_logp`（`log_softmax` から）。`mu_a` は :159 で 1e-30 に下限があるので使わない。
  - CSR（`legal_cols=[0,1]`・`legal_counts=2`）。
  - `MMDLearner` は `TabularNet` をそのまま回す（:62-70）。
  - 収集は numpy でまとめて速くする（10分の枠に入れるため）。
  - Kuhn は手番が必ず交互なので、反則の構造は T1 で押さえる。
- **R-NaD と同じ標本数**で回す: 512局/更新 × 6,000更新・seed 3本。
  - R-NaD の参照は、学習率 1e-2・Δm 500・ターゲット 0.01 で、後半 3,000更新の NashConv（ターゲット）0.0163 ± 0.0009（`tsuitate-bot/docs/rl-learning-speed.md:181-202`）。
  - R-NaD も同じ seed で回し直して、曲線を並べる。
- MMD の腕の共通設定（判断）: ミニバッチは k=5 等分。学習率は上限 1e-2 を約200更新保つ形（`coef=1e-2·201^1.1≈3.4`）、下限 5e-4。磁石は、クーンでは一様。
  - M1: pps 0.25（既定の選び方）
  - M1n: 絞り込みなし
  - M1q: quantile 0.75（Ataraxos）。
    - **更新ごとに、実際に選ばれた割合をログに出す**。クーンは |A| に同じ値が多く、「≥ しきい値」の割合が 25% から大きくずれうる。
    - 同値を乱数で切って、ちょうど 25% を選ぶ版も並べる。
  - M1h: quantile 0.5
  - M3: **絞り込みなし**＋温度を固定（0.05）。T0 の α-QRE の厳密値 0.038 と比べる（健全性の確認）。
    絞り込みを入れたままだと α-QRE で止まらないので、M3 には使わない。
  - M4: 温度の予定を2通りに振る（coef 0.2、decay 0.5）
  - （任意）M5: 1更新の局を 8,192 にした「ほぼ期待値」の腕。標本の雑音とアルゴリズムを分ける。
- 測るもの（250更新ごと）: NashConv（ターゲット = EMA、現在のネット）、最小の手の確率、エントロピー、実際に残した割合。
- **判定**（先に決める）:
  - M1 と M1n の後半の NashConv（EMA）が R-NaD の 0.0163 以下なら合格。
  - M1 が M1n の 1.2倍以内（seed の誤差込み）なら、pps の雑音の増え方は許容できる。
  - M1 が M1n の 1.2倍を超えたら、3070 の割合を 0.5 以上にする（2.6.3 の規則より優先する）。
  - M3 が 0.038 の ±20% に入らないなら、実装か歩幅（η ≤ α/L²）を疑う。
  - M1q が T0 どおり止まれば、Ataraxos の絞り込みは本線の既定にしない（今の既定のまま）。
  - M1q が意外に良くても、quantile を本線で使うには2つが要る。(c) で pps に勝つこと、そして搾取されにくさの確認（7節）。
  - 注意: 12情報集合・2行動の小さいゲームなので、本線の大きい行動空間での偏りまでは言えない。

   - 相手は既定どおり（rl_v15 以降＋歩哨 estimator_v14）。
4. **rl_search**（`rl_search:<重み>,eta=<η>`）。
   - R-NaD は η=30 で測る。
   - MMD は価値の意味が変わる（η の正則化報酬が入らない）。そのため η ∈ {20, 30, 45} で測って、最良を使う。
   - 3つから選ぶ分だけ MMD に甘い。小さい多重比較として報告に書く。
5. 使わないもの:
   - 直前の版との直接対戦（段階の数え器。`tsuitate-bot/docs/rl-learning-speed.md:62-64`）
   - 学習中の錨への勝率
   - 「最後の5時間の伸びの傾き」。評価の誤差だけで傾きの差の SE が約0.15pt/時間あり、見込まれる差 0.003〜0.09pt/時間より大きい【計算・批判側】（`power.py`）

### 6.4 門（先に決める）

**この A/B が決めるのは2つだけ**: ① MMD が本線より明らかに悪くないか、② Δ ≥ +2pt の大きい効きがあるか。

- Δ̂ = パネルのペア差（全体、同じ壁時計、最後の比較点の 4,096局）。MMD が2本なら、2本の平均。
- SE² = τ²·(1 + 1/n_MMD) + se_eval²。
  - 【二次】τ（同じ設定の run どうしの揺れ）は未計測で、0.5〜0.8pt と見込まれている（`tsuitate-bot/docs/rl-learning-speed.md` 2節の「本番規模の検出力」の末尾と 9.6）。
  - **τ = 0.8 と仮定し、その仮定を報告に書く**。
  - MMD を2本回したら、2本の差から τ の手がかりを出し、max(0.8, 推定値) を使う（自由度1なので不確か）。
  - se_eval は約0.23pt（σ_d 0.55〜0.60、15体 × 4,096 = 約6.1万組。σ_d は同 9.6 の「2台目がある（O3）」の見込み。初版の 0.28pt は 11体の panel_v1 で数えていた）。
- 【一次・批判側】speedlab の「±」は、seed が1本だと局ごとのペア差だけから出る（`rnad/speedlab.py:420`「局ごと、1 seed」）。
  τ が入らないので、上の SE で読み直す。

| 結果 | 判断 |
| --- | --- |
| Δ̂ ≥ max(+2.0, 1.645·SE)、かつ CI のガントレットで点推定が −1pt より悪くない、かつ rl_search（最良の η）で −2pt より悪くない | **採用**: 次の段階から本線を MMD に切り替える（凍結の規則は従来どおり） |
| Δ̂ ≤ −1.645·SE、または 6.1 の中止の門 | **棄却**: CPU の診断に戻る（行の選び方・磁石・温度・学習率） |
| それ以外 | **保留**: 本線は R-NaD のまま。延長や複製を回すかはユーザーが決める（傾きの基準は使わない） |

検出力【計算】（`power2.py`。panel_v2 の15体 × 4,096局、σ_d 0.60 の場合。0.55 でもほぼ同じ。初版は 11体で数えていたが、差は SE で 0.01〜0.02）:

| τ | MMD | SE | 採用のしきい値 | 棄却のしきい値 | P(採用): Δ=0 / +1 / +2 / +3 / +4 | P(棄却): Δ=0 / −1 / −2 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.8 | 1本 | 1.16 | +2.00 | −1.90 | 4% / 19% / 50% / 81% / 96% | 5% / 22% / 53% |
| 0.8 | 2本 | 1.01 | +2.00 | −1.66 | 2% / 16% / 50% / 84% / 98% | 5% / 26% / 63% |

- 見込まれる Δ【推測】:
  - MMD が壁時計で k 倍速いなら、15時間で k 段階ぶん進むので、Δ ≈ (k − 1)·g。
    g は1段階の伸びで、+0.1〜+2.7pt（`tsuitate-bot/docs/rl-learning-speed.md` 2節の「本番規模の検出力」）。
  - Δ=+2pt に要る速さは、×1.7（g=2.7）〜×5（g=0.5）。g=1.4 なら ×2.4。
  - 6.0a で収集律速と分かれば、壁時計の得は ×1.0〜1.1 しかない。Δ は「1更新あたりの効き」だけで決まる。
- したがって、**×1.5 程度の速さなら、結果はほぼ確実に「保留」**になる。
  - この A/B は、「明らかに壊れていないか」と「×2 を大きく超える効き」を拾うためのもの。
  - 小さい効きを測るには、複製を含む長い比較（例: 各腕2本×1段階）が要る。

## 7. リスクと、分かっていないこと

### リスク

1. **雑音が律速のまま**【実測＋推測】:
   - v7 のミニバッチ ≤1,024 の方策の勾配は、ほぼ雑音（2.13）。
   - k 歩の利得が √k に止まり、MMD の得が「計算」と「スパイクが無い」ことだけになるかもしれない。
   - (a) で先に測る。
2. **行の選び方**:
   - Ataraxos の絞り込みは固定点を変える（クーンで実測、2.6.1）。だから既定にしない。
   - pps は不偏だが、雑音が全行の 1.6〜1.8倍になる（rate 0.25）。序盤の行は重みが大きく、その分の雑音を持つ。割合は 6.0c で決める。
   - Ataraxos の「フィルタで最終性能まで上がった」効果が偏りから来ていたなら、pps では得られない。
     その場合の代わりは、`--mmd-pol-scale` を上げるか、α を下げること（2.6.6）。
3. **価値の偏り**: 価値は不偏な行で学ぶ（2.6.4）。それでも帯ごとの見張り（`calib_band`・`resid_band`）で崩れを見る。
4. **λ_A の偏り**: λ<1 は、価値の誤差を A に入れる（2.3）。0.8 でも、次の手番の誤差の 0.2 が入る。序盤の V は無情報に近い。
5. **予定の移植**:
   - t の数え方は Ataraxos の「1回200歩」が前提で、本線の8歩とは連動がずれる（2.10）。
   - 温度を下げる場合の収束の証明は無い（MMD 論文 p41）。
   - A/B では学習率を固定したので、焼きなましの効果は混ざらない。そのかわり、Ataraxos の4つの抑えのうち1つが無い。
6. **歩幅**: 新しい Adam（β1 0.9）・スパイク無し・8歩・学習率 1e-4 では、1更新で R-NaD の数十〜百倍動きうる（6.1）。
   P2 の学習率の腕と、Phase A の門で抑える。
7. **磁石**:
   - 混合の磁石は、v7 付近へ方策をつなぎとめる側に働く。A/B の間は安全側だが、採用後にいつ入れ替えるかは決めていない。
   - 一様・二段は、打ち・歩・香へ引く（2.5）。
8. **NeuRD の性質を失う**:
   - ソフトマックスの方策勾配は、確率の低い手を押しにくい。
   - 本線は `pi_top_gt_0999` が約27%（`tsuitate-bot/docs/rl-learning-speed.md:357`）と鋭い。
   - 磁石が支えるはずだが、方策が固まらないかを見る。
9. **pipeline の古さ**:
   - decoupled PPO で中心は直すが、外側の重要度に上限 2 を付けた分の偏りが残る。`prox_is_capped` で見る。
   - KL と磁石は残した行だけにかかる。残さなかった行は、共有の幹を通して信頼領域なしで動く。`kl_mu_unkept` で見る。
10. **価値の意味が変わる**:
    - η の正則化報酬が入らなくなる。
    - rl_search の η=30 は、今の価値の縮みで較正されている（`tsuitate-bot/docs/rl-deepnash-design.md:1338-1339`）。
    - 採用するなら η を測り直す（6.3 では3点から選ぶ）。
11. **入口の違い**:
    - `.bin` と `checkpoint.pt` を混ぜると、Adam の幾何が違う。
    - R-NaD の Adam の状態を持ち込むと、実効の学習率が何千更新も下がる。
12. **勾配ノルムのクリップの尺度**: 0.267 は Ataraxos のネット用。本線では毎歩クリップされる見込み（2.9）。6.0c で決め直す。
13. **BN を train モードにする事故**。
14. **設定の取り違え**:
    - `cfg_diff` の既定値が `RNaDConfig` 固定になっている（`rnad/rnad.py:874-881`）。
    - R-NaD 専用のフラグを黙って無視しない（4.3）。
    - MMD の書き出しは本線と同じ step 番号になる。Release のタグに `mmd` を入れる。
15. **検出力**: τ を入れた SE は 1.0〜1.2pt。小さい効き（×1.5 程度）は判別できない（6.4）。
16. **パネルの偏り**: 系列内の相手は、R-NaD の対照に有利に偏りうる。系列内・系列外の小計を並べる（6.1）。
17. **小さい代理の限界**:
    - P2 では R-NaD も伸びなかった。Kuhn は小さすぎる。
    - CPU で「速く強くなる」ことは示せない（`tsuitate-bot/docs/rl-learning-speed.md:438-440`）。

### 分かっていないこと

- Ataraxos の最終 run の実際のハイパーパラメータ・磁石の形・フィルタの実装（legacy か現行か）・途中再開での上書き。
- Ataraxos の「フィルタで最終性能まで上がった」現象（論文も「さらに調べる価値がある」と書く、p13）について。
  - 偏りから来たのか、計算の配分から来たのか。
  - ついたて将棋でも起きるか。
- 本線での B_noise と、変種どうしの期待勾配のコサイン（MMD の推定量で何局か）。(a) で測る。
- 本線の律速（収集か更新か）。6.0a で決める。
- 3070 での MMD の1更新の秒。6.0c で測る。
- 学習の揺れ τ。本線でも MMD でも未計測。MMD を2本回せば手がかりが出る。
- 混合の磁石の ε と、採用後の磁石の入れ替え方。
- 温度の起点（0 か 2,000 か）の良し悪し。P2 で見るが、本番の大きさでも同じかは分からない。
- 1ミニバッチ = 1時刻・1プレイヤー（Ataraxos）と、無作為な混ぜ方で、勾配の雑音の性質が違うか。
- 搾取されにくさを直接測る道具が無い。
  - 案: 凍結した書き出しに、同じ予算で短く搾取者を当て、勝率の伸びを比べる。
  - 偏った選び方（quantile）を本線に使うなら、その前にこの確認が要る。
