# 序盤の多様化（自己対局で序盤を強制する）

2026-10-29。方策ネットの序盤が飛車先の歩の速攻1本に固まっていることを測り、学習の自己対局で
**先後それぞれ独立に序盤を定跡から指させる**仕組みを入れた（既定オフ）。

- 本体: `src/rl/forced.rs`（ブックと予定）・`src/rl/env.rs`（`EnvGame` の中で指す）・
  `rl-env/`（`VecEnv` の `openings` / `opening_prob` ほか。`rl-env/README.md`）
- 学習: tsuitate-nn の `train_rnad.py --open-book --open-p --open-len --open-weight`（`rnad/openings.py`）
- 測る道具: tsuitate-nn の `rnad/opening_eval.py`（`entropy` = 序盤の分布、`robust` = 序盤を強制した対局）

## 1. 何が起きているか

各版を自己対局させ（256局、温度 1 = 学習と同じ指し方）、初期局面の方策と最初の数手の並びを数えた。

| 版 | 更新数 | 初手 ▲2六歩 の確率 | 2番目に高い手 |
| --- | --- | --- | --- |
| rl_v15 | 10,000 | 4% | ▲6八飛 68%・▲4八飛 26% |
| rl_v17 | 20,000 | 26% | ▲6八飛 63% |
| rl_v18 | 25,000 | 46% | ▲6八飛 52% |
| rl_v19 | 30,000 | 63% | ▲6八飛 37% |
| rl_v20 | 35,000 | 97% | 10^-1.5 |
| rl_v21 | 40,000 | ほぼ 100% | 10^-3.2 |
| rl_deduce_v9 | 108,000 | 100% | **10^-18.2** |
| MMD r2 128,000（current） | 128,000 | 100% | **10^-17.8** |

- 後手は鏡写し（△8四歩から8筋の歩を突く）。rl_v21 以降の版（v22〜v30、selfplay・deduce、速攻・入玉・防御の
  特化版、MMD の A/B と r2 の 118,000・128,000 の current/target）は、最初の3手（▲2六歩・2五歩・2四歩）が
  先後とも 256局すべて同じ。調べた版では4手目の ▲2三歩成まで 100%
- 「飛車の前の歩を突進させる」こと自体は 10,000更新からある（rl_v15 は ▲6八飛 から6筋の歩を突進させていた）。
  2筋なら飛車を動かさずに済むので歩が成るまで1手早い。20,000〜35,000更新で、まだほかの手も指されていた間に寄った
- 5〜6手目は版によって混ざり方が違う（最初の6手の並びのエントロピーは rl_v21〜v26 で 2.1〜3.3ビット、
  rl_v27 以降の本線で 0.2〜1.4ビット、速攻・入玉の特化版は 0.04〜0.4ビット）。rl_deduce_v9（1.4ビット）では
  後手の5手目の △2七歩打（84%）が、▲2六歩で空いたマスに打って ▲2八飛 に当てる手で、先手の ▲8三歩打（82%）も
  同じ形（MMD r2 128,000 は先手 ▲8三歩打 73%、後手は先に △5二飛と逃げる手が 98%）。どちらの打ちも自分の歩が
  取られた観測を見てから打っていて、下の強制した対局でもほとんど反則にならない（512局あたり数回以下。
  決め打ちではなく観測からの推論）

**このまま学習しても分かれない理由**: 確率 10^-18 の手は自己対局で事実上一度も指されないので、学習はその手の
良し悪しを知る手段が無い。戻す力も無い。R-NaD の正則化は1つ前の段階の方策（これも固まっている）からの相対で、
NeuRD の ±β のクリップも下限として働いていない（▲2六歩の中心化ロジットは +51.6、β = 16）。MMD の動く磁石は
自分の移動平均で、磁石への KL は逆向きの KL(π‖ρ) なので、確率の低い手への勾配はその手の確率に比例して消える。
差は 40,000更新の 10^-3 から 108,000更新の 10^-18 へ広がり続けている。55,000更新からのリーグ学習（相手の戦型は
変わる）でも変わらなかった。駒がぶつかるまで相手の手は観測に入らないので、自分の最初の数手は相手が誰でも同じになる。

## 2. 片側の序盤を強制した自己対局（基準）

ネット自身どうしで、片側の最初の数手を別の序盤に強制し、強制しない側は普段どおりに指させた（各 512局。
1セルの得点の標準誤差は約 2.2pt、強制しないときとの差の標準誤差は約 3.1pt で、**差が ±6pt を超えないものは
ノイズと区別できない**）。強制は駒がぶつかった時点で止める。**この節の数字は Python 側で強制した試作の道具の値**で、
定跡の最後の駒取りの手も指させ、見えない駒に遮られる手は指さずに止めている点が、学習の仕組み（3節）と違う。
今後の比較は `opening_eval.py robust`（env の中で強制する。学習と同じ規則）で取り直したもの（2.3）を使う。

### 2.1 手で書いた8つの序盤

強制した側の得点の、強制しないときとの差（rl_deduce_v9 の自己対局の先手 54.7%・後手 45.3%、
MMD r2 128,000 は 49.6%・50.4% が基準）。

| 強制した序盤（先手視点、4手） | v9 先手 | v9 後手 | MMD 先手 | MMD 後手 |
| --- | --- | --- | --- | --- |
| ▲6八飛 6六歩 6五歩 6四歩（6筋へ振って歩を突進。rl_v15 の手順） | −5.7 | −8.6 | +6.0 | −2.0 |
| ▲7六歩 6六歩 6八飛 4八玉（6筋へ振って囲う） | +0.4 | +1.0 | −9.4 | −15.6 |
| ▲7六歩 7八金 6八銀 7七銀（矢倉風） | −13.5 | −4.2 | −7.4 | −12.2 |
| ▲5六歩 5八飛 5五歩 4八玉（中飛車） | +3.5 | −6.8 | +6.0 | −1.1 |
| ▲7六歩 7八飛 4八玉 3八玉（7筋へ振って囲う） | −2.6 | +0.8 | −2.0 | −11.8 |
| ▲2六歩 2五歩 7六歩 7八金（飛車先を2つだけ突いて囲う） | **−25.2** | −7.2 | +6.2 | +10.7 |
| 無作為の4手（駒に触れない手） | −13.9 | −3.7 | −7.2 | −11.5 |

- **ネットが一度も指していない序盤でも得点が上がるものがある**（飛車先を2つだけ突いて囲う形の MMD の後手
  +10.7、2.2 の左端攻めの v9 の後手 +8.5・四間飛車の MMD の先手 +9.2、2.3 の囲うだけの v9 +8.2。どれも 2σ を
  超える）。今の速攻1本は「最善と分かったから」ではなく「試していないから」の可能性が高い
- **弱くなる序盤が版で大きく違う**（飛車先を2つだけ突いて囲う形は v9 で −25.2、MMD で +6.2）。
  決まった序盤の外での指し回しは版ごとの当たり外れで、身についた力になっていない
- 強制しない側の序盤の反則（自分の受理手 12手まで）は、相手の序盤によって基準の約 0.1回/局から
  0.5〜0.8回/局へ増える（相手がいつもの速攻で来る前提の手が混ざる）

### 2.3 学習と同じ規則で取り直した基準

`opening_eval.py robust`（env の中で強制する。定跡の最後の駒取りの手は指さず、見えない駒に遮られた手は反則として
指して止める）で、ネット自身どうし（`--ref` なし）の各 512局。値は測ったネットの得点（%、± 約 2.2）。
**opp** = 相手の側の序盤を定跡に強制、**cand** = 自分の側を強制（先後は半分ずつ）。強制しないときは
rl_deduce_v9 50.8%、MMD r2 128,000 52.9%。

| 系統 | v9 opp | v9 cand | MMD opp | MMD cand |
| --- | --- | --- | --- | --- |
| 囲うだけ | 45.2 | **59.0** | 44.5 | 51.6 |
| 居飛車速攻 | 54.2 | 46.9 | 50.7 | 45.6 |
| 向い飛車 | 57.5 | 42.6 | 63.9 | **35.4** |
| 左端攻め | 49.9 | 47.6 | 56.9 | 48.2 |
| 三間飛車 | 58.4 | **39.8** | 60.6 | 44.2 |
| 四間飛車 | 46.7 | 54.2 | 44.7 | 56.6 |
| 端攻め | 56.1 | 41.6 | 56.1 | 41.5 |
| 中飛車 | 45.4 | 51.5 | 58.6 | 43.5 |
| 六間飛車 | 56.6 | 46.8 | 50.8 | 39.6 |
| 平均 | 52.2 | 47.8 | 54.1 | 45.1 |

- 自分の側を定跡に強制すると平均で 3〜5pt 下がり、系統によっては 10〜15pt 下がる（向い飛車・三間飛車・端攻め）。
  上がる系統もある（囲うだけ・四間飛車）。どの系統が弱いかは版で違う（中飛車は v9 51.5 / MMD 43.5）
- 相手と自分が同じネットなので、opp と cand はほぼ鏡写し（同じ系統で足すとほぼ 100）。**学習の前後を比べるときは
  `--ref` に固定のネット（例: 出発点）を渡し、cand を新しいネットにする**（5節）
- 強制しない相手が速攻なので、最初の接触は平均 7.5手目で、強制した側は平均 3.5手でぶつかって止まる
  （長いラインの形は両者とも強制された局でしかできない）
- 系統の名前は定跡ファイルのまま（飛車のいる筋の数字で呼んでいる。ふつうの将棋の呼び方とは違う）

## 3. 仕組み

**局ごと・先後それぞれ独立に**確率 p で、その側の最初の数手を定跡のラインから指させる。

- **env の中で指す**（`EnvGame::settle` の、評価モードの相手の手番と同じ経路）。強制した手は `observe` に
  現れないので、学習器から見ると環境の手（チャンス手）になり、R-NaD の v-trace も MMD の GAE も変えずに正しい。
  強制した側の最初の判断が後ろの手数になるのは、後手や反則のときと同じ形
  - Python 側で強制して行を「無効」にすると、v-trace の逆向きの carry が無効の行で切れる（GPU リーグの不具合と
    同じ形）。μ ≠ π の行として入れると、相手の重要度比 π/μ ≈ 0 で強制されなかった側の価値の目標が止まる。
    どちらも採らない
- **独立に引く**: 強制されなかった側は、相手が強制されたかを自分の観測から推せない（駒がぶつかるまで相手の手は
  観測に入らない）ので、**ふだんの局面のまま**「相手の序盤は p の割合で違う」ことを学ぶ。両者をまとめて強制すると、
  「自分の序盤が定跡なら相手も定跡」という相関が漏れ、頑健さが本番では現れない局面にだけ付く
- **定跡の最後の駒取りの手は指させない**: ラインは作るときに、初期配置の相手の駒に触れる手（行き先か飛び駒の
  通り道）の手前で切る（例: 居飛車速攻は ▲2三歩成の手前の3手）。ぶつかった後の判断は方策が指す
- **止める条件は `opening.rs` の `OpeningBook::next` と同じ**: どちらかの駒取り・王手（両者に見える接触。
  両者とも止める）、その側の反則、予定の手数を指し終えた
- **定跡の手が実際には反則なら、反則として指してから止める**（`opening.rs` と同じ）。真実の盤面で合法かを先に
  調べて黙って止めると、方策が指し始める局面が見えない情報と相関する
- 乱数は局ごとの数え上げ（`mix`）で、側ごとに3つ（強制するか・ライン・手数）を必ず引く。p を変えても、両方の p で
  強制される側のラインと手数は同じ。学習は更新ごとに `set_opening_seed(seed·1,000,003 + 29 + step)` してから
  `reset` するので、再開しても同じ局に同じ定跡が付く
- `opening.rs` と `joseki.json` は凍結版の共有 pin（`frozen::SHARED_MODEL_PINS`）なので触らない。
  ラインは学習側が `joseki.json` を読んで渡す（ほかのラインを使うときは同じ形式の別ファイルを作る）

**変わらないもの**:

- **ネット自身の初手は分かれない**。強制しない局では今までどおり速攻を指し、確率 10^-18 の手はやはり指されない。
  この仕組みが身につけさせるのは「どんな序盤から来ても、ぶつかった後をうまく指す」ほうで、序盤そのものを散らす
  （初手の確率を戻す）には、序盤の数手だけ方策を平らにして指させ v-trace の比で補正する、などの別の手が要る
- 本番の指し方。学習で定跡の序盤を指した経験が付けば、本番で定跡から無作為に選んで指させても
  （estimator の `OpeningBook` と同じ）弱くなりにくくなるはず、というのが次の候補

## 4. 使い方

```sh
# 学習（tsuitate-nn）。p は側ごとの確率（両者とも強制される局は p²、どちらも強制されない局は (1−p)²）
python rnad/train_rnad.py ... --open-book ~/Develop/tsuitate-bot/joseki.json --open-p 0.25
#   --open-len 1:6        強制する手数を局ごとに一様に引く（既定はラインを切った後の最後まで）
#   --open-weight line    ラインごとに一様（既定 category = 系統ごとに同じ確率）

# 測る（CPU でよい）
python rnad/opening_eval.py entropy rl_deduce_v9=~/Develop/tsuitate-bot/models/rl_deduce_v9.bin --games 256
python rnad/opening_eval.py robust --cand a.bin [--ref b.bin] --book ~/Develop/tsuitate-bot/joseki.json --games 512
```

- 使えない組み合わせ（起動時に止める）: `--league`・`--guard`・`--speed`・`--nyugyoku`（強制した手の形・手数・
  玉の前進がボーナスに入る）、`--c-ply`（collect の行の番号で数えるので、強制した手のぶん手数がずれる）、`--mmd-lambda-unit turn`（「同じ側が続けて指す」を反則とみなすので、相手の強制した手を
  はさんだ手番を取り違える）。`--pipeline` は使える
- 設定は checkpoint の `collect_cfg` と `config.json` に残り、**再開で `--open-*` を付け忘れると止まる**
  （意図した変更なら `--override-config`）。強制しない run の checkpoint は従来どおり（ビット単位で同じ）
- ログの `opening` に、強制した側の割合・平均の手数・止めた理由・両者とも強制した局の割合・最初の接触の手数・
  接触の前の反則・序盤（各側の受理手 12 まで）の反則・その batch の乱数列（`seed`）が出る。**強制した側の序盤の局面は学習の行に入らない**ので、`pi_top_*` やエントロピーは
  強制しない run と直接は比べられない
- p の目安: 0.25（どちらも強制されない局が 56%、片側だけ 38%、両者 6%）から。強制しない側が速攻だと、
  強制した側は 3〜4手でぶつかって止まる（後手は3手）ので、長いラインの形が最後までできるのは両者とも強制された局が中心

## 5. 効いたかの見方（案）

同じ出発点（例: rl_deduce_v9 か今の MMD の run）から、強制あり（p 0.25）と強制なしを同じ更新数だけ回し、
両方の書き出しを **`--ref` に出発点を固定して** `opening_eval.py robust` で測る（相手が固定なので、opp と cand は
別のことを測る）。

1. **ふつうのガントレット**（CI の arena、系列外の相手）で下がっていないこと（強制した局のぶん自己対局の量が減る）
2. **opp 条件**（固定した相手の序盤を定跡に強制）の得点が、強制なしの run より上がること。これが「どんな序盤が
   来ても」の直接の物差し。**cand 条件**（自分の序盤を強制）は、定跡から入ったときに続きを指せるか（本番で序盤を
   散らすための前提）
3. 序盤の反則（`early_fouls_cand`、各側の受理手 12 まで）が、opp 条件で none 条件の値へ近づくこと。
   接触の前の反則（`precontact_fouls_*`）は、速攻どうしでは7〜8手目でぶつかるので構造上ほぼ 0 で、物差しにならない

## 6. 分かっていないこと・次の一手

- 2節の数字は 512局ずつの1回で、条件の間の差の多くは ±6pt（差の 2σ）の内側にある。大きい差（−10〜−25pt）は
  ノイズでは説明できないが、どの系統が本当に弱いかの順位は確かでない
- 人間の序盤のデータは手元に 81側（73局）しかなく、うち 73側は所有者（引き角の系統が多く、定跡ファイルとも重なる）。
  サイトの `games.moves` の書き出しがあれば、人間の序盤のブックを同じ形式で作れる
- arena（Rust の `bin/arena`）にはまだ序盤の強制が無い。CI で測るなら `ARENA_FORCE_OPENING` のような指定と、
  記録の形式（`games.jsonl` の版）・`arena-var` の組み合わせの検査を足す
- 強制した対局の記録は、模倣学習や NN の教師データに混ぜない（定跡の手がネットの手として入る）
